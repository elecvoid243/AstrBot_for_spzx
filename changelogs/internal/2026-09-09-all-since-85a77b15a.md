### 修复

- 本地 Python 执行器改用控制台子系统 `python.exe`（`$PYTHON` 指向 `pythonw.exe` 时自动重定向到同目录的 `python.exe`），直接子进程在 `CREATE_NO_WINDOW` 下获得的无窗口控制台会被嵌套子进程继承，`subprocess` / `os.system` / `multiprocessing` 等所有启动路径都不再弹黑框，据此移除注入用户代码的 `_winapi.CreateProcess` monkey patch 前导代码。 (`4c96e06ce`)
- Skill 引导菜单在鼠标移出后保持打开，并新增显式关闭按钮。 (`3e74eca92`)
- 在 `CreateProcess` 层抑制子进程控制台黑窗，覆盖绕过 `subprocess.Popen` 的启动路径（典型如 `pythonw.exe` 下的 Windows multiprocessing spawner）。 (`6c466f560`)
- 托管本地 shell 会话在 `exec_managed()` 与 `write_session()` 中增加自杀保护，并把检测从单一 `kill <pid>` 正则扩展为 kill 调用模式。 (`2834e40ce`)
- Git 日志 / 历史视图：轮询不再重复滚动日志、数据到达时恢复深链聚焦、清理过期聚焦与无匹配空态、渲染真实分组表头并保持 ref 为字符串、分支变更后保留 tag 列表、移除历史行中的嵌套按钮、仅在 History 标签页触发 git-log 请求并在切换 worktree 时重置筛选与选中状态。 (`d15e2f5db`, `7f3dcfcb0`, `6b99ea4e2`, `908d74a16`, `b55c15265`, `f7f2e6632`, `35d970023`)
- Git 历史 HEAD 处理：amend / reset / squash 改为从 `git worktree list` 的 worktree `head_sha` 解析 HEAD，不再把筛选结果第一行误当作 HEAD 而作用或隐藏在错误提交上；HEAD 未知时 amend / reset 保持隐藏、squash 判为无效而非猜测，squash 显示"HEAD 不在当前筛选结果中"的明确提示，History 刷新按钮同时刷新 worktree 列表避免 HEAD 滞后；数量预设改为 10 / 20 / 30（原 10 / 20 / 50）独立圆角按钮。 (`5ae0f7ede`)
- 提交终端命令后重置历史索引。 (`056684d38`)
- 推理侧栏的文件变更卡片在调用"在磁盘中打开"/"在文件夹中打开"前，剥离写入工具追加的纯显示用 ` (encoding: xxx)` 标记，后端不再按带标记的文件名查找而报 `File not found`；卡片显示仍保留标记。写入卡片的语言识别同样改用干净路径，恢复 Shiki 高亮。 (`0b5de2b7f`)
