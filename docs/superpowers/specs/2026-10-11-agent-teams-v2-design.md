# Agent Teams v2：可复用协作资产与统一执行工作台

- 日期：2026-10-11
- 文档类型：正式产品与验收规格
- 主规格：[GitHub Issue #2](https://github.com/elecvoid243/AstrBot_for_spzx/issues/2)；本文件为同步副本。
- 状态：需求及测试边界已确认，可进入任务拆分；不表示功能已经实现。
- 适用范围：Agent Teams 的自主协作、可视化工作流、跨机器资产复用、执行恢复和 WebUI 改版。
- 基线关系：本文整合本轮已确认决策与视觉原型；与早期 Agent Teams 设计冲突时，以本文规定的用户可见行为为准。早期设计保留为历史依据。

## 问题陈述

用户希望根据任务特点，自由选择自主团队协作或可视化工作流，并把验证有效的协作方式保存为资产，在另一台机器的 AstrBot 中导入使用。当前 Agent Teams 仍处于 WIP 状态，团队、成员会话、编排方式和本机资源之间耦合较强，难以稳定复用，也难以准确判断一次运行的进度、等待原因与结果归属。

现有自主协作与工作流各自维护执行生命周期，调度、配置生效和恢复语义不一致。用户会遇到无关慢任务阻挡后继任务、成员历史串入新任务、恢复时读取被修改的配置、长结果只能看到截断摘要等问题。重启之后重新派发未完成节点，可能重复执行已经产生外部效果的工具。

AstrBot 已经能够保存 Agent 输出、提供商实际返回的思考内容、工具调用及工具结果。本次需要解决的是执行中的持久化时点、关联标识和恢复协议：完成或正常清理时保存的聊天记录，并不等于每次模型或工具调用后都有可用于进程崩溃恢复的一致检查点。

现有页面偏向团队与成员配置，尚不能清楚表达可复用角色、每次运行的成员实例、人工待办和版本化产物之间的关系。用户需要一个同时适合编排、配置和处理运行任务的工作台。

## 解决方案

将团队与工作流统一为可版本化、可导入导出的协作资产。用户先定义角色职责、能力需求和编排，再将逻辑资源槽位绑定到当前 AstrBot 的模型、工具、技能与知识库。每次启动固定资产版本和有效配置，创建独立运行及成员上下文。

自主协调者和工作流都是同一运行能力的任务来源，共享调度、通信、输出契约、产物版本、预算、人工等待和恢复语义。允许工作流调用自主团队，也允许协调者调用已保存的工作流。执行继续复用 AstrBot 现有 Agent 主管道。

WebUI 以资产编辑和运行处理为中心，清晰展示角色模板、编排画布、依赖就绪状态、任务进度、待办和产物；普通聊天也可以明确调用已配置资产。首个完整验收场景是调研报告：并行调研 → 证据汇总 → 撰写 → 独立审查 → 有界修订 → 人工确认具体版本 → 导出报告。

首版包含全部下述范围，自主协作、可视化工作流、调用边界恢复、跨机器复用和 WebUI 改版均不是无期限延期的可选项；实现可以按依赖逐步交付。

## 用户故事

### 资产与角色

1. **US01**：作为任务发起者，我希望按需要选择自主团队或可视化工作流，以便为开放目标与固定流程选择合适的协作方式。
2. **US02**：作为资产作者，我希望保存有版本的团队和工作流定义，以便稳定复用已经验证的协作方案。
3. **US03**：作为资产作者，我希望定义角色职责、提示词、模型能力、工具、技能、知识库和执行限制，以便集中维护可复用的专业分工。
4. **US04**：作为任务发起者，我希望协调者能从允许的角色模板创建一个或多个成员，以便按实际任务调整参与人数。
5. **US05**：作为配置者，我希望区分角色定义、本机资源绑定和任务覆盖，并查看最终有效配置，以便理解每个成员实际使用的能力。
6. **US06**：作为任务发起者，我希望启动前知道缺失、歧义或不兼容的依赖，以便完成配置后再运行。
7. **US07**：作为资产作者，我希望后续编辑只影响新运行，以便不会改变正在执行任务的角色、流程和输入约定。

### 编排与自主协作

8. **US08**：作为工作流作者，我希望通过画布配置任务、依赖、条件、人工输入和子调用，以便不依赖任意代码表达式完成编排。
9. **US09**：作为工作流作者，我希望用明确的循环体、退出条件和最大次数表达修订，以便逐轮检查结果并防止无限循环。
10. **US10**：作为任务发起者，我希望已经满足依赖的任务及时启动，以便不被无关慢任务阻挡。
11. **US11**：作为任务发起者，我希望一个分支等待人工输入或故障处理时，其他独立分支继续执行，以便局部问题不会冻结整个运行。
12. **US12**：作为任务发起者，我希望同一成员在本次运行内保留上下文，而不同成员及新运行之间相互隔离，以便既保持任务连续性又避免历史串用。
13. **US13**：作为任务发起者，我希望成员能够受控地提问、反馈和分享产物，以便协作不必完全依赖协调者转述。
14. **US14**：作为任务发起者，我希望协调者统一负责成员创建、任务分派和整体完成，以便协作权责明确。
15. **US15**：作为工作流作者，我希望工作流能够调用自主团队，以便把开放性子任务交给团队处理。
16. **US16**：作为团队配置者，我希望协调者能够调用已保存的工作流，以便复用稳定流程。
17. **US17**：作为任务发起者，我希望嵌套调用在低并发限制下仍能推进，以便父任务等待不会耗尽子任务所需容量。
18. **US18**：作为任务发起者，我希望可以暂停、继续或取消整个运行，并区分这些操作与局部等待，以便明确控制执行。
19. **US19**：作为任务发起者，我希望限制成员数、并发、步骤、迭代和嵌套，并看到包含协调者与子调用的用量，以便控制执行成本和规模。

### 结果、审查与人工处理

20. **US20**：作为工作流作者，我希望任务显式提交符合输出契约的结果，以便后续条件和任务不依赖猜测自然语言是否表示完成。
21. **US21**：作为简单任务的作者，我希望直接使用默认文本结果结构，以便不必为每项任务设计复杂 Schema。
22. **US22**：作为结果消费者，我希望既能查看摘要又能读取完整报告、证据和文件，以便关键信息不会因摘要截断而丢失。
23. **US23**：作为审查者，我希望任务固定其输入产物版本，以便知道结论具体针对哪一份内容。
24. **US24**：作为审查者，我希望修订产生新版本并保留旧版结论，以便历史审查和批准不会被误用到新内容。
25. **US25**：作为任务发起者，我希望新版产物不会自行重跑所有下游任务，以便由我、协调者或既定流程明确安排后续执行。
26. **US26**：作为人工处理者，我希望待办持久保存、显示关联任务与版本，并在刷新或重启后继续回答，以便操作不会丢失或重复生效。
27. **US27**：作为报告使用者，我希望最终导出的是已经审查并人工确认的具体版本，以便交付内容与批准对象一致。

### 可靠性与历史

28. **US28**：作为任务发起者，我希望完整模型响应已保存后能够从该边界恢复，以便不必重新生成同一步工具计划。
29. **US29**：作为任务发起者，我希望已保存的工具结果能够复用，以便恢复不会重复执行已完成调用。
30. **US30**：作为任务发起者，我希望工具外部效果不明时明确等待确认或对账，以便系统不会未经判断重放可能有副作用的操作。
31. **US31**：作为任务发起者，我希望区分继续同一次尝试、重新尝试和下一轮循环，以便理解执行历史与额外消耗。
32. **US32**：作为任务发起者，我希望页面关闭、刷新或重连不影响运行，并能恢复正确进度，以便不必持续保持浏览器连接。
33. **US33**：作为配置者，我希望在启动前知道执行器支持的恢复能力，以便不会把远端运行查询或普通聊天历史误认为内部工具级恢复。
34. **US34**：作为任务发起者，我希望查看关联到成员、任务和尝试的输出、可用思考内容、工具调用及结果，以便定位问题和追溯过程。

### 跨机器复用与入口

35. **US35**：作为资产作者，我希望导出包含角色、固定版本子定义、契约和布局的资产包，以便在另一台机器上复用完整方案。
36. **US36**：作为资产接收者，我希望依赖明确兼容且齐全时一键完成配置，以便快速运行导入资产。
37. **US37**：作为资产接收者，我希望在同一页面处理缺失或歧义依赖，以便逐项补齐模型、工具、技能和知识库。
38. **US38**：作为资产接收者，我希望重复导入可识别已有内容、升级生成新版本，以便不会重复创建或修改正在执行的定义。
39. **US39**：作为资产作者，我希望导出包不携带本机凭证、会话与运行历史，以便只分享可复用定义。
40. **US40**：作为普通聊天用户，我希望明确调用已配置的团队或工作流，并在必要时补齐输入，以便不必切换到 WebUI 才能发起任务。
41. **US41**：作为普通聊天用户，我希望运行遵守我的身份与可访问资源范围，以便平台用户不会隐式获得管理员权限。
42. **US42**：作为任务发起者，我希望从来源会话收到受理状态和最终结果，并能进入统一运行详情处理人工待办，以便持续跟进任务。

49. **US49**：作为已有用户，我希望中英文说明、截图和旧新入口映射同步更新，以便能够找到改版后的功能。

## 实现决策

### 1. 领域与模块职责

采用以下统一概念。它们表达职责和不变性，不要求逐一创建新表、新类或独立服务。

| 概念 | 定义与约束 |
| --- | --- |
| 资产定义（AssetDefinition） | 有身份和版本的团队或工作流，包含角色引用、输入输出契约与依赖声明。 |
| 角色定义（RoleDefinition） | 职责、提示词和能力需求，不持有运行会话。 |
| 本机安装（Installation） | 将逻辑资源槽位绑定到本机资源；缺失依赖时处于待配置状态。 |
| 运行（Run） | 一次执行，保存输入、发起身份、来源、定义版本、有效配置快照与预算。 |
| 执行作用域（Scope） | 标识嵌套团队、子工作流与迭代归属，记录父子关系。 |
| 运行成员（MemberInstance） | 从角色创建的实例，具有唯一身份和独立上下文；同一角色可有多个实例。 |
| 任务（Task） | 明确的目标、输入引用、输出契约、依赖和执行归属。 |
| 执行尝试（Attempt） | 一次实际执行及其错误、消耗、消息关联和检查点。 |
| 结果与产物版本（Result / ArtifactVersion） | 经校验的任务输出及不可变的文本、证据集或文件引用。 |
| 调用记录（Invocation） | 单次模型或工具调用的身份、输入、状态和持久化结果。 |

资产模块承担定义校验、版本引用解析、导入导出、本机资源绑定及运行快照生成。运行模块承担任务推进、上下文、通信、嵌套、预算、用户控制、恢复与查询。

工作流推进和协调者派工是运行模块内部的两种任务来源，共享任务生命周期与恢复协议。优先复用已有数据库、消息格式和执行接口；只为真实的约束、查询和恢复需求增加持久化记录，不构造通用编排平台。

### 2. 定义、本机绑定和运行快照

运行启动时固定顶层资产及所有嵌套引用版本、角色配置、有效执行配置、资源身份和输入。导出的逻辑槽位与本机绑定分离；凭证通过本机引用获取，不复制到资产包。

配置沿用现有继承与覆盖语义，界面必须展示继承来源、局部覆盖和最终有效值。自主协作与工作流对相同配置具有相同的生效语义。

后续编辑只作用于新运行。恢复仍使用原快照；资源被删除、不兼容或权限不再允许时，明确阻塞受影响的任务，不静默替换成默认模型、其他角色、工具集合或知识库。保留配置快照不意味着绕过当前授权。

### 3. 复用 Agent 执行能力

团队执行复用现有 Agent 主管道，保留模型提供商、工具、插件钩子、人格、技能、知识库和权限行为。不能只调用底层工具循环而绕过这些能力。

执行请求携带实际发起身份、来源、有效配置、成员上下文，以及运行、作用域、任务、尝试关联。执行结果与取消、恢复控制必须可关联到该尝试。

执行生命周期由 core 管理，WebUI 和聊天调用相同的应用服务。Dashboard 页面连接、进程内事件总线、会话注册表及聊天收集器均不能成为唯一执行事实来源。过渡期可以复用现有队列和适配接口，但恢复依据必须持久化。

保留可注入的执行边界：调度测试可以使用脚本化执行器；调用检查点测试必须穿过真实执行及持久化链路，仅替换外部模型或工具服务。

### 4. 调度、成员上下文和权限

- 依赖满足且存在执行容量时，任务即可启动；不能以整批任务全部完成作为无关后继的屏障。
- 不同成员可并行；同一成员同一时刻只能由一个执行者推进上下文。
- 同一实例跨任务保留本次运行上下文。不同实例及新运行使用独立上下文；跨运行复用只通过显式产物或知识完成。
- 协调者只能从当前资产允许的角色创建成员，并遵守实例、并发和预算限制。
- 成员的提问、反馈和证据共享不授予其派工、创建成员或结束整个运行的权限。协调者负责这些操作，运行时负责验证权限和完成条件。
- 持久化任务状态是事实来源，通知只负责唤醒调度；重复通知不得重复派工。
- 任务领取及状态提交具有条件更新或等价的一致性约束。旧执行者的迟到结果不能覆盖新的有效执行状态。
- 首版面向单实例执行，不要求分布式调度或多节点集群。

### 5. 局部等待、全局控制和完成条件

任务状态、阻塞原因和用户对整个运行的控制必须分别表达。

| 情形 | 对外行为 |
| --- | --- |
| 等待人工输入 | 保存待办与任务关联；仅阻塞依赖答案的执行，其他就绪分支继续。 |
| 分支失败待处理 | 保存失败尝试与可处理原因；仅阻塞受影响路径，不隐式暂停全部运行。 |
| 依赖缺失或工具结果不明 | 明确展示阻塞原因及处理入口，不冒充成功。 |
| 暂停整个运行 | 停止放行新执行，在可保存的安全点停驻；在途外部操作可能继续，不承诺撤销。 |
| 继续运行 | 按持久化状态和原快照继续符合条件的任务，不清除其他局部等待。 |
| 取消运行 | 向子作用域和执行者传播取消请求，停止新派工；保留已经发生的外部效果与执行记录。 |
| 循环达到上限 | 退出条件未满足时明确失败或等待处理，不显示完成。 |

人工待办、回答和消费关联必须持久化。重复回答或重连后的重复提交不能再次推进同一任务。

整体完成必须满足所需任务结果、输出契约和人工确认条件；不能因为协调者输出了一句“完成”，就忽略未处理失败、未决调用或未满足的必要审批。

### 6. 有界循环、双向嵌套和执行历史

循环采用显式循环块，包含循环体、退出条件和最大次数。条件只读取已校验的输出字段，不执行任意用户代码；任意无约束回边不作为循环接口。

工作流调用团队和协调者调用工作流使用同一运行语义。子调用默认创建独立作用域和成员，通过声明的输入输出交接，并固定引用版本。嵌套深度必须有界。

等待人工、资源或子流程时释放活跃执行容量。父任务等待子流程不得占住子任务唯一可用的名额；根并发限制为 1 时也应能推进正常嵌套。

区分三种操作：下一轮循环创建新的任务实例；重新尝试创建新的 Attempt 并保留失败记录；从检查点恢复继续原 Attempt。每轮输入、输出、审查结论和消耗可追溯。显式重试采用何种输入必须对调用者可见，不因“最新版本”隐式改变原任务输入。

### 7. 受控通信与用量

成员消息保存发送者、接收者、作用域、关联任务和产物引用。运行时校验成员可见范围与操作权限。接收者在安全执行点消费消息，防止异步投递与模型回合同时修改上下文。

按消息标识去重并保存消费位置，恢复后不能重复注入同一消息。协调者通过摘要定位结果，并能读取完整产物，不能只依赖固定长度截断的最新回复。

根运行统一计入协调者、成员、重试与嵌套调用的消耗；各作用域保留明细，按调用身份去重。恢复不清零，父子汇总不重复计算。

并发、步骤、循环、深度和成员实例数有明确限制。提供商用量区分已报告、估算和未知；未知不等于零。额度预留及单次输出限制用于约束并发调用，不能把事后统计宣传为任何情况下绝不超出的硬保证。达到可判定的执行限制后停止放行新调用，等待时间不占活跃执行名额。

### 8. 输出契约与不可变产物

任务通过显式结果提交工具提交数据，经输出契约校验后才可完成。简单任务使用默认文本结构；审查任务可以提交通过标记、问题列表和审查对象引用。非法数据返回具体字段错误，允许在剩余执行预算内修正。

结果提交请求先持久化；运行时在无未决工具调用的安全点，将任务完成、结果、产物引用和对应关键事件一致地保存。恢复时幂等完成已经接收的提交，不将普通自然语言、展示用 JSON 文本或流式片段直接视为完成结果。

产物版本一经提交不可变。任务启动时固定输入版本，并记录实际读取的引用；运行中不能漂移到最新版本。审查结论和人工确认绑定具体版本，批准 v1 不等于批准 v2。

产生 v2 不取消处理 v1 的任务，也不自动级联重跑下游。用户、协调者或既定流程可以明确安排后续任务；定义好的修订循环自动将新版本送审，属于已声明编排。

文件产物使用稳定的系统管理存储引用，不只保存临时绝对路径。文件就绪后才提交可见记录，未引用临时文件沿用既有清理机制。导出报告读取被确认的版本。

### 9. 持久化与调用边界恢复

派发前保存运行、作用域、任务、尝试、成员与对话、消息、检查点的关联。复用现有消息与工具结果格式，但不能从裁剪后的展示文本反向重建执行上下文。

检查点保存完整有效模型上下文、必要临时内容、多模态资源引用、配置引用、计数和预算。思考片段、签名及其他恢复所需的提供商字段按实际返回保存；不假定所有模型都提供思考内容。

| 持久化边界 | 必须保存 | 恢复保证 |
| --- | --- | --- |
| 模型请求前 | 调用身份、有效输入、上下文位置、配置引用。 | 没有已保存响应时可重发模型请求；不保证恢复半段流式生成或消除远端重复计费。 |
| 完整模型响应后、工具执行前 | 完整响应及待执行工具调用。 | 复用已保存响应，不重新让模型规划同一批调用。 |
| 每个工具执行前 | 调用意图、参数、开始状态、可用幂等键。 | 尚未开始可执行；已开始但结果缺失时按工具能力对账。 |
| 每个工具执行后 | 原始结果、完成状态、上下文应用位置。 | 不重复执行已有结果的调用，幂等补齐上下文。 |
| 提交结果或请求人工输入 | 提交请求或待办、关联状态及关键事件。 | 幂等完成收尾或继续等待，同一回答不重复消费。 |

同一响应中的工具调用分别记录；部分完成时只处理未解决的部分，不能重放全部工具。

外部效果已发生但结果尚未保存是必须显式处理的窗口。仅在工具提供幂等键、可查询状态或明确安全重试能力时自动解决；其余调用进入结果待确认，展示已有证据并等待处理。用户决定重新执行时保留原调用历史。系统不承诺任意外部操作恰好执行一次。

关键状态与事件使用现有数据库事务一致保存，不要求完整事件溯源。数据库无法保存必要事实时，不继续放行依赖这些事实的下一步外部执行。

### 10. 运行查询与执行器能力

运行查询返回持久化快照，关键事件有单调递增游标。页面重连可从游标继续，重复事件去重；游标无法续接时重新读取快照。流式 token 可合并或限量缓存，不要求逐 token 持久化，但完整已完成响应、工具结果、关键状态与用户动作必须持久化。

内置 Agent 执行器是首版调用边界恢复的主要验收对象。第三方执行器按实际能力接入：

- 能提供内部检查点时，接入相同协议。
- 执行托管在远端时，保存远端运行标识，按其查询或续接能力恢复。
- 既无内部检查点、又无法可靠查询远端状态时，只能保证外部调用边界；中断后结果待确认，不能展示为内部工具级可续跑。

资产就绪检查、角色配置与导入匹配使用相同能力判定。执行器不满足资产所需能力时阻止启动并解释原因，不静默降级。

插件钩子或工具内部的额外调用，恢复保证止于系统实际保存的边界；只有接入同一协议才能承诺更细粒度恢复。

### 11. 资产包、导入和本机配置

首版采用版本化 JSON 定义包，包含格式版本、资产身份和版本、入口、角色、团队或工作流定义、输入输出契约、布局、固定版本子定义、依赖声明及可选示例输入。

导出包不携带本机模型凭证、绑定 ID、会话、运行上下文或运行历史。角色提示词作为定义内容导出时必须清楚可见；引用人格时区分实际导出内容与需要本机匹配的依赖。子定义不能只保留原机器的本地 ID。

依赖声明表达逻辑槽位、能力、必要来源或兼容性要求。同名不等于兼容，不将本机授权随包迁移。

导入行为依次为：

1. 校验包格式、契约、角色及子定义引用、条件与循环限制；未知或不支持的格式版本明确报错，不静默接受。
2. 展示识别结果和本机匹配预览，仅自动匹配明确兼容且无歧义的资源。
3. 资源齐全时通过一次确认完成安装；缺失或歧义项集中展示并提供配置入口。
4. 一致保存定义和绑定；允许保留待配置资产，但未就绪时不能执行，校验失败不留下半份可执行安装。
5. 重复导入识别已有内容；升级生成新定义版本，不覆盖已有运行快照或静默改写同身份同版本的不同内容。

导入只安装定义和绑定，不运行包内脚本，不自动安装插件或部署外部模型、服务。

### 12. WebUI 和明确聊天调用

两个入口调用同一运行服务，传入实际发起身份、来源和输入。普通聊天支持明确指定已配置团队或工作流；名称歧义或必填输入缺失时先补齐，不默认开启自主猜测与隐式路由。

聊天用户仅能访问已向其开放的资产和本机资源，复用既有身份与权限机制，不把普通平台身份映射成 Dashboard 管理员。具体平台映射在接入任务中验证。

来源会话收到受理状态与最终结果；完整过程由统一运行详情展示。人工输入使用同一持久化接口，平台缺少交互组件时可进入 WebUI 处理。消息、过程记录和产物维持原有可见范围。

### 13. 工作台与视觉交互

工作台按资产和运行组织：

- 资产包含团队、工作流和角色模板；提供概览、输入输出、就绪检查、编辑、资源绑定、导入导出及发起运行。
- 运行包含进行中、待处理和历史；详情优先显示目标、进度、待办和产物，并提供执行图、任务尝试及成员过程。
- 设计模式修改定义；运行模式只展示该次快照。角色模板与实际运行成员使用不同标签和详情，避免把模板配置误认为当前实例状态。

画布采用节点工具箱、主画布和属性面板，复用已有 Vue/Vuetify 与画布能力。提供拖放、缩放、适配、小地图、撤销重做和自动布局。节点突出任务名、角色、输入输出及状态；详细能力配置进入属性面板。循环和子流程使用可折叠分组，条件以可读字段规则呈现。

运行图展示实际任务关系、当前迭代、等待原因和产物版本；自主协作可展示动态生成的任务关系，不要求用户预先画出完整工作流。

角色页面提供概览卡与分组配置，覆盖职责提示词、模型、工具与技能、知识库及限制。继承来源、有效值和局部覆盖可见；缺失资源既定位到字段，也汇总到资产就绪检查。

运行监控按需展开输出、提供商返回的思考内容和工具明细。采用 AstrBot 明暗主题和设计变量，统一文字层级、间距、圆角及工具栏密度。角色身份与执行状态采用不同表达；状态提供文字或图标，不仅依赖颜色；支持减少动画。

窄屏将工具箱和属性面板折叠，优先保证任务、待办与结果可读；长名称、空状态、失败和缺失资源不能导致关键操作被遮挡。对话框遵循仓库现有 Vuetify 标题与按钮约定。

本轮确认的 HTML 原型是布局和交互参考。其模拟运行、示例资源、样例导出格式和固定演示文案不构成生产协议，也不要求直接复用其单文件实现。

### 14. 迁移与旧入口

旧成员配置转换为角色定义，旧工作流节点改为角色引用，保留可表达的名称、有效配置、连线和布局，并保存旧新标识映射。不兼容的旧循环或资源引用必须报告并进入待配置，不静默删边或替换配置。

迁移前列出旧活跃运行并安排结束或停止。旧运行和长期会话只读保留；旧未完成运行作为历史中断记录，不能交给新引擎原地续跑。用户可以用迁移后的定义发起全新运行，新成员不继承旧会话。

迁移具有事务与重复执行检查；再次运行不重复创建。移除旧执行入口时保留读取历史所需的路径。

| 旧入口 | 新入口 |
| --- | --- |
| 团队侧栏 | 资产 → 团队 |
| 编辑标签页 | 资产 → 工作流 → 编辑 |
| 成员标签页 | 资产 → 角色模板；团队内保留角色关联配置 |
| 监控标签页 | 运行 → 运行详情 |
| 历史标签页 | 运行 → 历史；旧引擎记录标记只读 |

导航、页面结构或术语变更与中英文说明、截图、入口映射和变更日志在同一 PR 交付。纯视觉整理尽量与功能增加分开；必须同时变化时说明原因。

### 15. 实施约束

遵守仓库 KISS、组件化和现有代码约定，不为每个领域名词新增抽象层。后端 API 或 Schema 变化同步生成前端客户端；相关代码完成规定的格式、静态检查、类型检查和行为验证。

实现兼容项目支持的 Python、Windows、macOS、Linux 和处理器架构；文件与临时存储沿用项目跨平台路径能力。

表结构、具体工具名、接口字段拼写、面板像素尺寸和默认限额由实现任务确定，但不能改变上述可见行为、权限边界和恢复保证。它们的细化不要求重新讨论已确认产品方向。

## 测试决策

### 已确认的公共边界

用户已于 2026-10-11 确认：以 WebUI 和聊天共用的资产／运行公共服务接口作为主要测试边界；辅以少量现有 HTTP／聊天入口接入测试和 WebUI 关键交互验收。后续实现沿用该边界，不为测试额外创造一层生产包装接口。

测试通过公开的创建、配置、启动、查询、控制、回答、结果读取和导入导出行为观察结果。断言用户可见状态、产物、调用次数及外部效果，不以私有方法、表结构、内部容器或逐层 mock 调用序列作为正确性标准。

调度测试可沿用可注入执行适配器，以确定性脚本控制快慢、失败、等待和并发。恢复测试使用真实数据库和实际执行／检查点链路，在外部模型与工具边界提供可控替身；必须包含独立进程终止后重新构建服务并恢复，不能仅通过正常取消、内存对象重建或页面断连证明崩溃恢复。

为工具效果提供独立于被终止执行进程的可观察记录，区分“调用已经发生”和“结果已经持久化”。在关键边界注入故障，验证已完成调用没有再次发生，以及结果不明时确实阻塞。

不要求付费模型在线调用成为常规测试的前提。提供商返回思考与必要签名、多模态引用、远端状态查询等行为使用真实接口形状的可控响应验证。

### 现有测试先例

- 现有 AgentTeamService 和 AgentTeamRunService 测试覆盖定义校验、临时 SQLite 数据库、执行适配器、启动、控制、恢复及所有权，可复用其公共边界和测试设施。
- 现有 API 测试使用轻量 FastAPI 应用与依赖替换验证错误响应、字段级校验、身份传递、历史分页和事件流，适合少量入口契约验证。
- 现有执行集成测试覆盖配置档案、人格、工具和技能允许范围及主管道传递，作为避免旁路现有能力的回归先例。
- 现有聊天历史、交互选择和对话检查点测试覆盖文本、思考、工具调用／结果及序列化行为；其正常结束保存不构成本规格调用级崩溃恢复的替代证明。
- 现有前端页面、工作流编辑器、角色配置、运行监控和事件消费测试可作为行为交互先例。改版后更新已改变的用户行为断言，不保留旧标签布局作为硬性约束。
- 现有测试中直接读取数据库或私有 runner 的写法不作为新增测试必须模仿的标准。

跨机器验收至少使用隔离的数据目录与不同本机绑定，并进行实际导出、导入和运行，不能只在同一实例验证 JSON 往返。

视觉验收基于正式 WebUI 实际页面，覆盖画布、角色配置、运行详情和导入配置。HTML 演示正常工作不能替代生产页面验收；无需为纯装饰样式增加与实现互相复述的单元测试。

### 完成条件

主场景、上述行为与故障矩阵、相关既有回归、规定的代码检查和 API 客户端生成均通过；涉及的中英文文档与截图完成更新。尚未支持的第三方执行器能力必须准确声明并被就绪检查执行，不能以统一“可恢复”标记掩盖差异。

本规格编写阶段未实施上述功能或新增测试。此前针对聊天历史、交互选择和对话检查点的 40 项通过结果，仅是已有能力的调查依据，不计为新版验收通过。

## 范围外

- 自动安装导入资产所需的插件、技能包、模型或外部服务。
- 将本机凭证、运行会话、消息历史或知识库内容打包为协作定义的一部分。
- 将旧引擎的未完成运行原地转换成新版可安全恢复的运行。
- 恢复尚未完整保存的半段模型流式生成，或保证远端模型请求不产生重复计费。
- 对任意外部工具提供无条件恰好一次执行保证，或自动重放结果不明的副作用。
- 任意图回边、无限循环、无限嵌套和任意用户代码条件执行。
- 默认自动识别所有普通聊天意图并自主选择团队或工作流。
- 多节点分布式调度、通用工作流平台、完整事件溯源体系。
- 自动让新版产物覆盖历史审批，或对所有下游消费者级联重跑。
- 将其他独立子智能体体系一并合并重构。
- 将 HTML 原型的模拟运行及演示包格式直接作为生产实现。

### 后续拆票原则

以可以独立验证的完整行为拆分任务，显式标注真实阻塞关系；不要把数据库、API、前端分别变成横向巨型任务。每张票引用相关 US 和 AC 编号，并包含该行为必需的迁移、接口、界面和验证。

原设计中的阶段仍可用于里程碑：执行与检查点基础、工作流主链、自主协作与嵌套、资产移植与聊天入口、完整工作台及迁移交付。阶段不是单张任务票，也不意味着界面与验证必须等全部后端完成才开始。

本 Issue 是后续任务的需求与验收来源；本地规格保留同步副本。更改用户可见行为时先更新主规格，再更新受影响任务，避免形成互相冲突的并行计划。
