## 问题陈述

用户需要让多个 Agent 按明确流程或自主分工完成任务，并在关键节点做出有依据的判断。当前资源槽位、多个工作流创建入口、版本与运行细节混在一起，使简单任务也需要理解过多内部概念；复杂流程的输入、分支、循环和人工返工路径又不够直观。

运行页面不能完整、持续地展示每个 Agent 的实际执行过程。动态 ask_user_choice 与预设人工节点使用不同的等待机制，用户可能看到任务停止推进，却找不到可回答的入口。JSON 堆叠、状态混用和后台刷新造成的闪烁进一步妨碍阅读与判断。

用户还需要明确的资产删除入口、稳定的草稿和固定版本、可验证的试运行，以及不易漏填的聊天授权配置。这些能力必须在同一套产品语义下工作，不能只用新的视觉外壳包住原有的不一致行为。

当前 Agent Teams 尚未投入使用。本次直接采用新格式，不承担旧资产、槽位、资产包和旧运行的迁移或兼容。

## 解决方案

提供统一的 Agent Teams 工作空间，管理自主团队、工作流和角色模板：

- 工作流从一个 Agent 开始，在同一画布扩展为条件、并行汇合、有界循环、人工问答／审批及子流程调用；节点侧栏直接选择实际资源和明确的上游输入。
- 自主团队预设协调者和可用角色，由协调者动态选择成员并分派任务；成员可以直接配置，也可以引用固定角色模板版本。
- 资产编辑自动保存草稿，用户手动保存固定版本。正式启动、聊天访问和资产引用使用明确版本；草稿试运行独立记录。
- 运行默认采用“任务／Agent 树—详细执行过程—人工待办与产物”三栏。执行图作为可切换总览，窄屏保留同等操作能力。
- 画布人工节点和运行时 ask_user_choice 汇入同一持久请求机制。用户能先阅读过程、上下文、推荐理由和精确产物版本，再从 Dashboard 或原聊天提交决定。
- 删除退出可用列表且禁止新的直接启动，同时保留既有固定引用、正在运行的任务、历史和产物。

交互参考已制作的 HTML 原型，并借鉴 Dify 的节点配置与数据选择、LangGraph Studio 的执行追踪组织；正式实现继续服务 AstrBot 自身的执行、权限和恢复语义。

## 实现决策

### 1. 产品边界与复用策略

本次只重构 Agent Teams 的版本化资产、编排与运行体验。复用现有资产／运行公共服务、图调度、执行投递与收集、主 Agent 执行管线、持久化、权限和恢复能力；保留 Vue Flow，并复用 ChatUI 的消息、思考、工具、文件及注入信息渲染能力。

不嵌入整个普通聊天页面，不新建第二套模型执行引擎或通用消息平台。按资产、流程定义、执行恢复、人工交互和过程观察的实际职责收敛实现；只有所在切片确有需要时才抽取模块，不安排无人调用的预重构层。内部重构不得改变新格式运行的权限、用量、调用身份和未知工具结果处理。

### 2. 统一资产与直接资源格式

角色模板、直接配置的工作流 Agent、自主团队协调者及预设成员共用直接资源配置语义。人格、模型、工具、Skills、知识库保存实际资源引用，显示名称仅用于展示。接口、持久化、运行冻结配置和新版资产包均不使用资源槽位、别名或运行期绑定映射。

继续校验资源存在性、所有者可用范围、人格限制、模型及执行器能力。无效资源定位到具体节点和字段，不静默替换。既有执行器不支持的本机能力不因改版而开放。

直接配置 Agent 可不使用人格，不继承发起聊天或配置档案的人格。团队／工作流明确配置默认模型，直接配置 Agent 可覆盖；启动前必须确定实际模型，不回退到发起聊天的临时模型。模板 Agent 的有效配置依固定版本和本地覆盖计算。

### 3. 角色版本、继承与覆盖

角色引用同时保留资产身份和固定版本。新版本提示不改变有效配置，用户手动升级才采用新版本；本地覆盖在升级后保留，未覆盖字段跟随所选版本。

工具、Skills、知识库各自只有继承模板或自定义完整列表两种配置方式；空自定义列表表示全部禁用，不保存增减项补丁。界面明确显示字段来源。直接配置的 Agent 可保存为可复用角色模板，不强制创建模板才能运行。

人格提供通用设定，职责提供角色分工，任务提供本次目标；三者组合并分别记录来源。覆盖字段的未设置、明确清空和具体值必须能区分。

### 4. 编辑工作区与图契约

资产创建只提供自主团队和工作流两种意图，角色模板作为可复用资产管理。新建工作流直接进入预置一个 Agent 的画布；单 Agent 与多步骤流程使用同一资产定义和编辑方式。

首批节点覆盖输入／输出、Agent、条件、并行汇合、有界循环、人工问答／审批、子工作流及自主团队调用。节点类型、摘要和状态可辨识；从目录添加、连接、拖动、缩放、定位、删除及撤销／重做不破坏引用。沿用现有画布能力，不将已有缩略图或自动布局重新实现为另一套组件。

控制连线描述顺序或命名分支，数据引用通过侧栏按上游节点、输出字段和类型选择。引用校验由后端规则负责，前端显示可定位错误。复制、删除、改名和调整结构不得静默保留悬空引用。仅为了本次必要交互完善编辑操作；尚未确认的批量编辑、高级代码模式等不自动扩为独立功能。

输入与输出节点有真实的运行契约。Agent 默认输出文本，按需通过表单定义结构化字段及类型；不要求手写 JSON Schema，也不自动将所有 Agent 输出结构化。

### 5. 输入、调度与循环

下游仅获得显式选择的上游数据；执行连线不隐含共享其他 Agent 的对话、工具过程或完整上下文。必要的人格、职责和当前任务仍按本节点配置注入。

汇合等待本次实际进入的所有分支成功，条件跳过的分支不参与等待。不提供 ANY／竞速汇合。局部失败阻塞该路径及依赖它的下游，独立分支继续；被阻塞的汇合不能因部分成功提前执行。

循环是可见的有界结构，保存最大轮次及退出／反馈关系；运行按轮次保留任务和产物身份。达到上限未满足退出条件时给出可解释结果，不无限回边。审批退回依据显式命名出口和用户配置的返工路径，不默认交给原生成 Agent。

### 6. 自主团队与嵌套调用

自主团队预设协调者和可用角色，均支持直接配置或固定模板引用；协调者只能在此范围内选择成员和动态安排任务，不自由创建新的角色或资源权限。

子工作流和自主团队调用固定资产版本，在独立作用域运行，返回明确选定的结果。任务树、过程、待办和产物保留根运行、子作用域、成员、任务、尝试与轮次的归属；同名成员或同一模板被多次调用不能串用记录。深度、并发、实例和用量约束沿用实际执行器的既有规则。

### 7. 草稿、固定版本与试运行

角色、团队、工作流编辑自动保存草稿，并显示保存中、已保存、失败和冲突。草稿更新使用明确的修订并发控制，迟到保存不覆盖更新状态。手动保存新版本才形成不可变引用；已有版本及已启动运行的冻结配置不随草稿或新版本变化。

试运行支持单节点、局部流程和完整流程。选择已有上游结果时固定其来源及版本；手填输入仅替代指定上游数据。缺失或类型不匹配在执行前提示。保存草稿快照和测试范围，测试记录独立于正式运行，并说明所选步骤真实调用模型与工具。

试运行不绕过权限、能力和执行准入，不修改已有正式结果。测试一个产生外部效果的步骤可能产生新的实际效果；不会把历史回放或更改输入描述成撤销外部效果。通用历史分叉编辑器不属于本次必需交付。

### 8. 运行展示与稳定刷新

默认以任务／Agent 树、所选 Agent 过程、人工待办／产物三栏组织运行，执行图可切换查看。窄屏可用页签或面板切换，保留同一运行和选择状态；最终视觉在已确认信息结构内收敛。

状态分开表达尚未启动、等待依赖、等待容量、等待人工、执行中、暂停、失败、取消和完成等实际原因。后端事实决定状态，不能用流结束或最后一段自然语言判断任务成功。

后台增量更新保持页面、页签、节点选择、滚动意图和正在填写的答案；刷新过程不卸载整个内容区域，不切换到空态或其他页面。切换成员和关闭页面只改变观察订阅，不结束执行。

### 9. 可续读的详细过程

在现有执行事件与持久过程能力上扩展统一可读记录，覆盖回复／思考增量、模型调用、工具开始／参数／进度／结果／错误、上下文来源、人工请求／决定及状态变化。

事件保留稳定归属与去重身份、顺序及续读游标。首次快照和后续订阅有一致边界；断线按游标补齐，重复事件不会重复显示。实时片段与最终完整消息归并为同一条记录；记录确实缺失时显示缺口，不拼造内容。历史与实时展示使用同一语义。

连续文本可以有界批量保存，不要求每个 token 单独提交；人工决定、工具和执行边界及时持久化。长过程按需加载，订阅和缓冲有界。保持原有审计、用量及未知外部效果事实，界面收到输出不等于工具成功。

### 10. 实际上下文与可观察边界

每次模型调用关联实际注入内容及来源，至少包括人格、职责、任务、明确上游输入、知识与 Skills，以及已有注入追踪能提供的追加、替换、裁剪信息。配置摘要与实际发送内容分开，不能把预期配置当成实际请求。

思考仅展示模型或执行器真正返回的内容。缺失、截断或远端不可观察范围明确说明。工具参数和结果以文本、字段、表格、文件或错误呈现；JSON 仅为按需调试详情。运行过程、文件及上下文读取均校验现有权限，不因能回答某个请求而获得所有者的全部配置。

### 11. 统一人工请求与动态工具接入

画布问答、精确产物版本审批、运行时 ask_user_choice 共用持久人工请求的发现、读取与作答边界；不同请求保留各自的输入、动作及审批语义。未知工具外部效果的人工确认仍使用既有恢复语义，不冒充产物审批。

人工请求关联原运行、作用域、任务、Agent、尝试和工具调用；保留问题、选项／允许的自由输入、推荐、来源依据、产物版本、可回答身份及状态。展示前先保存请求；决定提交后先保存唯一有效结果，再由有执行权的原调用消费。

动态工具不能仅挂在易失的内存 Future 上，不能用重新执行整个节点代替回答。普通 ChatUI 的既有 ask_user_choice 超时与回退行为保持不变；只有经过可信团队执行上下文进入的请求采用本规格的持久等待策略。团队内等待不会被普通聊天的默认超时、GC 或旧回退文本偷偷结束。

### 12. 人工等待、恢复与竞争

人工等待只阻塞依赖答案的步骤，独立分支继续。等待本身不应占满活跃执行配额而使独立分支无法推进。问题、关联证据和已提交答案持久化，真实服务重启后恢复原请求与原尝试，已确认完成的步骤不重跑。

同一请求从多个页面或聊天重复回答只生效一次；已处理请求返回可解释的当前结果。全局暂停时允许保存决定，恢复执行许可后才消费；取消关闭未决请求且不释放下游。答案、取消、超时和恢复之间的竞争以持久状态和执行权为准，迟到回调不能复活取消的运行。

不承诺任意外部副作用恰好一次。遇到结果未知的工具调用继续保持既有阻塞和显式处置规则，不因重启或收到答案自动重放外部效果。执行器无法满足必要恢复能力时启动前给出能力错误，不能宣称已经具备持久恢复保证。

### 13. 推荐与超时策略

默认没有回答期限。请求可配置期限及超时动作：继续等待人工，或采用创建请求时已展示的有效推荐。该策略适用于问答、选择和产物版本审批，必须显式启用才会自动决定。

推荐包含明确的有效选项／动作及理由。动态问题由提问 Agent 提供，预设人工节点读取用户选择的上游 Agent 输出；独立评审使用显式评审 Agent。不能从任意说明文字猜测选项，也不能在超时后偷偷再次调用模型。缺少有效推荐时继续等待并显示原因。

人工与自动决定分别记录来源及采用的推荐。截止时间与请求状态持久化，重启不重置计时；超时期间若全局暂停，可记录有效决定但不推进执行；取消优先关闭请求，不能以迟到超时唤醒。

### 14. 人工待办、聊天绑定与双端作答

统一“需我处理”只列用户有权回答的人工请求，入口显示数量并跳转到提出问题的具体 Agent、过程和产物；运行详情处理同一请求，不另造副本。

聊天访问只需粘贴完整 /asset whoami 返回内容，解析并校验平台实例、发送者、UMO 和配置档案；UMO 不被假定必然包含发送者。完整解析不代替服务端资产归属和授权校验。聊天绑定固定资产版本，错误或缺字段的输入不得形成部分授权。

聊天发起的运行将问题、选项、推荐理由和可访问证据发回原聊天；支持原发起者与具备既有权限的 Dashboard 用户处理同一请求。群成员身份不能代替原发起者身份，不能仅按群 UMO 授权。回答定位到请求而非仅凭最近一条消息；聊天投递失败、重复投递与迟到回答有明确结果，Dashboard 仍可发现未决请求。

### 15. 资产删除与新版导入导出

角色、自主团队和工作流提供明确删除入口，只删除整个资产，不提供单版本删除。删除后所有版本退出可用列表和新配置选择范围；新保存的配置不能新增对已删除资产的引用，已有固定引用仍有效。

删除后的资产不能被 Dashboard 或聊天直接发起新运行，旧聊天绑定不能绕过限制；已开始运行继续，已有父流程固定版本调用继续，历史和产物保留。必要版本数据保留，删除不级联取消任务或清空运行证据；重复删除与并发启动、保存有确定结果。

新版导出包表达真实资源要求和资产闭包，导入时显式选择兼容的本机实际资源并改写引用；不把源实例资源 ID 直接当成本机资源，也不恢复运行期槽位表。继续保留固定版本、嵌套依赖、权限、内容一致性及事务完整性校验。旧格式资产包明确拒绝，不自动转换。

### 16. 新格式替换和交付约束

只实现新格式，移除旧 Agent Teams 迁移入口、旧格式解析、槽位映射和兼容执行路径。不得借分批开发保留双读、双写、旧资产升级向导或新旧模式切换。

共享资源格式替换涉及多条执行和资产包通路时，在同一隔离集成分支按纵向切片推进；受影响的早期切片可局部验证，但在所有新格式通路接齐前不声称可独立发布，也不通过兼容层让中间状态虚假保持绿色。集成票验证全部替换后才能合入可发布基线。其他后续切片在完整新格式基线上保持检查通过。

旧配置需按新格式重建。此规划不授权删除用户数据，不提供自动清库功能；新格式自身的存储结构变更仍遵循现有数据库管理方式。版本固定、历史保留和恢复要求针对新系统产生的数据，不要求兼容改造前的记录。

### 17. API、文档与原型边界

扩展现有资产／运行公共接口以支持草稿、固定版本、直接配置、图校验、试运行、过程续读、人工请求和删除；HTTP、聊天及工具接入共用服务端规则。保持统一错误表达、字段定位、归属校验及必要并发冲突处理。

接口和 Schema 变化同步 OpenAPI 与生成客户端。导航、术语和操作变化同步中英文说明、真实实现截图及旧入口到新入口的映射；正式交付按仓库规范记录必要的导航变更。本轮不改发布版本或历史 changelog。

HTML 是交互探索，不是生产实现或验收证据。资产布局 A／B／C 尚未被选为三个产品模式，不能将原型切换器、示例数据、假流式输出或内存状态模型搬成正式功能。已确认的三栏运行信息结构、画布与直接资源等行为应落实为真实链路。

## 测试决策

**已确认的主要测试 seam：现有版本化资产／运行公共接口。** 以同一公共行为驱动角色保存、资产编辑与启动、事件读取、人工作答、控制及删除；内部使用真实临时数据库、真实图调度与恢复逻辑。外部资源目录和模型／工具用现有可注入边界控制，优先复用 RoleAssetService、WorkflowService 与 TeamPorts 的设施，不另建通用测试总线。

HTTP 与聊天入口做必要的真实接线、鉴权和契约验证；主 Agent 集成场景用可控外部模型／工具服务穿过真实执行管线。WebUI 测试关注可见行为和输入，少量浏览器闭环证明 UI 与实际后端接通。以上是一个主要业务测试边界及其接入验证，不把每个内部类都变成新的 seam。

1. **好测试的标准。** 从公开操作与输入出发，断言保存后可读取的有效配置、实际交付给执行器的上下文／资源、用户可见事件、唯一决定和后续任务结果。避免断言私有方法调用顺序、具体表列或某个组件内部变量。
2. **资源与角色。** 五类资源直接选择并实际生效；未选人格不继承默认值；模型默认／覆盖可预测；版本升级保留本地覆盖；继承与空自定义列表不同；缺失、越权和能力不支持时不启动。
3. **图与数据。** 单 Agent、串行字段引用、结构化输出、条件跳过、并行 ALL 汇合、局部失败和有界循环均穿过真实调度。删除／改名／断开引用给出定位错误；未显式选择的上游对话不会进入下一 Agent。
4. **自主团队和子调用。** 协调者只使用预设角色，成员配置和固定版本正确；相同模板的多个实例、嵌套作用域及循环轮次彼此隔离；深度、预算和并发限制不退化。
5. **草稿和试运行。** 自动保存刷新可恢复、并发冲突不静默覆盖、固定版本不漂移。单节点／局部／完整试运行使用固定草稿和指定上游输入，所选步骤确实调用受控执行器，记录与正式运行分开。
6. **可读流与上下文。** 受控模型真实发出正文、思考和工具事件，核对归属、顺序、首段输出、增量与最终合并、来源内容和缺失说明。并行 Agent 切换不能串流；仅关闭观察页面不取消执行。
7. **续读与性能边界。** 快照与订阅交界有事件到达时不丢失；重复和乱序到达按契约处理；断线后续读不重复。长历史有界加载，后台更新不替换页面或重置人工输入。不给任意机器承诺未经测量的吞吐指标。
8. **人工闭环。** 同时产生多个动态及预设问题，分别回答，答案回到对应原调用。精确版本审批、返工出口与有界循环真实执行；不是只让页面的状态标签变成已回答。
9. **重启与未知结果。** 复用真实磁盘数据库和受控工作进程终止的先例，在请求提交、答案提交、答案消费及产物提交边界重建服务。通过独立外部调用记录验证不重复已完成步骤、不盲目重放未知工具效果。
10. **并发决定与控制。** 用屏障和可控时钟验证两端同时回答、取消与回答竞争、暂停后作答、恢复和迟到超时；只保存一次有效决定。拒绝已取消或已处理请求的再次推进，不使用固定 sleep 猜测正确性。
11. **推荐与期限。** 无默认期限；两种超时策略分别验证；所有人工类型采用创建时推荐；无效推荐仍等待且不发起隐藏模型调用；重启不重置截止时间，记录可区分人工与自动决定。
12. **聊天与权限。** 整段身份解析在私聊／群聊有效，缺字段和错配拒绝；只有原发起者及既有授权者可以作答。Dashboard 与聊天共享请求；其他群成员、其他用户、伪造运行／作用域／文件引用不能越权。
13. **普通 ChatUI 回归。** 普通 ask_user_choice 的开关、超时、回退、自由文本回答和现有事件接线保持原行为；只有团队执行使用新的持久等待与推荐策略。Agent Teams 的变化不接入范围外的普通会话协作调度。
14. **删除与导入。** 删除后新选择和直接启动拒绝、已有固定调用和运行继续、历史可读；重复和并发删除结果明确。新版资产包跨不同资源 ID 导入后有效；缺依赖、越权、半失败不产生半导入；旧槽位格式明确拒绝。
15. **已有先例。** 版本化工作流 HTTP 测试已使用 FastAPI TestClient 与真实 SQLite；公共工作流场景使用真实资产服务和可脚本化 TeamPorts；图测试已覆盖条件跳过与无关分支继续；人工和检查点测试使用独立外部服务账本及真实进程退出；Vue Test Utils 与 Vitest 已覆盖待办、产物预览、版本化工作区和后台轮询稳定性。复用这些可观察断言和设施。
16. **交付判定。** 每个切片同时完成必要存储、公共接口、UI、契约生成、行为测试和受影响说明；不把全部测试推给最后一票。最终用真实 Dashboard 与受控执行器演示完整流程、恢复、双端作答和删除，并执行仓库要求的格式、静态检查、相关测试与前端构建。兼顾 Python 3.10+ 以及 Windows、macOS、Linux 的现有项目约束。

## 范围外

- 旧角色、槽位、资产包、旧运行的迁移、兼容执行或自动清库。
- 独立工具调用、HTTP、代码、知识库检索和数据转换等通用自动化节点；它们是后续方向。
- Agent 自由创建普通 WebChat 会话、动态角色并跨会话发消息；这由独立的普通会话协作功能处理。
- ANY／竞速汇合、无界循环、自动推断返工对象或隐藏评审模型。
- 模板自动升级、发布审批流程、单个资产版本删除及历史永久清空。
- 整体替换为 LangGraph 执行引擎，迁移到另一套画布框架，新增消息中间件、分布式集群或微服务部署。
- 根据回复猜测或生成模型思考；把配置摘要冒充实际注入上下文。
- 对所有未知外部副作用承诺恰好一次；在不支持的远端执行器上假装具备完整观察或恢复能力。
- 普通 ChatUI 的全局超时策略改造、多账户体系改造、操作系统沙箱改造。
- 原型 A／B／C 作为可配置产品模式、通用历史分叉编辑器、所有调研中提及的高级编辑便利功能。
