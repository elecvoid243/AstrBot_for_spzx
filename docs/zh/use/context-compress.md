# 上下文压缩

在 v4.11.0 之后，AstrBot 引入了自动上下文压缩功能。

在 `配置文件` 中选择要修改的配置文件，进入 `AI → 高级 → 上下文管理策略` 设置压缩策略，然后点击右下角的 `保存配置`。

AstrBot 在每次模型请求前检查上下文，包括工具执行后的后续请求。提供方设置了正数 `compress_threshold_tokens` 时使用该绝对阈值，否则使用模型窗口的 82%。计量包含系统提示词、消息和工具定义；输入加上生效的输出预算仍须放进模型窗口。摘要可能遗漏细节。

是否触发压缩只取决于 Token 预算，不再按对话轮数预先截断；轮数仅在“按对话轮数截断”策略内部决定一次丢弃多少。

## 压缩策略

目前有两种压缩策略

1. 按照对话轮数截断，删除较早完整轮次。启用 token 预算截断时，默认目标为模型窗口的 40%，保留最新轮次和已标识摘要。
2. 由 LLM 生成摘要，这是新配置的默认策略。可指定摘要模型，留空时尝试当前会话的聊天模型。压缩提示词是内置的固定结构化模板，不再提供配置项。

压缩后仍有压力时，AstrBot 从最早的普通历史轮次开始裁剪，保留系统消息、摘要和当前完整轮次。只超过压缩触发阈值时不会强制删除受保护内容；如果受保护内容、工具定义和输出预算仍超过模型窗口，请求会以明确的上下文容量错误停止。请缩小当前输入、减少工具定义、降低输出上限或选择更大的模型窗口。

- AstrBot 会在每次对话请求前调用压缩器进行检查。
- 一个长轮次包含多个工具批次时，可以摘要较早的完整批次，保留当前用户请求、最新工具批次和近期原文。并行调用与结果不会拆开，未知执行状态和系统指令保持保留。压缩不会重新执行工具。

## 阈值、目标与重试

- 触发阈值：`min(窗口 × 0.8, 窗口 − 输出预算 − headroom)`。提供方的 `compress_threshold_tokens` 仍可覆盖，但会被钳制到同一压力预算内。
- 保留尾部：按消息预算的 `keep_recent_ratio`（默认 `0.15`）保留原文；只会落在工具调用/结果的平衡边界，不会拆开一个批次。
- 目标水位：压缩后尽量降到窗口的 `55%`。一次摘要不够时，同一步最多再压一次；仍不达标会在压缩报告中标记为不足，并回落到逐轮丢弃或容量错误。
- 全文压缩的 checkpoint 是一条带 preamble 与 `<compacted-summary>` 标签的 user 消息；轮内压缩保留 assistant checkpoint，当前用户请求原文不动。
- 提供方级 `compaction_headroom_tokens`（默认 `16384`，会按窗口大小收敛）与 `compress_threshold_ratio`（默认 `0.8`）用于控制触发位置。

## 工具输出修剪与摘要保留

有读取工具和输出目录时，内置 Runner 在上下文有压力后，先尝试将超大的历史工具结果缩为头尾预览，保存完整原文并附上可读取位置，非文本内容保持原顺序。预览总量不超过约 7,000 个估算 token；落盘失败时该历史结果保持原文。修剪足以释放空间时不调用摘要模型。超过约 27,500 个估算 token 的新结果即时落盘机制继续生效。

生成的摘要通过内部标识获得保护。标识在历史保存、恢复和模型切换时保留，但不发送给模型提供商。新的有效摘要可以合并替换旧摘要；空摘要、未缩短内容的摘要，以及生成期间输入已变化的摘要不会替换历史。摘要失败时，已有标识继续有效，普通旧历史仍可被裁剪。

旧会话中没有标识的摘要不会仅凭文字前缀自动获得保护，以免误认用户消息。有可压缩历史时，可以发送 `/compact` 手动生成带标识的新摘要。只有一个工具批次时可能没有可安全缩减的范围。

## ‼️ 重要：模型上下文窗口设置

默认情况下，当您添加模型时，AstrBot 会自动根据模型的 id，从 [MODELS.DEV](https://models.dev/) 提供的接口中获取模型的上下文窗口大小。但由于模型种类繁多，部分提供商甚至会修改模型的 id，因此 AstrBot 不能自动推断出您所添加的模型的上下文窗口大小。

打开 `模型提供商 → 对话`，在左侧选择模型所属的提供商，在右侧模型列表中点击已添加的模型，编辑上下文窗口大小（`max_context_tokens`）并保存。

未填写窗口时，AstrBot 会尝试从 MODELS.DEV 元数据解析容量，并使用配置中的回退窗口。自定义模型名称可能无法识别，请显式配置准确容量。摘要模型也需要足够的输入空间和输出预算。
