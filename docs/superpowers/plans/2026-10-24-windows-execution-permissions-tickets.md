## 拆分原则与共同验收约束

每票交付一个可演示或可验证的完整行为，包含该行为必要的策略、执行、API、UI 和测试；不把数据库、后端、前端拆成互不交付的横向票。W01–W04 是可复现的原生可行性切片，不宣称已提供产品功能。尚无证据需要独立的大范围预重构票，沿现有 ProcessSandbox、工具调度和 Shell session 接口扩展。

以下约束适用于每一张票，发布时应携带与该票相关的约束，不能只让实现者依赖未提交的本地文档：

- 模型代码不可信；宿主和已安装插件实现可信。实际资源边界覆盖进程树、别名和并发，不能用命令黑名单或提示词替代。
- 始终失败关闭；不创建无沙箱回退、自动放宽、永久解释器白名单或默认复制工作区方案。
- Windows 支持范围须以实测为准；未支持的平台、文件系统、路径或工具链明确拒绝。
- readonly 允许私有可丢弃临时写入；workspace 允许原工作区及获准附加目录的数据写入；两者均默认禁止网络和范围外读取。
- 新会话及旧 full 采用 workspace，已有 readonly/workspace 保留。模式及显式目录持久保存，临时授权和任务不跨重启恢复。
- 所有资源在产生宿主侧准备副作用之前完成校验。保护控制端代码、配置、凭证、审批存储、句柄及管理接口。
- UI、API 与后端状态一致；权限不足、后端不可用和程序错误可区分；涉及 API/schema 的票同步前端客户端，界面说明变更同步中英文用户文档。
- 每票增加真实行为测试及相关关联审计，不记录凭证；操作系统隔离测试不能以 mock、sandboxed 布尔值或 Windows skip 代替通过。
- 前序测试成为回归。最后一票验证组合行为，不承担前序未做的安全边界。
- 分阶段未适配入口保持拒绝；W14 通过前不宣称整套机制已可正式替代旧权限保证。

## 已确认的测试边界

产品主线复用 FunctionToolExecutor 的公开工具调用边界，使用确定性模型输入，贯通真实 Windows 后端，并检查真实文件、网络接收记录与进程树。审批和会话归属经现有 WebUI HTTP API 验证，少量浏览器用例检查审批与状态展示。W01–W04 暂以现有 ProcessSandbox 作为最高可用入口，样例在产品接入后经主线复验。

这套已确认方案复用现有工具调度、子 agent、Shell 生命周期、模式持久化和 FastAPI 鉴权测试方式，不要求真实 LLM，不把每个内部层级变成单独测试入口。具体 Windows build、架构、文件系统和工具版本随实测记录。

## W01 — 验证离线 Python 的最小 Windows 隔离执行

### 构建内容

维护者通过现有 ProcessSandbox 入口，在原生 Windows 上启动一个非管理员 Python 进程：读取获准样例、进行计算并使用私有临时空间，同时真实拒绝未授权读取、持久写入与网络访问。

### 验收标准

- [ ] 以 AppContainer/LPAC 等候选建立可重复实验，记录准确运行环境和实际授予的能力；不将候选名称视为隔离证明。
- [ ] 获准目录读取和临时计算成功；宿主当前用户可读的未授权哨兵文件仍不可读；读取宿主秘密和修改持久样例均失败。
- [ ] 默认拒绝入站和出站 IPv4/IPv6、UDP、DNS、loopback 与外部服务连接，子进程结果一致；连接证明使用受控测试服务。
- [ ] 用户代码运行前已受 Job 和身份约束；后代不能脱离；有限期限到达能终止整棵树，父进程提前退出不遗留无限执行。
- [ ] 最小环境与句柄继承不暴露宿主 Token、凭证或可写文件句柄；Python 原生调用不能绕过基本边界。
- [ ] 不支持的解释器、系统、后端初始化失败均返回明确不可用，观察到无裸 subprocess 回退。
- [ ] 留下可重复的行为测试和候选取舍，明确尚未覆盖的原目录、故障及兼容性问题；该票不开放产品入口。

### 被以下阻塞

- 无——可立即开始。

## W02 — 验证原工作区访问、路径竞态及并发权限隔离

### 构建内容

在 W01 的真实后端中，使用原工作区分别完成只读分析和授权读写；同时证明两个会话、同会话不同策略的执行不会合并权限，路径替换不能改变授权边界。

### 验收标准

- [ ] readonly 原数据不变，workspace 普通文件创建、修改、删除成功；附加读/写目录按模式生效，不依赖整个项目复制写回。
- [ ] 覆盖大小写、短路径、卷/设备路径、UNC、junction、符号链接、hard link 和运行期间重解析替换；无法证明安全的目标明确拒绝。
- [ ] 覆盖父目录删除权、非继承 ACL、对象所有权和跨边界硬链接；仅执行一次 resolve 或目录扫描不能满足验收。
- [ ] 并发只读与读写执行、不同会话和不同策略版本互不获得对方的动态权限、临时空间或进程控制能力；共享依赖只读。
- [ ] 动态 ACL 只变更本机制拥有的条目，回收保留用户原有和并发变更；准备目录及 ACL 操作本身也不能跟随恶意目标越界。
- [ ] 工作区与宿主运行安装、插件、解释器或审批存储重叠时，安全排除或明确拒绝；不存在可通过修改宿主后续加载代码获得执行的授权。
- [ ] 明确原目录严格边界的 go/no-go 结论及支持范围。无法满足时返回设计复议，不能标记为通过并继续产品接入。

### 被以下阻塞

- W01：需要真实受限执行身份与 ProcessSandbox 路径来验证文件系统及并发效果。

## W03 — 验证初始化、故障回收和本机代理边界

### 构建内容

管理者初始化后能以普通运行权限启动受限分析；中途杀死宿主、启动器或让清理失败后，越权执行不会继续，系统能进入明确故障状态并安全修复。

### 验收标准

- [ ] 确定是否需要常驻特权组件及身份凭证保存方式。用户授权管理员助手只执行固定安装/修复操作，模型无管理员命令入口。
- [ ] 对正常退出、启动中断、后代残留、宿主/启动器故障和回收中断做故障注入；先确认受限进程结束再撤销防护，不产生短暂放宽窗口。
- [ ] 重启不复用未清理身份，不自动恢复任务；清理可重试且只处理机制拥有的对象、ACL 和规则，保留用户改动。
- [ ] 真实拒绝通过宿主进程访问、注册表、管道、COM/RPC、WMI、计划任务、服务、桌面、WSL 等代理越界；必要通道有明确协议和身份约束。
- [ ] 进程数、内存、期限和输出上限可观察地生效；验证私有临时存储容量限制，不能以 Job 限制替代磁盘容量证明。
- [ ] 普通权限不足以添加授权或修复时明确失败，不静默扩大系统权限。用户可以识别未初始化、需修复和不支持状态。
- [ ] 记录可重复支持矩阵、部署方案、清理失败行为及不含秘密的关联审计；这些结果成为 W05 接入门槛。

### 被以下阻塞

- W02：需要已验证的动态身份、原目录授权与 ACL 所有权记录才能验证实际安装和故障回收。

## W04 — 验证仅能访问一个获准服务的网络执行

### 构建内容

维护者为一次受限执行授予一个测试服务的主机、端口和协议，Python 与其后代仅能连接该服务；授权到期或出口故障后不能直连或访问其他目标。

### 验收标准

- [ ] 在 W01 默认拒绝基础上实现受信任出口或等效机制；环境代理设置不作为安全边界。
- [ ] 授权绑定执行身份和有限期限；改名或复制程序、原生 socket、子进程不能绕过，其他执行不继承放行。
- [ ] 域名授权由可信组件处理解析、重定向、地址变化和 DNS rebinding；未授权私网及控制端服务仍拒绝，不能额外开放任意 DNS。
- [ ] 明确支持的协议及语义；HTTP 请求范围与原始 TCP 可达能力如实区分，未支持协议明确拒绝，不默认为全网络。
- [ ] 本机普通测试服务与 AstrBot 管理 API、数据库及其他控制服务明确区分，普通授权不能放行受保护接口。
- [ ] 覆盖双栈、UDP、loopback、LAN、UNC/SMB 及跨进程代理绕过；获准服务访问成功且未获准服务无请求记录。
- [ ] 出口崩溃、动态规则更新失败、超时与进程树结束均不恢复直连；回收没有存活执行短暂失去约束的窗口。
- [ ] 形成可重复测试及最小授权契约，供 WebUI 网络审批复用；本票不新增审批入口。

### 被以下阻塞

- W01：需要已具备默认网络拒绝和执行身份绑定的真实后端。

## W05 — 在只读会话中安全运行 Python 并返回结果

### 构建内容

用户在只读会话调用 astrbot_execute_python，实际受限执行读取工作区并返回文本或受控分析产物；工具和 WebUI 能如实显示策略拒绝及后端不可用。

### 验收标准

- [ ] 从公开 FunctionToolExecutor 调度进入真实 Windows ProcessSandbox，服务端生成含身份、版本、资源和期限的不可变快照；共享 LocalBooter 无可串权会话全局状态。
- [ ] readonly 不再因工具类别而拒绝 Python；读取和计算成功，写持久文件、读范围外数据和联网真实失败，程序错误与权限错误可区分。
- [ ] 本地 Python 不进入宿主 exec，也不保留裸启动回退；模型指定 sandboxed、环境变量或额外工具参数不能扩大权限。
- [ ] 同时在工具暴露与实际分派拒绝未适配工具、后台与委派入口；尚未接入的 Shell、文件、插件和 MCP 不能成为旁路，返回可理解原因。
- [ ] 既有模式入口不能绕开限制；当前尚未支持的模式操作返回明确不可用，不能转换为 full 或宿主执行。
- [ ] 以真实 Windows 进程重复 W01–W03 中适用的核心读取、写入、子进程、环境和故障样例，不能只检查传入参数。
- [ ] 私有临时目录独立；文本/产物限量；附件导出验证真实对象、类型、尺寸和重解析点，不暴露附件存储写权限或读取任意宿主文件。
- [ ] WebUI 显示后端就绪/未安装/不支持/故障及调用结果，启动与拒绝有执行关联审计。

### 被以下阻塞

- W03：产品执行前必须通过原目录边界、初始化及故障回收验证。

## W06 — 在只读会话中运行和管理受限 Shell session

### 构建内容

用户在只读会话运行受支持的 Shell，查看增量输出、在基线权限内输入命令或终止后台 session；进程及其所有后代持续受到同一沙箱边界约束。

### 验收标准

- [ ] astrbot_execute_shell 和 Shell session 路径全部通过统一策略及真实后端，移除 readonly 整体拒绝和原本的裸启动路径。
- [ ] 对支持矩阵内 PowerShell、cmd、Git Bash 分别演示读取、计算、输出以及 Shell→Python、Python→Shell；不支持工具链明确拒绝。
- [ ] 重定向、原生命令、后台启动和后代不能修改只读数据或联网；Shell 配置和环境不从宿主无条件继承。
- [ ] poll、输出查看、stdin、interrupt、terminate 均验证实际会话归属及有效策略；其他用户和会话不能借 session ID 访问。
- [ ] yield 仅返回后台状态，不终止或无限延长授权；根进程结束时仍跟踪后代，达到期限终止整棵树。
- [ ] 保留必要的增量输出和结束后读取能力，输出及保留周期有界；WebUI session 状态和真实进程树一致。
- [ ] 终止或后台读取故障不挂死控制端，也不以“根进程已退出”误报整个执行结束；复用并扩展现有生命周期回归。

### 被以下阻塞

- W05：复用已接入产品的不可变执行策略、默认拒绝入口及后端状态展示。

## W07 — 持久选择工作区权限并可靠收紧运行中任务

### 构建内容

用户在 WebUI 选择 readonly/workspace 并管理附加目录，实际 Shell/Python 按所选模式访问原工作区；收紧期间先终止超额任务，再显示生效，重启保留明确选择。

### 验收标准

- [ ] workspace 普通项目 CRUD 成功，范围外及控制端仍受保护；readonly 将所有持久写入目录降为只读，私有临时空间仍可写。
- [ ] 模式及附加读/写目录经身份、审批管理资格和会话归属验证并持久保存；客户端提供 UMO、API key 或插件 token 不能跳过管理校验。
- [ ] 新会话与旧 full 使用 workspace，已有 readonly/workspace 保留；恢复可写只恢复 workspace，损坏/未知策略错误不回退 full。
- [ ] 历史共享 temp、动态扩展根和控制端重叠目录重新校验；拒绝不安全目标，并在 UI 说明需要处理的配置。
- [ ] 收紧或移除目录先冻结新启动和敏感 stdin、推进版本，终止超额进程树并撤销授权后才报告生效；并发启动、输入和变更无法跨过该顺序。
- [ ] 终止失败保持阻塞及处理中/失败状态；符合新策略的任务仅经重新核验继续，不承诺回滚已有修改。
- [ ] 重启先完成后端恢复检查再接受调用，模式和目录正确恢复，旧运行不自动重启；关联审计不记录秘密。
- [ ] WebUI 同时显示持久模式、目录、收紧进度和错误；API 契约、前端客户端与相关用户说明同步更新。

### 被以下阻塞

- W06：收紧验收必须覆盖已经可运行、可交互和可后台化的 Shell/Python 执行树。

## W08 — 通过内置文件工具和补丁执行同一资源策略

### 构建内容

用户用内置读取、列表、搜索、编辑、写入和补丁工具处理已授权数据；切换工具不会绕过 Shell/Python 的读取和写入边界。

### 验收标准

- [ ] 对实际可调用的内置文件工具完成盘点和接入；只读读取成功、持久写入拒绝，workspace 普通写入成功，范围外读取同样拒绝。
- [ ] 授权针对实际对象及多目标操作的全部资源，实际访问抵抗路径替换，或交给同一受限 worker；不止在调度前做字符串检查。
- [ ] 补丁中的新增、删除、重命名、多个文件和隐含目录均按同一策略处理；模型 confirm 标志不是批准。
- [ ] 目录枚举、搜索和结果输出不能泄露未授权文件内容，受保护控制端目录及恶意链接无法通过读取工具旁路访问。
- [ ] 并发权限收紧和文件操作有可验证顺序，策略过期后不能继续开始超额操作；错误与拒绝在工具结果及 UI 可理解。
- [ ] W05 中仅这些已适配文件能力恢复暴露；直接分派及两套已有文件工具选择方式均受检查，未知工具仍拒绝。
- [ ] 真实文件副作用测试复用 W02 的关键链接和 ACL 样例，并与公开 Shell/Python 的结果对照一致。

### 被以下阻塞

- W07：需要已生效的模式、持久目录和并发收紧协议，不能另造文件工具专属权限状态。

## W09 — 在 WebUI 批准一次额外文件权限并执行

### 构建内容

只读或 workspace 会话遇到额外读取/写入需求时，用户在 WebUI 审阅一次具体调用并批准；执行仅获得所批目录权限，下一次调用仍使用原基础策略。

### 验收标准

- [ ] 请求绑定所有者、会话、执行、策略版本、工具、命令/代码、实际参数、cwd、环境摘要、额外资源、理由和有限期限；待审批不启动相应调用。
- [ ] WebUI 展示可审阅内容及权限范围，审批接口验证真实登录身份、审批资格、归属、请求状态及跨站请求保护；普通聊天 key、插件 token 和模型 confirm 不能审批。
- [ ] 启动前复验内容、目标对象及版本，并原子消费一次；重复提交、并发消费、参数变化、拒绝、过期及重启后批准均不能启动。
- [ ] Shell、Python 与已适配文件工具使用同一授权模型；控制端资源不能通过普通文件授权放行，授权不永久改变会话模式或目录配置。
- [ ] 权限持续至整棵执行树结束或期限届满；后台 yield 不提前撤销，后代也不无限持有；临时扩权执行关闭自由 stdin，基线交互仍可用。
- [ ] 收紧、用户撤销、会话终止或故障按现有生命周期终止超额执行并作废旧审批；WebUI 展示基础模式与本次额外权限。
- [ ] 已部分运行失败的代码不得批准后盲目自动重跑，重试必须作为新执行审阅；摘要绑定不被描述为冻结全部项目依赖。
- [ ] 通过 WebUI API 加真实 Windows 工具调用覆盖成功与伪造、重放、跨用户、过期及撤销，审批/消费/结束审计可关联。

### 被以下阻塞

- W08：需要同一策略下的执行器和内置文件操作，完成额外文件授权的完整工具覆盖。

## W10 — 在 WebUI 批准一次指定服务的网络访问

### 构建内容

用户审阅目标服务、协议、端口和期限，为本次执行批准网络权限；程序只能访问获准服务，执行结束、撤销或故障后权限失效。

### 验收标准

- [ ] 将 W04 的已验证网络契约接入 W09 的请求、认证、一次消费及生命周期，不增加第二套批准机制。
- [ ] UI 明示网络可达能力、有限期限和基础网络拒绝状态；不把网络批准描述成远端业务只读保证。
- [ ] 默认拒绝、单服务允许、未授权目标拒绝、域名变化/重定向/私网防护通过真实调用复验，适用 Shell 与 Python 及其后代。
- [ ] 控制端管理接口、数据库和其他会话服务不能通过宽泛 localhost 或普通单次批准开放；缺少所需后端能力时明确不可用。
- [ ] 域名、端口、协议或执行参数变更要求新请求；伪造、重放、旧版本、跨会话及过期授权均拒绝。
- [ ] 收紧、网络出口崩溃、规则更新失败和宿主重启不留下直连或活跃授权；WebUI 与审计如实显示终止/失败。
- [ ] 文件及网络权限可明确组合到同一具体执行，均受部署上限和保护规则约束，不因组合获得额外范围。

### 被以下阻塞

- W04：依赖已通过故障和范围验证的网络执行边界。
- W09：依赖身份校验、一次消费和进程树授权生命周期。

## W11 — 让子 agent 和后台委派继承并响应权限边界

### 构建内容

主 agent 将分析或编辑任务交给子 agent、后台任务后，实际调用仍受正确会话策略约束；用户在主会话收紧或撤销权限能影响这些执行。

### 验收标准

- [ ] 主 agent、直接 handoff、动态子 agent、前台/后台和嵌套工具调用均传递可信所有者、会话及策略关联，不能接受模型提供的替代归属。
- [ ] 子 agent 工具列表与直接执行一致，未适配工具仍拒绝；工作转交后不因默认配置、独立上下文或共享 LocalBooter 扩权。
- [ ] Shell/Python 产生的后代属于同一次执行树；子 agent 重新发起工具调用属于独立执行，不自动继承父执行的单次授权。
- [ ] 子 agent 的额外权限请求明确归属于其实际执行，可在正确会话 WebUI 审阅，批准不可被父级、兄弟或其他会话消费。
- [ ] 权限收紧与撤销能冻结相关新调用并终止超额执行，后台返回或主 agent 等待不丢失管理能力；无法确认停止时不显示已生效。
- [ ] 用确定性 agent 流程加真实受限进程验证并发、嵌套、后台、过期策略及跨会话拒绝；不依赖真实 LLM 稳定输出。
- [ ] 进度、错误和执行审计保留根会话到子执行的关联，既有正常委派功能回归通过。

### 被以下阻塞

- W09：需要已有审批及撤销生命周期，才能证明委派不复用父执行的额外授权。

## W12 — 接入可信插件适配并拒绝未适配调用

### 构建内容

一个可信插件完成适配后，可按实际参数处理授权资源并返回结果；同类未适配插件和试图丢失策略的嵌套/后台调用仍被拒绝。

### 验收标准

- [ ] 在现有工具体系提供最小适配契约：可信操作类别、实际资源解析、调用时检查，以及外部进程/嵌套调用的策略传递；不根据名称或自然语言描述自动授信。
- [ ] 用一个最小本地文件分析插件完成发现、调用、结果和拒绝的完整演示，真实文件权限与内置工具一致。
- [ ] 外部进程通过统一启动器；多资源、动态目标和运行中目标变化不能通过空声明或宽泛元数据绕过实际校验。
- [ ] 直接、后台、子 agent 和插件转调路径均验证适配状态及策略；插件启动后台工作不能持有已经撤销的模型执行权限。
- [ ] 未适配工具默认隐藏且直接调用拒绝；UI 能说明不可用原因，升级说明明确兼容性影响。
- [ ] 提供插件适配文档及行为测试，明确插件实现属于可信部分，本机制不承诺隔离恶意插件自身任意宿主代码。
- [ ] API、工具 metadata 和现有配置保持最小必要变更，不引入用于自动信任未知插件的兼容开关。

### 被以下阻塞

- W11：插件的嵌套和后台行为需要已验证的跨调用策略传递及撤销。

## W13 — 接入受限 MCP 调用并阻止跨会话授权复用

### 构建内容

一个具备可信适配及服务端受限权限的 MCP 测试服务可完成指定资源查询；未知服务、越界资源及跨会话凭证/授权复用被拒绝。

### 验收标准

- [ ] 演示一个可控测试服务的端到端调用，明确可信适配、服务端凭证/权限范围与实际资源，不把任意公网 MCP 服务视为可证明安全。
- [ ] readOnlyHint、工具名称或描述不足以放行；未适配 MCP 在暴露和直接调用层均拒绝，伪造注解不能改变结果。
- [ ] 校验实际参数及远端资源范围，越界请求在本地拒绝且远端受限凭证不能执行范围外操作；日志和模型输出不泄露凭证。
- [ ] 远端连接经明确的受控通信边界，执行器不能借它任意代理网络；如需额外网络权限复用现有审批及期限。
- [ ] 对支持的 stdio 启动和连接池共享方式说明隔离保证，拒绝不能隔离的部署方式；不得把不同会话的动态权限合并到共享服务进程。
- [ ] 主 agent、子 agent、后台及嵌套 MCP 调用遵守同一归属、策略和一次授权规则；收紧或断线后不盲目重放结果不明的有副作用请求。
- [ ] 对无法在远端终止或证明副作用边界的工具保持禁用，UI 和适配说明如实描述能力范围，不声称本地 Job 控制任意远端服务器。

### 被以下阻塞

- W10：需要可验证的网络授权与故障生命周期，不能通过 MCP 连接绕过默认网络边界。
- W11：需要跨 agent 和后台调用的身份、策略及授权隔离。

## W14 — 验收升级、恢复和支持矩阵并发布使用说明

### 构建内容

用户从旧版本升级，在支持的 Windows 环境完成初始化、使用和重启恢复，能够理解新权限、审批及第三方兼容性变化；未支持环境明确拒绝而不降低保证。

### 验收标准

- [ ] 对全部声明支持的 Windows build、架构、文件系统、Python 和 Shell 组合完成真实隔离验收，未测组合不宣称已支持。
- [ ] 使用完整产品路径复验文件/读取/网络/对象/进程树边界及授权生命周期；组合测试覆盖并发会话、模式收紧、单次文件+网络授权和子 agent/第三方工具。
- [ ] 新安装和旧版本升级均验证 workspace 默认、full 迁移、readonly 保留、损坏策略拒绝、历史危险根处理；迁移幂等，不扩大既有明确限制。
- [ ] 宿主重启、升级中断、安装/修复失败及卸载演练不会遗留可利用身份、ACL 或网络规则；仅清理机制拥有的条目，保留用户修改。
- [ ] 持久策略恢复正确；待审批、单次授权和旧任务全部不自动恢复；故障修复前 UI 与执行状态保持一致。
- [ ] 检查所有本地模型执行入口、文件工具和第三方路径不存在裸执行、full 回退或仅隐藏列表的旁路；跨平台共享接口无意外回归，不扩大其他平台保证声明。
- [ ] 中英文使用/升级说明覆盖初始化、模式、审批、收紧失败、保护资源重叠、支持矩阵、第三方适配及清理；发布说明列明兼容性变化。
- [ ] 运行适用的后端检查、前端构建/契约检查和真实 Windows 验收；证据附于测试记录或 Issue，不新增无关 SUMMARY 报告。
- [ ] 发现边界缺口则阻止发布并修复责任切片；不得以已知风险备注替代满足已认可保证。

### 被以下阻塞

- W12：插件适配和全部传递依赖完成，完整本地调用覆盖可验收。
- W13：受限 MCP 与网络/委派组合路径完成，才具备最终发布验收条件。
