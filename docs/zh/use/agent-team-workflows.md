# Agent 团队资产与运行工作台

打开 **更多功能 → Agent 团队 → 资产**。在 **团队** 管理版本化自主团队，在 **工作流** 管理图工作流，在 **角色模板** 配置可复用职责和本机资源。工作流可直接配置 Agent，无需先创建角色模板。导入、导出、聊天调用权限、编辑和启动操作仍在相应资产卡片中。导入完成后自动打开入口资产所属的团队或工作流分类。

工作流和自主团队的编辑（包括画布布局）会自动保存为草稿；尚未保存版本的新草稿也显示在资产列表中。请查看保存状态：失败时可重试，冲突时保留本地内容，并可主动选择读取服务器草稿。**保存版本** 会校验当前草稿并生成固定版本；正式运行和聊天访问使用已保存版本。

如果固定版本更新导致冲突，先核对原基版本和最新版本，再选择保留整份草稿并使用该基版本，或读取最新版本重新编辑；系统不会合并字段。核对期间草稿或最新版本发生变化时，须重新核对。

在 Agent 属性中选择**直接配置**或**角色模板**。模板引用同时固定角色和版本；出现新版时需要主动升级，已有工作流和运行不会自动变化。开启覆盖可替换模板值，关闭则继承；空职责表示清空，清空人格表示不使用人格，清空模型则使用工作流默认模型。工具、Skills 和知识库各自选择继承或完整自定义；自定义为空时禁用该类资源。直接配置的 Agent 可保存为角色模板，不包含当前任务或工作流默认模型；需要主动选择新模板才会使用。

## 条件与全部汇合

在工作流画布的节点目录中添加**条件**或**全部汇合**。选择条件节点，将 `value` 指向声明的工作流输入或上游任务必填的标量字段；选择比较运算和相同类型的值，再从命名的**成立**、**不成立**端口连接对应路径。选择已有连线可修改条件出口。条件是控制步骤，不调用模型、不生成产物，也不能用作工作流结果或普通数据引用。

将并行路径连接到**全部汇合**。汇合等待所有实际进入的路径成功，忽略跳过的路径；如果没有路径进入，汇合自身也会跳过。局部失败会阻塞其依赖项，其他独立路径继续执行。运行视图区分等待前驱（列出实际节点）、等待配额、路径跳过和依赖失败；这些调度等待不会创建人工请求。汇合后的 Agent 仍须显式选择需要的上游字段。

## 回答人工问题

在工作流画布添加**人工问题**，填写问题和允许的选项；选项留空时可自由输入。可选上游 Agent 任务及其必填字符串字段，分别指定推荐答案和理由，并将该任务连接为依赖。请求保留来源产物的精确版本与字段；推荐缺失或无效时仍可人工作答。系统不会为推荐隐藏调用模型，也不会默认设置截止时间。

在 **运行 → 待处理 → 需我处理** 查看自己有权回答的未决请求，包括最近运行列表之外的请求；**查看运行** 中显示同一张卡片。选择**查看过程**定位相关任务及其保存的过程，再填写答案。全局暂停期间可以保存答案，继续运行后才消费；取消会关闭待办并阻止迟到推进。等待人工时，独立分支仍可运行。

**运行 → 进行中** 包含尚未完成和需要处理的运行。**待处理** 集中显示人工等待、阻塞、失败、中断和暂停。**全部运行** 返回最近的运行，保留原服务的 50 条上限。

## 查看模型实际上下文

打开 **运行 → 查看运行**，选择任务，在模型交付卡片展开 **模型实际上下文**。消息角色和文本、模型与工具定义来自本机 Provider 调用前的最终请求；参数生成和修复调用各有自己的交付身份与上下文。展开装配来源与插件注入记录，可核对实际装配的人格、职责、任务、显式输入说明、技能及检索知识。来源记录先于插件修改，插件可能替换或裁剪内容，因此来源不保证完整保留在最终请求中。

记录的内容预算为 8192 字符，截断时展示原因和原始记录长度。二进制媒体被省略，远程媒体地址去除凭证、查询和片段；没有可授权引用的本地路径被省略。未设置的人格会标明缺失；旧运行和远端执行器可能未提供上下文。读取沿用运行所有者权限，回答人工请求不授予所有者的过程访问权；查看过程不会把过程注入下游 Agent。

## 将完整嵌套资产移植到另一实例

在实例 A 的 **资产 → 团队／工作流** 中选择 **导出资产 JSON** 并下载。版本 3 包含入口的精确子团队、子工作流、固定角色、内联配置和显式资源需求，保留继承、null 和空列表的区别；不包含凭证、资源内容、授权、会话或运行历史。旧槽位格式包会被拒绝，需要按当前格式重新创建。

在实例 B 打开 **导入资产包**，粘贴或选择 JSON，再点击 **校验并预览**。对每一项来源配置档案、模型、人格、工具、技能和知识库明确选择兼容的本机资源，即使来源 ID 与本机 ID 相同也须选择。检查不可用候选及原因、有效配置和来源字段。来源指纹不同仅作提示，仍可选择能力兼容的本机模型；确认时会重新校验配置档案权限与资源可用性。缺少资源时先在目标实例配置，再重试。

![隔离组件样例中的资源选择与有效配置](/images/agent-teams-package-resources-zh.jpg)

全部需求就绪后点击 **确认安装**。完整闭包与导入回执在同一事务中保存；失败不会留下半安装。相同内容与选择的重复导入复用固定身份；已导入来源版本的内容或本机选择不同则拒绝覆盖。保存的定义直接使用本机 ID，通过普通 **启动运行** 入口执行；再次导出读取本机定义。导入不安装插件或服务、不授予聊天访问权限，也不执行包中脚本。

## 从普通聊天明确调用资产

请调用者在目标平台会话发送 `/asset whoami`，将完整返回内容粘贴到 **聊天访问**。例如：

```json
{"platform_id":"qq-main","sender_id":"12345","source":"qq-main:GroupMessage:88888","profile_id":"default"}
```

开放固定版本前核对只读字段。群聊 UMO 标识会话，并不代表发送者。粘贴文本不能证明身份，也不能绕过资产管理权限。显示名称或与 Dashboard 账户重名的发送者 ID 不会关联两种身份。

资产所有者进入 **Agent 团队 → 资产**，根据资产类型选择 **团队**（自主团队）或 **工作流**（单任务或画布工作流）。在资产卡片上打开 **聊天访问**，粘贴完整返回内容并核对只读字段，选择 **开放此版本**。授权固定为页面显示的资产版本，并允许向该确切会话返回最终结果；群聊授权因此明确允许结果在该群内可见。所有可达角色、允许创建的成员及嵌套工作流必须使用来源配置档案，继续遵守现有模型／人格池及工具、技能、知识库限制。导入资产包不会自动向聊天用户开放。选择 **撤销访问** 后阻止后续外部调用和结果投递，已发生的执行仍保留记录。

使用 `/asset list` 查看已开放的资产名称、ID、固定版本和必填输入名称。例如明确调用：

```text
/asset 调研报告 | {"topic":"风能"}
```

同名资产使用返回的资产 ID 区分。缺少必填输入时，在下一条明确指令中补齐字段；选择和输入有效前不会创建运行。普通聊天不会自动选择资产。使用 `/asset status <运行 ID>` 可在同一已授权来源会话中重新连接已受理的根运行。

来源会话会收到受理、人工输入提示及最终契约化结果，长结果分段发送。消息包含运行 ID 和 `/#/asset-run?workflow_run=...` 路径，将其接在本实例 WebUI 地址后即可打开 **聊天发起的运行**。页面显示 `/asset connect <连接码>`，请由本次运行的实际发起人在最初的同一个聊天会话发送该指令，并保持浏览器页面打开。确认后，无需 Dashboard 账户即可查看本次运行状态、回答原来的持久人工待办及读取最终结果。群里的链接和连接码本身不会让其他群成员取得发起者身份。

连接仅限这次运行，有效期 30 分钟；到期、刷新页面或服务重启后重新连接并确认，仍处理原运行和同一个待办，不会重新发起资产执行。撤销授权或修改来源配置档案后，已有连接也不能继续读写。审批待办只能预览它明确要求的固定产物版本及该版本声明的文件，不提供其他子产物、版本、导出或修改入口。所有者私有的运行过程、思考、工具记录和资源配置不会开放给发起者。

受限的聊天运行页面显示已保存的动态问题、选项和推荐。截图为实际组件中的样例数据。

![受限聊天运行页面中的动态选择，使用样例数据](/images/agent-teams-chat-decisions-zh.jpg)

每条待办通知包含运行和请求 ID、问题、选项、推荐及理由，以及受限查看链接。可在原会话复制通知中的 `/asset answer <运行 ID> <请求 ID> <JSON>` 示例并替换示例值。动态选项使用 `{"action":"answer","choice_id":"选项ID"}`；自由文本使用 `{"action":"answer","choice_id":"__free_text__","free_text":"回答内容"}`。静态问题使用 `{"action":"answer","answer":"回答内容"}`。审批需携带展示的准确 `artifact_ref`，使用 `"action":"approve"`；退回使用 `"action":"reject"` 并填写 `"feedback"`。只有原授权会话中的原发起者可回答；Dashboard 与聊天处理同一个请求。

入口映射：聊天返回的旧 `/#/agent-teams?workflow_run=...` 改为发起者受限入口 `/#/asset-run?workflow_run=...`；前者仍作为所有者登录 Dashboard 后的完整 **运行** 详情入口。旧消息只有运行 ID 时，可从原授权会话发送 `/asset status <运行 ID>` 获取新入口。

完成后，可选择 **预览文件** 在当前页面读取最终文本文件，或选择 **下载文件** 取得带原文件名的完整字节；二进制文件请下载后使用本机应用打开。文件列表仅包含本次根运行实际发布的不可变结果版本所声明的文件，无需额外创建审批待办。所有者后续修订、无关子产物及其他运行的文件不会因此开放。每次文件请求仍须通过原来源确认和当前授权校验。

运行保存带平台命名空间的实际发起人及来源，由资产所有者继续在 Dashboard 管理这次委托运行。合成成员消息保持普通成员权限，即使 ID 与管理员重名也不会提升。聊天仅能读取根运行已完成的最终结果，不能通过子任务 ID 或未批准版本越过结果边界。重启后续传已有通知游标、继续处理原待办；平台已受理消息但回执尚未保存时崩溃，可能重复投递消息，不会因此重新发起资产运行。

来源必须唯一标识接收受众和账号。Satori 会话和 Misskey note 会话的现有来源身份不能保留这一区分，当前不可用于资产调用；Misskey 私聊和聊天室继续支持。请使用受支持的独立会话，或由所有者在 WebUI 发起资产运行。

企业微信智能机器人的资产回复要求原会话响应通道可用。HTTP 回调模式须关闭仅 webhook 发送，并设置非空的初始响应文本，让平台获得可轮询的流；否则 `/asset` 不会创建运行。长连接模式可以使用原请求回复，即使普通回复配置为仅 webhook 发送。资产通知不会发到全局群 webhook。原响应过期或进程重启后，请在同一个已授权会话、响应通道可用时发送 `/asset status <运行 ID>`，取回待发送通知和结果。无法确认原会话投递通道时，消息保持待发送状态。

## 自主团队

![自主团队预设配置，使用隔离样例数据](/images/agent-teams-autonomous-presets-zh.jpg)

选择 **资产 → 团队 → 新建自主团队**，填写 **团队名称**并选择默认模型。配置协调者并添加成员预设；每项可以直接配置，或引用固定版本的角色模板。直接配置可选择配置档案、职责、人格和资源；模板预设可局部覆盖这些设置，包括清空人格或使用空资源列表。同一模板可以用不同覆盖添加多个预设。协调者只能创建列表中的成员预设；目标在启动时填写。配置 **成员上限**（包含协调者）、**最大并发任务数** 和 **成员任务上限**；角色的实例数与并发限制也会生效。填写可选的 **最终版本审批问题** 后，必须批准协调者最终产物的精确版本，整个运行才能完成。**输出契约（JSON Schema）** 约束最终结果，留空使用默认文本契约。

保存资产，点击 **启动运行**，输入非空的 **goal** 后启动。协调者通过 `team_manage` 创建允许角色的实例、派发任务、检查完整结果和等待。成员通过 `submit_task_result` 提交契约化结果。任务依赖会固定上游原始产物版本，供 `read_task_artifact` 完整读取；协调者也能读取成员的完整原始产物。普通“完成”文本和过早提交不能完成运行，成员不能通过调用工具名称获得协调者权限。

若资产声明了附加输入，启动时逐项填写。所有声明值都会从运行的冻结输入交付协调者，多行文本和字面大括号保持原值；后续资产编辑不会改变恢复的输入。运行概览保留成员身份与关系，完整冻结配置在运行详情中按需读取。

在 **运行 → 查看运行** 中查看动态任务及 **本次运行成员**。**展开执行图（只读）** 显示依赖和协调者的虚线 **派发** 连线；派发连线表示创建关系，不是执行前置依赖。选择任务查看完整产物、冻结配置和成员过程。同角色的不同实例、新运行拥有独立会话；同一实例在本次运行的多个任务间延续上下文，检查点恢复后也保持该连续性。

等待成员会释放活跃执行容量，并发为 1 时仍可推进。**等待成员** 是局部等待；暂停、继续、取消、原 Attempt 恢复、显式重试与未知工具结果处理沿用下文的公共协议。成员失败或调用结果不明会阻止成功。编辑模板只影响新运行；本次运行后创建的动态成员仍使用启动时冻结的模板与配置。必要的最终审批使用已有持久化人工待办。

版本化自主执行的入口对照：**团队侧栏／运行监控 → 资产 → 团队 → 新建自主团队／运行 → 查看运行**。成员直接通信与工作流调用自主团队使用下文的版本化路径。

成员工具的外部效果未知时，在 **已保存的成员过程** 中展开该调用，核对参数和证据后再按公共处理协议作出决定。独立成员可以完成，但协调者不能用这些结果绕过尚未解决的成员调用。

## 协调者调用已保存工作流

进入 **资产 → 团队 → 新建自主团队／编辑资产 → 允许调用的工作流**，通过 **允许一个已保存工作流** 添加引用，选择 **固定工作流版本**。面板展示该版本的必填文本输入和公开输出契约。工作流返回其自身输出节点所选任务的结果。将团队保存为新版本；未列入允许范围的工作流不能由其协调者调用。

设置 **根运行嵌套深度上限** 和 **最大并发任务数**，再 **启动运行** 并填写目标。协调者调用允许的工作流时须提供所有声明输入，可显式交接可见的精确产物版本。每次调用创建独立成员，不继承父对话和无关产物。协调者等待调用任务，再读取完整结果及不可变产物。所选返回任务必须具有已校验结果；返回任务被跳过时，即使其他路径完成，调用仍明确需要处理。

在 **运行 → 查看运行** 选择协调者，通过调用旁的 **查看子工作流** 进入调用任务，查看返回值和精确的子作用域原产物引用。嵌套团队中的协调者也使用这一路径。再次选择 **查看子工作流** 可检查子任务，或展开 **子作用域** 查看保存的工作流图。**人工待办**、进度和 **已保存的成员过程** 展示实际任务、等待、尝试及工具结果。

等待会释放共享根容量，并发为 1 时仍可完成。团队和工作流混合嵌套共用有界深度，角色限制仍生效。全局暂停、继续和取消传播到子工作流；局部人工等待或分支失败不冻结独立分支。继续运行保留局部等待，必要时通过所选任务的既有入口继续同次尝试或处理未知工具效果。重启复用已保存工具结果，外部效果不明时保持阻塞待确认。

执行及恢复使用原资产、角色、输入、资源配置和精确结果版本；编辑允许工作流只影响新团队版本和运行。返回的托管文件可完整读取，显式修订可保留已交接的精确文件。未提交子文件及无关文件仍不可访问；旧产物、审批和消费者输入版本保持原含义。

版本读取归属于当前选择和编辑对象。旧请求迟到成功或失败均不覆盖最新版本、必填输入与返回契约；修改另一行工作流也会保留各行最新选择，所有当前版本读取完成后才可保存。保存使用最终显示的明确选择。

## 工作流显式数据

![在实际工作流画布中选择上游字段](/images/agent-teams-explicit-data-zh.jpg)

截图是使用隔离样例配置的实际组件预览，并非模型运行。

画布中的控制连线决定执行顺序。选择下游 Agent 并添加输入，选择工作流输入或上游任务，再按名称和类型选择必填标量字段；在任务指令中用 `{evidence}` 等输入别名引用。可选字段、数组和复杂契约并非都能安全引用。需要结构化结果时，在上游 Agent 启用结构化输出并用表单定义必填字段和类型；默认输出为文本。选择输出节点，指定返回完整已验证结果及原产物的任务。

控制连线不会共享上游对话或工具历史。图任务只能读取所选的上游产物字段。删除任务或更改字段可能使引用失效，启动前应按诊断修正，也可撤销编辑。已保存版本与运行任务保留各自配置；每个图任务及循环轮次使用独立对话，同一任务恢复时沿用原对话。

## 依赖画布

选择 **新建工作流**，画布预置输入、Agent 和输出视图。填写工作流名称并选择 **默认模型**。选择输入视图声明输入名称；Agent 通过明确的输入引用和 `{input}` 占位符读取输入。选择 Agent 可编辑任务、职责、配置档案、可选人格、模型覆盖和资源选择。未选择人格即不使用人格，自定义资源空列表表示禁用该类资源。未单独选择模型的 Agent 使用工作流默认模型；如果每个本机 Agent 都单独选择了模型，可以不设默认模型。启动前每个本机 Agent 都必须解析到允许使用的模型。保存版本并重新打开后，可填写声明的输入启动运行。输出显示 Agent 原始文本结果和产物。

![在工作流画布中直接配置 Agent](/images/agent-teams-inline-workflow-zh.jpg)

原 **新建工作流** 和 **新建画布工作流** 合并为 **新建工作流** 一个画布入口。角色模板仍是独立资产，新工作流无需预先创建模板。已有固定角色图节点仍可编辑。相同成员标识的任务使用相同冻结角色与配置并串行执行，但每个图任务拥有独立对话；不同标识可在工作流及角色限制内并行执行。

连接任务的右侧端口与后继任务的左侧端口。点击连线或使用 **选择依赖**，开启 **字段条件**，比较上游已校验的输出字段。条件使用 `eq`、`ne`、`gt`、`ge`、`lt`、`le` 与匹配类型的值，不执行代码。字段须是上游契约中的必填标量；可通过嵌套对象、本地 Schema 引用与 `allOf` 声明。大小比较仅支持数值字段。

使用 **添加输入引用**，为全局输入或上游结果字段命名别名，在指令中插入 `{别名}`。结果引用必须存在依赖路径。后继启动时固定生产者原始产物版本，图任务通过 `read_task_artifact` 仅读取已选择的字段。修订上游不会改变或重新执行已有消费者。非法引用、条件和无约束回边会在保存前返回明确字段路径。当前画布支持无环依赖、持久人工待办、显式有界循环体与固定版本自主团队调用。

画布控件支持缩放、适配，工具栏提供小地图、撤销重做与按依赖自动布局。布局及属性随资产版本保存。窄屏将工具箱与属性折叠为可展开区域。选择 **保存新版本**，再从保存后的资产 **启动运行**。保存不会执行流程，后续编辑不会改变已有运行。

**运行** 中显示只读冻结图。选择节点或使用 **查看任务**，查看真实状态、等待／失败原因、执行尝试、有效配置与具体产物版本。条件不匹配时跳过对应路径；汇合等待活跃路径，跳过路径不阻塞汇合。失败只阻塞相关后继，其他就绪分支继续。全部必要路径提交已校验结果后，整体才会完成。重复调度通知不会重复派工。

启动时幂等收尾已处于保存安全点的提交，其他遗留执行尝试标为中断。尚未开始的独立分支仍可按持久化状态推进。选择中断任务后，可从已保存的内置模型边界继续原尝试；新的执行所有权阻止旧执行者提交迟到结果。

## 工作流调用自主团队

先保存一个已就绪的自主团队。在 **资产 → 工作流 → 新建工作流** 的角色工具箱中点击 **调用自主团队**，选择节点后配置 **固定子团队资产** 和 **固定团队版本**。为所选版本的每个必填输入声明来源，可选择工作流输入或具有依赖路径的上游结果字段。输出契约沿用所选团队版本。展开画布上方的团队定义可查看固定协调者与允许角色，再折叠以保持父图简洁。

设置 **根嵌套深度上限** 与 **最大并发任务数**，点击 **保存新版本**。重开资产后保留固定版本、输入引用和布局。版本响应只应用于当前编辑上下文中的最后选择，不可用的选择会阻止保存。启动时先冻结全部子定义、角色配置和资源绑定；后续编辑子团队只影响新运行。声明的中文、多行文本和字面大括号原样交付子协调者。必填输入在解析上游结果后仍须为非空文本；非法值显示输入字段错误，不创建子作用域，无关分支继续执行。

在 **运行 → 查看运行** 中，进度包含实际子协调者和动态派发的成员任务。展开 **子作用域** 查看调用父节点、精确资产版本、根运行身份与子任务图。从进度、子图或 **查看任务** 选择实际子任务，读取完整产物、执行尝试和成员过程。父调用通过声明输出契约返回子团队原始的已校验产物；后继输入固定该返回版本。父产物修订可保留当前版本中已交接的文件，未交接文件仍不可引用；旧内容、消费者输入和审批继续绑定各自的精确版本。

父等待释放根执行容量，因此根并发为 1 时也能完成子任务。子团队等待人工、模型失败或外部工具效果未知时，无关父分支仍可执行。子人工请求在根运行的 **人工待办** 中处理；选择受影响的子任务恢复、重试或处理未知工具。重试子任务在现有作用域中创建新的 Attempt。用量与限制包含子任务和历史尝试；无法确定的消耗显示 **未知**。计量详情见下文 **根运行用量与限制**。

全局暂停、继续和取消覆盖全部作用域与执行者。暂停中回答会持久保存，继续后才消费，其他局部等待保持。恢复沿用原子作用域、Attempt 与冻结输入。父子成员和会话独立，父子关联不授予跨作用域消息或产物访问；只有声明的精确输入输出引用跨越边界。协调者反向调用沿用上文“协调者调用已保存工作流”的明确允许范围。

## 运行进度与成员过程

打开 **运行 → 查看运行**。运行列表与历史来自已保存的运行记录；进入详情后可展开 **运行列表与历史** 切换运行。详情先显示目标、固定资产版本、任务完成数与等待原因。点击进度中的任务或右侧需要处理的任务，查看该任务的产物及成员过程；**展开执行图（只读）** 保留图上的真实任务选择与固定输入版本。

运行列表只加载最多 200 字符的目标预览、状态、进度、等待原因、执行尝试及产物入口；完整目标、冻结输入值、结果与过程记录在所选运行的详情中读取。观测游标未变化时，轮询不返回快照，也不读取已保存的过程历史；初始与重连快照最多包含整个运行最近的 128 条过程记录；较早内容按任务分页读取。

![作用域任务和过程历史样例](/images/agent-teams-process-history-zh.jpg)

截图使用真实工作台组件和隔离的样例记录，并非后端联验。

在任务列表选择协调者或成员；展开子作用域可选择其中的任务和循环轮次，同名成员仍按实际任务运行区分。模型和工具记录显示所属尝试。点击 **加载更早过程** 为所选任务读取之前的记录。阅读器对每个任务的每类历史最多保留 512 条；实时跟随时保留最新记录，也可加载更早记录。向上滚动或加载历史会保留阅读位置，并提示新活动；点击 **返回最新过程** 可追上最新内容，切换任务也会恢复跟随。使用 **加载更早消息**、**加载更早事件**、**加载更早尝试** 分页查看相关历史；在用量明细中使用 **加载更早用量** 查看之前的调用。用量汇总仍包含完整账本，即使明细分页显示。远端执行器可能无法提供内部思考或工具进度。

**产物** 区域仍可选择具体版本，读取完整结果并预览或下载文件。**已保存的成员过程** 按需展开完整模型响应、提供商实际返回的思考、工具调用参数和原始工具结果。工具先返回部分结果再失败时，各条原始结果和最终错误均可读取。记录明确显示任务、执行尝试和运行成员；没有返回思考内容的模型不会出现思考区域。长内容可滚动查看，不依赖截断摘要。

关闭、刷新或离开页面不会取消运行。重新打开后读取一致的持久化快照；后续变化通过单调观测游标继续读取，重复事件不覆盖较新的状态，游标过期时重新读取快照。完整已完成的响应和工具结果在进程重建后仍可读取。这里的观测游标用于重连展示，不代表恢复未完成的模型或工具调用。

窄屏将进度、等待原因与运行成员纵向排列，长名称和身份标识换行，产物及过程操作仍可访问。

## 成员通信

打开 **运行 → 查看运行 → 选择任务 → 已保存的成员过程 → 成员消息**。每条投递显示发送者和接收者实例、作用域、来源任务和执行尝试。展开后可读完整消息，区分等待消费与已消费，并查看接收任务、尝试及保存的上下文位置。**读取完整版本**按消息中的固定引用读取产物；后续修订不会改变该引用。

成员通过 `team_communicate` 查看允许的接收者并发送提问或反馈。通信限定在当前运行和执行作用域内。成员可共享自己的产物、冻结的共同输入或已经明确共享给自己的具体版本；消息不能转授其他运行或未共享版本的访问权。成员创建、派工和整体完成仍由协调者负责。发送消息不会启动新任务或把工作标记完成。

模型请求进行中收到的消息留待下一个安全请求边界处理。消费位置与该请求的有效上下文一起提交。重复投递，或在消息、工具结果、上下文保存前后重启，不会再次追加已消费的消息。现有暂停、取消、容量及原尝试恢复协议继续适用。

长标识和版本读取按钮在窄屏下换行，深色主题中也可读取相同记录。

## 继续原尝试

打开 **运行 → 查看运行**，选择已中断的任务，点击 **继续同一次尝试**。页面说明最后保存的是模型请求、完整模型响应还是已开始的工具。恢复保留原 Attempt、资产版本、成员会话、有效配置、临时上下文、多模态内容、提供商思考与签名及执行计数。资源消失或权限变化会阻塞执行，不切换默认资源。

完整响应已保存时，直接复用原响应和工具计划。响应尚未保存时可重发请求；不保证恢复半段流式生成或远端计费去重。内置执行器支持完整工具 Schema 和两阶段填参；其他执行器不能使用此工作流的内部恢复。

每个工具调用保存独立的意图、执行归属、原始结果和上下文应用位置。在 **已保存的成员过程** 展开工具条目可查看这些证据。已保存结果直接复用并只应用一次；上下文已经应用时，从下一模型步骤继续。部分输出与完成状态分别保存：尚未结束的生成器中断或失败时，即使已有输出落库，调用仍保持结果未知。同批部分完成时逐个恢复：复用已保存结果，执行尚未开始的调用，外部效果未知的调用保持待确认。所有结果确定前，不放行依赖这些结果的模型请求。

## 处理结果不明的工具调用

在 **运行 → 查看运行** 中选择受影响的任务，进入 **已保存的成员过程**，展开结果未知的工具条目。先核对原参数、部分输出、调用身份和已保存的查询证据。该任务等待处理时，独立工作流分支仍可继续。

- 适配器在执行前明确声明状态查询、幂等键或安全重试能力时，**继续同一次尝试** 可以按原调用身份对账；**按工具声明的能力对账** 可再次检查。不确定的查询仍保持未知，工具名和超时不能作为重放依据。
- 在 AstrBot 之外已经核实完整结果时，选择 **记录核实结果并继续** 或 **记录核实失败并继续**，填写已知证据和完整工具结果，再提交。没有证据与结果的普通完成标记不能解除未知状态。
- 决定重新执行时，选择 **明确请求新的执行** 并记录依据。这可能重复产生外部效果。新的调用关联原结果不明的调用，原证据继续可读；保留已保存模型计划、原 Attempt 和固定配置。

决定与对账结果在刷新、重启后保留。同一个已提交决定重复执行不会再次安排操作；原执行者的迟到结果不能覆盖已选择的新执行。恢复只能依赖工具声明的保证，AstrBot 不承诺任意外部工具恰好产生一次效果。

结果提交属于内部幂等操作，适用于默认文本契约和通用契约，包括稳定文件引用。恢复收尾已有意图或只重做该提交，保留一个产物版本和一次完成事件。已保存的接受或拒绝结果保留原状态和上下文位置。同批其他工具必须达到已知结果安全边界后才能完成；外部效果未知时不能收尾。继续执行前会重建大工具输出的完整临时文件，临时存储清理后仍可读取已有结果引用。

## 暂停、继续、取消和重试

打开 **更多… → Agent 团队 → 运行 → 查看运行**。“整个运行控制”作用于根运行及现有任务执行者；选择某个任务不会把全局暂停变成局部等待。

- **暂停运行**持久化决定，停止放行新任务、模型和工具调用。已经放行的外部调用可能仍会完成；执行者保存结果后在安全点停驻。暂停不会撤销外部效果，暂停时间不消耗回复超时。
- **继续运行**使用原快照和原 Attempt 解除全局暂停，保留局部失败和工具结果待确认。进程重启后，暂停仍生效；继续会恢复原检查点。“继续同一尝试”是中断任务的检查点恢复，与创建新 Attempt 不同。
- **取消运行**向现有执行者请求取消，并永久停止新派工。请在弹窗确认决定。已完成结果、已接受的结果证据、外部效果和历史在刷新或重启后仍可读取；迟到执行者无法覆盖取消状态。
- 选择失败任务，点击 **重试失败任务**。弹窗显示原始冻结文本输入和精确产物版本；点击 **确认决定**后使用这些输入创建新 Attempt。重试不会静默选取新版产物，也不会创建新的循环迭代。展开“历史尝试”可查看失败详情、输入引用与已保存的 token 消耗；完整过程记录继续按 Attempt 关联。图任务重试沿用已有容量和成员互斥限制。

请先在“已保存的成员过程”中处理结果不明的工具调用。普通任务重试不能绕过工具对账或有证据的人工决定协议。重复相同控制或重试请求不会新增决定或 Attempt；其他控制改变版本时，请刷新后再作新决定。

整个运行暂停期间，仍可保存核实结果、核实失败、显式工具重试或对账决定。页面会确认决定已保存，等待“继续运行”，保存决定本身不会放行外部工作。继续运行或在已接受继续后重启，会使用原 Attempt 与调用证据，并遵守局部等待及容量限制。正常关闭核心服务与意外停止进程都会保留暂停后的接续决定。已保存的待执行决定在被消费前不能由另一决定替换。

## 人工待办与版本批准

运行中的 Agent 可以在同一待办中提出动态选择。阅读补充说明与推荐后，选择选项并按需添加备注，或选择自行输入并填写答案。每个问题独立回答；原工具消费答案后，所选标签和备注仍可查看。

![使用样例数据的动态选择组件](/images/agent-teams-dynamic-choice-zh.jpg)

此组件预览使用样例数据，不代表后端联验。

1. 打开 **资产 → 工作流 → 新建工作流／编辑资产**，在 **角色工具箱** 添加 **人工问题** 或 **版本批准**。人工节点无需模型或角色。问题填写原因、允许回答（每行一个，可留空）与回答长度上限。
2. 版本批准选择上游 **产物任务** 和精确 **产物版本**，并将产物任务连接为依赖。保存为资产新版本后启动；已有运行仍使用原定义。
3. 在 **运行 → 查看运行 → 人工待办** 处理请求。问题、约束、关联任务、Attempt 和批准对象持久保存。推荐动作与理由可选择明确的上游 Agent 字段。等待释放执行容量，只阻塞需要答案的路径；独立分支继续，结果可在执行进度中选择查看。
4. 问题选择或填写回答，再点击 **提交回答**。批准必须先点击 **预览批准对象** 查看完整的固定版本，再点击 **批准此版本**。文件可预览；**退回修改** 须先预览并填写反馈。将“通过”和“退回”出口连接到明确路径；退回不会自动重跑作者。需要返工时，将撰写和审批放入有界循环，把反馈映射到下一轮输入。
5. 批准后点击 **导出已批准版本**，导出 JSON 包含完整内容和精确文件引用；预览后可下载该版本的文件。配置了批准节点的产物，其未批准版本不能通过下载接口导出。创建 v2 不继承 v1 批准、不修改已有预览，也不会自动重跑下游。
6. 刷新或重启后重新打开该运行可继续处理。重复相同回答不会重复消费；已回答待办不能被另一回答覆盖。整个运行暂停时允许保存答案，并明确显示 **回答已保存，将在整个运行继续后消费**。继续保留未回答待办；取消保留原待办和回答历史并阻止新的消费。人工请求不能通过普通任务重试重写答案。

如果指定的修订版本尚未生成，待办仍保留该精确版本，预览和批准会明确提示版本不可用。先在产物任务显式创建所需修订，再回到原待办预览和批准；系统不会换成已有 v1 或最新版本，也无需创建新尝试。

## 单任务资产

1. 点击 **新建工作流**，填写名称，选择角色模板及其版本。
2. 在 **必填输入** 中填写逗号分隔的输入名称，例如 `topic`。任务正文可用 `{topic}` 引用该输入；文字中的大括号需要成对双写以转义。仅支持声明的简单占位符。
3. **输出契约（JSON Schema）** 留空时使用非空文本结果，也可填写 `type: object` 的 JSON Schema 声明证据、审查标记或文件字段。仅支持本契约内的引用，不加载远端 Schema。点击 **保存新版本**；保存只创建定义，不创建成员会话，已有运行保持原版本。
4. 在资产卡片点击 **启动运行**，填写所有必填输入。需要前序产物时，在 **固定输入产物** 中选择具体版本；选择项的摘要只用于定位内容。缺失输入或不可访问资源显示字段路径，不换用默认资源。
5. 启动后打开 **运行 → 查看运行**。**产物版本** 可切换查看完整文本、证据或结构化结果；长内容在结果区域滚动，内容不会被截断。文件支持 **预览文件** 和 **下载文件**。展开 **输出契约（JSON Schema）**、**结果提交历史**、**固定的有效配置** 和 **已保存的成员过程** 查看冻结的约定及字段错误。
6. 点击 **创建产物修订**，编辑完整结果 JSON，可附加已就绪的文件，再点击 **保存产物版本**。修订必须通过原契约，创建不可变的新版本；版本冲突时先刷新并选择最新版本。原运行结果和既有消费者的输入保持不变，也不会自动重跑后继。

每次运行创建新的成员身份和独立会话。运行冻结角色、输入、人格提示词及有效配置；运行中的工具纠错沿用同一成员上下文。后续编辑模板只影响新的运行。

Agent 必须调用 `submit_task_result` 按契约提交结果。默认契约接受 `{"text":"完整结果"}`。自定义契约使用唯一的 `result_json` 参数，将完整结果对象编码为 JSON 文本，例如 `{"result_json":"{\"approved\":true}"}`。参数描述在 `full` 和两阶段 `skills_like` 模式的填参请求中提供完整冻结 Schema，包括组合结构和本地引用；provider 接收兼容的字符串参数，服务端仍按原契约校验解码后的结果。非法提交返回具体字段路径，允许在剩余执行预算内修正；普通回复不会完成任务。有效提交先保存意图，执行到已保存的安全点后，在同一事务中写入结果、产物版本、完成状态和关键事件。重复提交不会生成第二次完成或重复版本。

自主团队任务使用 `read_task_artifact(artifact_id, version)` 读取固定输入的完整内容，传入该版本内的 `file_id` 可读取已授权文件；图任务通过此引用只能读取所选标量字段，不能读取文件。实际读取的引用持久保存，不能改读未声明的新版。通过现有授权工具取得完整文件内容后，先调用 `store_task_file(filename, content, encoding)`，成功后把返回的稳定引用放入 `files: [{"file_id":"..."}]`。content 可为 UTF-8 文本或 base64 字节。文件完整存入系统管理的数据库后才可提交，不保存临时绝对路径，刷新和进程重启后仍能预览、下载。单文件最大 50 MiB。

切换或关闭页面不会停止核心执行。刷新带有 `workflow_run` 参数的地址会重新读取该运行，也可从运行列表重新打开。核心进程重启时，已保存安全点的有效结果意图会自动幂等收尾，其余未完成执行标记为 **已中断**。通过 **继续同一次尝试** 恢复符合条件的模型边界；结果不明的工具保持待处理。

## 配置有界审查修订循环

![使用示例数据的有界循环配置](/images/agent-teams-bounded-loops-zh.jpg)

截图展示使用示例数据的实际编辑器组件。

退出条件和反馈字段可从任务的必填标量输出中选择。摘要显示上一轮结果与下一轮输入的对应关系；展开轮次可查看实际反馈输入及固定产物。

打开 **Agent 团队 → 资产 → 工作流 → 新建工作流／编辑资产**。配置撰写和独立审查任务，连接撰写到审查的无环依赖；审查输出契约包含必填布尔字段 `approved`。点击 **添加有界循环**，选择明确的循环体、退出结果任务、字段比较（`approved eq true`）和最大轮数（1–100，不能超过成员的有效迭代限制）。任意代码表达式、图回边、重叠循环体以及离开循环体后又进入它的路径在执行前报错。

为撰写任务声明第一轮的草稿与反馈输入。在循环中 **添加反馈输入**，显式将上一轮撰写结果的 text 传给下一轮草稿，将上一轮审查的 text 传给反馈。每轮内部的普通依赖输入读取本轮产物。可折叠或展开画布上的循环分组。保存产生资产新版本，已有运行保留原定义和有效配置。

每轮创建独立 Task 和新 Attempt，固定本轮输入版本，分别保留模型、工具过程及用量。修订产物有独立的不可变资产标识：比较具体版本时同时看 `artifact_id` 和 `version`，不能只看版本数字。重试保留 Task 和本轮固定输入，创建新 Attempt；恢复继续原 Attempt 的检查点。旧内容、审查结论与批准引用不会被覆盖。

在 **运行 → 查看运行 → 循环轮次** 展开某一轮，可查看输入、结果、退出结论的精确引用和任务模型调用数；未知用量显示“未知”。点击任务进入完整过程、产物与控制；展开该轮执行图查看真实任务状态。执行过的循环体只有在已校验退出条件匹配后才放行组外消费者。最后一轮仍不匹配时显示 **已达轮次上限**，运行需要处理且没有成功的最终结果。循环体局部等待时独立分支继续；全局暂停和取消也作用于跨轮次边界，重启不产生重复轮次或重放已保存效果。

如果首轮整个循环体因条件未选中而跳过，循环和轮次显示 **条件未选中，已跳过**，不产生退出产物或新轮次。汇合忽略这条未选中的路径，使用活跃分支的输入。已经执行但出口被跳过、执行失败或耗尽的循环仍会阻塞依赖它的消费者；跳过任务的输入不会生成替代结果。

可选条件分支被跳过时，退出任务仍可用已校验的通过结果结束循环。如果未通过的退出条件需要读取被跳过任务的反馈，循环会进入需要处理状态，因为该轮没有可固定的反馈结果。

不添加人工节点也能独立演示通过或达到上限。需要确认报告时，在审查依赖之后配置 **版本批准** 并选择撰写产物任务；待办固定通过轮次的具体产物，导出读取被批准的引用。手动新版产物不会自动重跑消费者，也不会继承旧批准。

## 执行器就绪与远端恢复

进入 **资产 → 团队／工作流 → 启动运行**，对话框先检查固定版本的本机依赖与执行器能力，再放行 **启动运行**。**检查就绪** 可重新执行与启动相同的判定；阻塞项显示具体字段。角色、画布工作流和自主团队共享规则；自主协调者必须支持本机派工工具。

| 执行器 | 已接入的恢复边界 |
| --- | --- |
| 内置执行器 | 完整模型上下文及逐个工具调用检查点。 |
| Dify 工作流 | 原 `workflow_run_id` 与已配置的工作流输出。 |
| 开启保存历史的 Coze | 原 `chat_id`、`conversation_id` 和该次 chat 的回答；关闭保存历史则不提供查询能力。 |
| 当前 DeerFlow API | 原线程／运行 ID、精确运行状态及分页的该次运行消息；接口或完整输出缺失时须确认。 |
| Dify chat／agent／chatflow、百炼 Application | 仅外部调用边界；Chatflow 的状态查询不能单独恢复经过输出审核的最终回答。 |

在 **运行 → 查看运行** 选择受影响任务。执行器面板显示恢复边界和原远端身份；**查询原远端运行** 保留原 Attempt，仅查询该身份，不创建新运行。已保存完整响应直接复用。身份缺失、查询不可达、身份不匹配、状态仍活动／未知或完整输出缺失时保持待确认。明确选择新 Attempt 前先检查原服务；查询失败不证明操作未发生。

Dify 工作流通过已配置输出键提供结构化对象，由原输出契约校验器接收。远端普通文本和展示用 JSON 不会自动完成任务。Coze、DeerFlow 的回答保存为过程输出，缺少显式结果提交时显示 **等待提交结果**；要求 `task_result` 的资产会拒绝没有该能力的执行器。远端查询不恢复其内部工具；未接入协议的插件／工具内部调用只保证 AstrBot 实际保存的边界。思考与签名按提供商实际返回保留；不返回思考的模型正常工作。

Dify Agent 实际返回的 `agent_thought` 事件显示在 **已保存的成员过程 → 远端过程事件** 中，保留提供商的 thought ID、思考、工具输入和 observation。Workflow 与 chatflow 的过程事件保留实际节点执行 ID、inputs、process_data 和 outputs，包括提供商实际返回的思考及 agent 日志。同一 thought 后补的观察结果作为独立快照保留；重复快照与恢复不会重复记录，没有帧序号的相同思考增量则按收到的顺序分别保留。同一节点的多次执行通过原执行 ID 和迭代 ID 区分。这些记录用于观察远端执行过程；存储失败时，任务会在接受完整回答之前阻塞，恢复先重放已保存的观察记录，再查询原运行。团队 DashScope 调用在连接结果不明或重定向时同样等待确认，不会重新发送创建请求。

## 根运行用量与限制

在 **资产 → 团队／工作流 → 编辑资产 → 作用域限制** 配置总调用步骤、子树成员实例数、每个循环的轮次、Token 额度和单次模型输出上限。单任务、画布工作流和自主团队使用同一表单；留空不增加上限。保存新版本后启动运行，已有运行仍使用原版本的限制。画布和自主团队原有的并发、深度与局部成员限制继续生效，嵌套同时遵守祖先作用域的限制。

“总调用步骤”按每次获准的模型、工具或状态查询投递计数，包括协调者、成员、参数补全、压缩、重试和子调用。等待人工、子流程或在途预留释放执行容量。进入额度预留等待时会自动唤醒独立就绪任务，仍遵守根与祖先作用域的限制。挂起的 Agent 回合仍持有成员上下文，同成员的其他任务等待该回合退出后再推进。从检查点恢复保留原 Attempt；显式重试产生新 Attempt，但已发生用量与限制不清零。循环上限限制每个循环的轮次，不能通过恢复或重试创建额外轮次。

在 **运行 → 查看运行 → 用量与限制** 查看根汇总，选择任务或进入子作用域查看对应明细；展开 **调用明细** 可追溯作用域、任务、Attempt、Invocation 和实际投递身份。父子明细共享同一记录，汇总不重复计数。读取其他根运行的输入产物不会转移其历史消耗。

Token 汇总分别展示提供商已报告的部分、估算、在途预留以及用量未确认调用。缺失报告显示未知；工具没有 Token 报告时也显示未知，不能据此推断工具没有其他费用。Token 额度约束接入此协议、可估算的模型请求；插件或工具内部未接入协议的收费不能作为硬性额度控制。未配置单次输出上限时使用请求已有上限；请求也未提供时采用 2048。预留约束并发新增调用，但输入估算和提供商输出约束可能不准确，事后报告可能超过额度，不能保证任何情况下绝不超支。

用量追踪启用前创建的运行保留原有过程记录。面板单独显示已保存的历史模型响应及历史消耗未知状态，恢复后出现新用量也不会清除该标记。历史响应和检查点步骤不是准入凭据；已报告总量仅涵盖已计量部分。这类运行中，用量未知的调用总数仍显示未知。

达到可判定限制后停止新增调用，并展示限制名称、值和任务归属。已保存的结果和外部效果仍可追溯；若有效结果及整个工具批次已提交并应用，额度拒绝后续收尾叙述不妨碍结果完成。终止时未确认的消耗保留保守估算，迟到报告可补齐原记录，却不能取得当前执行权。仅被其他在途调用占用的额度会等待释放，等待不占活跃名额。

## 在两个实例交付已审查报告

1. 在 **资产 → 工作流** 配置报告流程：调研子调用、有界撰写／审查循环，最后连接 **版本批准**。调研团队的协调者可调用已保存的图，由两名独立调研者并行执行后交给证据编辑汇总；在协调者上配置允许调用的工作流。固定角色和子资产版本，声明 `topic`、`feedback` 输入，并明确把上一轮草稿与审查映射到下一轮。
2. 从资产卡启动，在 **运行 → 查看运行** 检查调研子作用域及撰写／审查轮次。第一次审查不通过后必须产生修订稿并再次审查；达到循环上限仍未通过时显示待处理。最终人工待办绑定实际产物 ID 和版本。第二轮循环可能生成另一个 ID 的 v1 产物；循环轮数不等于产物版本号。
3. 点击 **预览批准对象** 阅读完整文本与文件，批准该具体版本，再使用同一人工待办中的 **导出已批准版本** 和 **下载文件 · 文件名**。文件预览弹窗用于阅读，关闭后返回人工待办下载文件。导出产物及 Markdown 应与批准对象对应；批准旧稿不会自动批准另一修订。
4. 用 **导出资产 JSON** 导出根资产。在具有不同本机资源 ID 的隔离实例 B，打开 **导入资产包 → 校验并预览**，在集中依赖表单中为每项来源需求选择本机资源。即使来源 ID 与本机 ID 相同，也必须明确选择。一次 **确认安装** 以事务保存固定的嵌套闭包，不自动启动。用相同输入运行导入的根资产，处理它自己的人工批准。关闭浏览器不会停止服务端运行或丢失待办，重新打开原运行链接即可继续。
5. 从普通聊天使用同一资产时，在已配置根资产上打开 **聊天访问**，授权指定平台发送者／来源。在该来源执行 `/asset whoami` 查看应授权身份；按卡片展示的语法调用资产，遇到必填项澄清时先补齐，再打开受理消息中的运行链接。在同一来源通过 `/asset connect <challenge>` 确认浏览器。来源身份可读取并处理自己的人工待办、接收最终结果，不会获得所有者的过程或配置权限。

![真实报告批准及其固定产物与版本](/images/agent-teams-report-t25-zh.jpg)

报告应使用本机实际配置的提供商与工具。文档中的 QA 截图来自隔离实例和可控的外部模型响应，示例报告为测试内容；恢复与结果不明的处理仍受上文执行器能力边界约束。

## 新旧入口对照

| 原有入口 | 当前用途 |
| --- | --- |
| 所有执行器统一显示“继续同次尝试” | 可查询的远端执行器显示“查询原远端运行”；内置执行器继续使用原检查点恢复入口。 |
| Dify Agent 运行只展示最终回答 | 已保存的成员过程 → 远端过程事件，保留实际思考与工具观察快照。 |
| Agent 团队 → 成员、工作流编排、运行监控、历史 | 资产 → 团队／工作流／角色模板；运行 → 查看运行／历史。迁移入口和旧运行检查已移除。 |
| 保存可复用的单任务工作流 | Agent 团队 → 资产 → 工作流 → 新建工作流；定义不依赖旧团队。 |
| 编辑可复用的依赖工作流 | Agent 团队 → 资产 → 工作流 → 新建工作流／编辑资产；旧执行编辑器已撤除。 |
| 启动、查看新版工作流运行 | 资产 → 工作流 → 启动运行，然后在运行 → 查看运行 → 执行进度中选择任务；查看任务选择器也继续可用。 |
| 详情中的默认运行图和回复 JSON | 执行进度优先；图移至展开执行图（只读），回复移至按需展开的已保存的成员过程。 |
| 编辑模板与检查运行配置 | 资产 → 团队／工作流编辑新版本；运行只显示被冻结的快照。 |
| 中断后只能读取过程记录 | 运行 → 查看运行 → 选择任务 → 继续同一次尝试；已保存工具结果直接复用，外部效果未知的调用等待确认。 |
| 外部效果未知时只能查看等待原因 | 运行 → 查看运行 → 选择任务 → 已保存的成员过程 → 展开未知调用 → 对账、记录核实结果或明确请求新的执行。 |
| 运行详情仅提供检查点恢复 | 运行 → 查看运行 → 整个运行控制；选择失败任务 → 重试失败任务。 |
| 用量仅显示检查点中的模型／步骤计数 | 资产 → 团队／工作流 → 编辑资产 → 作用域限制；运行 → 查看运行 → 用量与限制 → 调用明细。 |
| 成员通信只能从工具结果定位 | 运行 → 查看运行 → 选择任务 → 已保存的成员过程 → 成员消息；展开引用即可读取完整版本。 |
| 协调者只能派发成员任务 | 资产 → 团队 → 新建自主团队／编辑资产 → 允许调用的工作流；运行 → 查看运行 → 选择协调者 → 查看子工作流。 |
| 修订仅能使用普通任务依赖 | 资产 → 工作流 → 编辑资产 → 添加有界循环；运行 → 查看运行 → 循环轮次。 |
| 新版工作流没有持久人工入口 | 资产 → 工作流 → 编辑资产 → 人工问题／版本批准；运行 → 查看运行 → 人工待办。 |

单任务资产继续兼容。依赖资产在相同的任务结果协议上提供无环调度、字段条件与持久人工待办；有界修订循环与自主团队复用同一调度。结果不明的工具处理已位于所选任务的过程详情内。

## 人工等待期限

![人工等待策略与持久决定状态](/images/agent-teams-human-deadlines-zh.jpg)

重启保留原截止时间。运行暂停时可保存有效决定，继续后才消费；取消会关闭请求。即使未打开 Dashboard，后台仍会处理到期请求。

人工问答和审批默认无限期等待。可在人工节点设置期限，选择继续等待或自动采用创建请求时已展示的有效推荐。动态选择的期限由提问角色或 Agent 的人工等待策略配置。引用模板的 Agent 可以继承固定模板，也可以覆盖策略（包括恢复无限等待）。此设置独立于普通聊天超时。

待办显示持久化的截止时间和决定来源。推荐缺失、无效或证据不可用时仍等待人工；到期时不会再次调用模型作决定。
