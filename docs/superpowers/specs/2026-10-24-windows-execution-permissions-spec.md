# AstrBot Windows 执行权限机制 — Spec

- 日期：2026-10-24
- 状态：Approved — 用户已于 2026-10-24 确认 Spec、测试边界及 14 张 ticket 的拆解与依赖；尚未实施
- 依据：《AstrBot Windows 执行权限机制 — 设计基线》（2026-10-24，Approved）
- 目标平台：原生 Windows；具体系统版本、架构、文件系统和工具链支持范围须实测确定

## 问题陈述

AstrBot 用户需要在只读会话中继续运行 Shell 和 Python，以读取项目、搜索文件、计算和分析数据。直接禁用执行工具会失去这些能力；仅限制文件写入工具，则无法阻止模型通过代码、原生库、子进程或后台进程读写文件。

当前机制还存在读取范围过宽、执行器继承宿主环境、后台任务与权限切换脱节，以及第三方工具缺乏统一约束的问题。用户无法据此确认“只读”究竟保护了哪些数据，也无法安全地临时授予某一次执行额外权限。

本功能需要让权限成为实际资源访问的边界，并使 WebUI 展示的权限状态与仍在运行的进程权限一致。

## 解决方案

保留 readonly 和 workspace 两种会话模式。readonly 允许读取获准数据和使用私有临时空间；workspace 额外允许修改获准的工作区及附加写入目录。两者均默认禁止执行器联网、访问其他用户文件和访问控制端敏感资源。

Shell/Python 始终通过 Windows 沙箱执行，限制覆盖整个进程树。用户可在 WebUI 审阅一次具体执行所需的额外文件或网络权限，并授予有期限、不可复用的单次授权。收紧权限时先阻止新增越权操作，再终止超额授权的执行树，确认完成后才展示新模式已生效。

内置文件工具、子 agent、插件和 MCP 使用同一会话策略。未完成可信适配的工具默认拒绝。沙箱不可用或边界无法验证时，明确报告不可用，不回退到宿主执行。

新会话及旧 full 配置默认采用 workspace。已有 readonly/workspace 选择保持不变。持久模式与明确配置的目录可以在重启后恢复；待审批请求、单次授权与运行任务不自动恢复。

## 实现决策

### 信任与保证

- 模型生成代码、工具参数、工作区内容及工具输出均不可信；AstrBot 主程序和已安装插件实现属于可信计算基础。
- 边界覆盖模型可调用执行路径及整个进程树，不以命令黑名单、工具描述或模型遵守指令作为隔离手段。
- workspace 允许授权范围内的修改和删除；网络授权不保证远端请求只读；终止任务不回滚已完成修改或已发送请求。
- 不保证抵御恶意已安装插件实现、内核漏洞、系统管理员或已失陷宿主。插件“可信实现”不免除其遵守调用策略的义务。

### 策略及资源

- 复用会话身份、LocalBooter、ProcessSandbox、SandboxSpec 和现有 Shell session 管理，不建立平行执行体系。
- 持久策略包含所有者、会话、版本、模式、工作区和显式附加目录。每次执行生成服务端控制的不可变快照，包含执行标识、实际资源、私有临时根、网络范围、资源上限及审批关联。
- 共享 LocalBooter 不保存可被并发请求覆盖的当前会话策略。模型参数不能直接赋予沙箱状态或提权能力。
- readonly 下工作区及持久附加写入目录只读；workspace 下按目录授权可写。两者均只读访问必要运行依赖，并可读写本次私有临时空间。
- 初始创建目录、准备脚本、日志及修改 ACL 同样必须先验证目标，避免启动用户进程前发生越权副作用。
- 环境变量采用白名单；临时目录、缓存及必要用户配置隔离，不复制宿主全部环境。
- 受保护资源包含宿主运行安装、插件代码、解释器、启动器、策略及审批存储、凭证和控制接口。与授权目录重叠且无法安全排除时拒绝该范围。开发 AstrBot 使用独立工作副本。
- 结果附件由可信处理端有界导出，检查真实对象、重解析点、尺寸及类型；不自动写回工作区，也不执行模型生成的临时脚本。

### Windows 后端验证与生命周期

- 优先验证专用非管理员身份、独立 AppContainer/LPAC 身份、ACL、Job Object 与受控网络出口的组合。最终原语、库、语言、部署服务及支持矩阵在可行性阶段决定。
- WRITE_RESTRICTED 本身不足以证明读取白名单；任何替代候选必须满足相同验收条件。候选失败应返回设计讨论，不能静默降级或改用隔离副本作为默认访问方式。
- 每个执行隔离身份及动态授权；共享运行依赖只能共享经过验证的只读权限，不能因共用账户或能力而合并会话数据权限。
- 用户代码开始前即纳入 Job 及访问边界，禁止进程树脱离；根进程退出不代表授权结束。仅继承必要句柄。
- 默认拒绝直接入站和出站网络，覆盖双栈、UDP、DNS、loopback、LAN、UNC/SMB 和子进程。设置代理环境变量或按程序名设防火墙不能单独验收。
- 注册表、进程句柄、管道、COM/RPC、WMI、计划任务、服务、桌面和 WSL 等不能成为边界外代理执行通道；实际必要本机通道须协议和身份受控。
- 原地 ACL 只管理本机制拥有的条目，保留用户现有及并发修改。对象校验覆盖路径别名、链接、重解析竞态、所有权、父目录删除权和非继承 ACL。
- 安装及必要修复可请求用户授权管理员助手；助手只提供固定受控操作，模型代码始终无管理员权限。是否需要常驻特权组件必须通过验证决定。
- 超时、撤销及控制端故障终止相关执行树；未确认终止前不能先清除防护，使存活进程短暂获得更宽权限。残留身份不得复用。
- 进程数、内存、期限、输出与临时存储容量均需有实际约束。临时存储容量需独立证明，不能视为 Job Object 自动提供。

### 统一调用与适配

- FunctionToolExecutor 及工具暴露路径统一检查是否具有可信适配，并覆盖主 agent、子 agent、后台和直接分派路径。未知工具隐藏且直接调用拒绝。
- 首个产品执行切片即关闭未适配入口；后续逐个恢复能力，避免新增沙箱旁边继续存在裸执行旁路。
- Shell/Python 实际启动只能经过后端；readonly 不再整体禁用已适配执行工具。Windows 后端不可用时停止调用，结果明确区分策略拒绝、后端不可用和程序错误。
- 内置文件工具在实际操作处检查真实对象，或使用同一受限 worker；仅调度前校验路径不够。
- 插件适配须包含可信操作分类、实际参数到资源的解析、执行时约束及外部进程统一启动。嵌套和后台调用不能丢失策略。
- MCP 注解不构成授权依据；远端工具依赖可信适配和服务端受限凭证/权限。无法证明范围的工具保持拒绝，AstrBot 不声称控制任意远端实现。

### 审批协议与 WebUI

- 请求绑定所有者、会话、执行、策略版本、工具、命令或代码、实际参数、cwd、有效环境摘要、所需资源和有限期限；授权数据仅保存在可信控制端。
- 待审批不执行；WebUI 展示可审阅内容、资源、理由和期限。审批校验登录身份、审批资格、会话归属、请求状态及防跨站请求措施。
- 聊天 API key、插件页面 token、模型 confirm 参数及命令前缀都不能批准请求。
- 批准在启动前复验并原子消费一次；参数、目标或策略变化要求新请求。拒绝、过期、重复消费及状态不明均不执行。
- 摘要绑定请求，不证明所有项目依赖不可变；资源边界始终由沙箱实施。部分执行失败后不能获批即盲目重跑，须作为新执行审阅。
- 授权覆盖整个执行树且有有限期限；后台返回 session ID 不结束授权，父进程退出也不延长授权。临时扩权首版关闭自由 stdin；基线内交互仍受资源边界约束。
- 网络请求区分目标主机、端口和协议。域名授权通过可信出口处理解析、重定向和私网目标；控制端敏感接口不属于普通单次授权可放行资源。
- UI 同时展示基础模式与单次权限，并展示待审批、拒绝、过期、收紧中、故障及工具不兼容状态。接口或 schema 修改同步再生成前端客户端。

### 模式切换、恢复与迁移

- 收紧先冻结新启动与敏感 stdin、推进策略版本并作废旧待审批；终止超额权限执行树、确认停止并撤销资源后，才发布新策略生效。
- 终止失败保持阻塞及真实的处理中/失败状态；已符合新策略的任务仅经关联重新核验后继续。
- 重启恢复持久模式和显式目录，先核验残留身份、ACL、网络、临时目录和进程；单次授权和待审批失效，任务不自动恢复。
- 新会话和旧 full 迁移为 workspace；显式 readonly/workspace 保留；恢复可写只恢复 workspace。未知或损坏策略报错，不回落 full。
- 历史共享临时根、插件动态目录及与控制端重叠的目录必须重新验证，不能原样扩权迁移。
- 按执行关联审计审批、启动、消费、拒绝、变更、终止和清理；审计存储受保护且不记录凭证或完整宿主环境。

## 测试决策

以下测试边界已获用户确认。测试验证可观察行为及真实副作用，不把内部函数调用次数、命令文本黑名单或 sandboxed 标志作为安全证据。

1. **主要产品边界：公开工具调度到真实 Windows 执行。** 使用确定性模型响应或直接构造公开工具调用，通过 FunctionToolExecutor 进入实际 Shell/Python、策略及 ProcessSandbox，观察结果、文件内容、网络服务接收记录及执行树存活状态。不需要真实 LLM，也不 mock 操作系统隔离。
2. **审批身份边界：现有 WebUI HTTP API。** 通过真实认证与会话归属校验改变模式、管理目录、审批、撤销及查询状态，随后用上述工具边界验证生效。浏览器只覆盖用户可见审批与状态闭环，不为每层另造测试入口。
3. **可行性阶段边界：现有 ProcessSandbox。** 在产品接入前用真实后端验证原生能力，保留可重复夹具；产品接入后相同攻击样例经主要产品边界复验。测试专用资源与支持矩阵有明确清理规则。
4. **已有先例。** 复用现有工具执行器和子 agent 分派测试、Shell session 归属与生命周期测试、文件模式持久化测试及 FastAPI 认证 API 测试的构造方式。现有部分 Python 测试跳过 Windows，mock 启动参数的测试不能证明新隔离能力；旧 full 回退断言需随规格更新。

| 工具覆盖 | 内置读写、补丁、子 agent、后台、插件和 MCP 的实际资源遵循策略；未适配工具在直接调用时仍被拒绝 |
| 恢复与部署 | 模式及目录恢复正确，full 正确迁移，临时授权不恢复，清理保留用户 ACL；不支持环境无裸执行回退 |
| 资源与产物 | 进程、内存、期限、输出及临时容量上限有效；附件导出不能跟随恶意链接读取宿主秘密 |

先前完成切片的安全用例进入持续回归，最终票只做组合与发布资格验证，不能将必需的安全边界推迟到最终票补做。后端无法满足已认可保证时，记录可复现失败并停止依赖功能推进。

## 范围外

- 无沙箱 full 模式、自动提权、模型自批，以及按解释器名或命令前缀长期放行。
- 把工作区整体复制到隔离区再写回作为默认架构；该替代方案需要另行决策。
- 首版在聊天消息、IM 或普通 API key 中批准权限；首版临时扩权执行的自由交互输入。
- 隔离恶意已安装插件、修复任意远端 MCP 服务、保证授权网络操作的业务只读语义。
- 自动回滚已经完成的文件修改、撤销已发送请求，或崩溃后自动重放任务。
- 借本项目顺带重写 Linux/macOS 沙箱；共享接口改变须保持兼容，未通过同等级验证的平台不得继承 Windows 的保证声明。
- 无依据的通用权限框架、全仓库机械重构或与权限交付无关的 WebUI 导航重设计。

## 进一步说明

本 spec 综合已认可设计，不重新打开已确认的产品选择；尤其默认模式为 workspace，而非 readonly。它尚不表示原生候选后端通过验证。

最终后端、常驻组件必要性、身份凭证管理、支持矩阵、ACL 成本、链接竞态防护、域名出口和临时存储配额仍是技术验证项。实现者可在不降低已认可保证的前提下选择方案；若不可实现，应提交失败证据供设计复议。

交付按可演示的纵向行为拆成 tickets。未完成的工具能力保持拒绝，整个机制在全部支持矩阵验收前不得宣称可正式替代旧权限保证。发布时明确升级影响、受支持环境和故障处理方式。
