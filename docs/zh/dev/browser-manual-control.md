# 浏览器人工控制协议（H01–H05）

完整字段与连接生命周期见 [英文协议](../../en/dev/browser-manual-control.md)。

## 视频与坐标来源（V02）

新版私有运行时对 JPEG 与视频同时启用 `coordinate_contract_version: 2`。
新的离散输入必须携带已解码画面的 `coordinate_token` 和服务端签发的 `frame_id`，
不能通过省略字段降级。原生 frame/document/owner 几何及窗口、嵌套、open/closed
shadow 滚动状态在输入前再次核对；未知 frame、活跃 View Transition 和有界发现失败
会暂停新输入并允许恢复。这不锁定任意 DOM 语义或承诺任意动画下的原子点击。
已按下拖动保留原始有效锚点和完整有序移动，松开与重置仍使用原输入会话；
新增的原生路由和会话查找有整体超时。

`video_stream_version: 1`、`frame_provenance_version: 1` 声明可选视频能力。
登录态向 `POST /api/v1/plugins/browser-media/session` 提交当前聊天与浏览器身份，
取得 15 秒、一次性媒体票据。返回的同源 WebSocket 首条消息为
`{ticket,type:"offer",sdp}`，后续每五秒发送 `{operation:"heartbeat"}`。
宿主选择 owner/viewer，并持续核对账号凭证版本、聊天、插件与真实浏览器；
普通公开扩展请求不能伪造媒体上下文。凭证和私有 CDP/loopback 地址不进入媒体消息或 URL。

双方 `iceServers: []`。私有 aiortc 1.14.0 适配器只挂接所属 sender/transport，
按实际协商 VP8 payload 与最后发送的 RTP 包建立映射，关闭时还原。
最多四个观看者共享有界 CDP JPEG 采集/解码，各自离线程 VP8 编码；缺少已验证依赖时
保留 JPEG，未知适配接口仅使媒体失败关闭，不依赖公网中继、音频或硬件编码。

接收端还要求原生 `VideoFrame`，仅保留一个已验证的原生画面，避免逐帧转 JPEG。前端只使用 `requestVideoFrameCallback().rtpTimestamp` 与实际解码尺寸匹配的有界记录。
记录绑定媒体会话/epoch、浏览器代次/会话、文档、CSS 视口、滚动/完整坐标 token、
控制 epoch 和输入处理水位；晚到、缺失或歧义元数据不能用最新 SSE 状态替代。
水位是真实的画面反馈下界，不要求每输入一个字符重新采集；完整坐标仍有效时，
有序文字和快捷键可以继续使用原签发画面。
视频 target 还携带 `media_session_id`、`media_epoch`、`rtp_timestamp`、`capture_sequence`。
独立媒体序号处理 RTP 回绕；`frames=0` 观测订阅只收状态/动作，不启动竞争 JPEG 采集。
短暂元数据缺口期间，已聚焦键盘按原合法画面保留有界有序输入，待映射恢复后发送；
坐标变化或失焦丢弃队列，松键不等待新像素。捏合缩放后的视觉视口会暂停新输入，
直到缩放比例恢复为一。

视频故障保留人工所有权，明确重试或 JPEG 回退后等待有效新像素；导航和捕获 epoch
不重建 PeerConnection 或控制 WebSocket。侧栏/聊天/账号切换、关闭浏览器、停用插件和
观看端断开会清理媒体，最后一个观看者退出后停止采集和编码。停止 Agent 保留浏览器，
权限撤销清除旧画面。最终离线包安装与四观看者资源压力属于后续独立验收。

- 使用 Dashboard 登录态调用 `POST /api/v1/plugins/browser-control/session`，
  请求仅含 `chat_id`、`generation`、`browser_session_id`。宿主校验聊天所有权、
  插件启用状态及审计标记，返回 15 秒内有效、一次性使用且绑定账号凭证版本的票据。
- 在返回的同源 WebSocket 建立后 5 秒内发送 `{ticket}`；凭证不得放在 URL 中。
  服务端确认 `operation: acquire`、`status: applied` 后才允许点击。
- `control_mode` 区分 `agent`、`acquiring`、`human`、`paused`；
  服务端 `control_epoch` 与观测帧 `sequence` 独立。点击携带连续 `input_id`、
  CSS 视口坐标和当前图片的标签页、文档、视口、滚动位置，运行时再次验证真实目标。
- 重复最后一个输入编号仅返回已记录的确认，不重复执行；旧编号、跳号和旧代次拒绝。
  不提供任意 CDP、脚本执行或自行指定其他目标的代理。人工控制期间复用一致性截图路径，
  以目标上限每秒十次采集的 JPEG 经原 SSE 通道反馈静态页变化；画面和控制状态分别保留，
  避免状态消息覆盖唯一的新画面。只读模式继续兼容原有观测流。
- 每 5 秒发送心跳；宿主 15 秒无消息关闭连接，私有运行时 30 秒无续约撤销控制。
  断连或隐藏面板立即停止输入并保持暂停，不自动启动 Agent。
- 明确发送 `release` 后才交还；先清除旧元素索引并重新观测实际页面，再开放 Agent。
  浏览器、标签页和登录态保留。运行中的本地 Agent 进入可恢复的 `PAUSED`，
  等待不占普通工具超时，不持续请求模型。接管先关闭准入，取消或有界等待在途动作及已派发
  的页面事件；确认静止前不开放人工输入，失败时保持暂停。旧模型结果和批次剩余调用失效，
  工具调用与真实中断/未执行结果逐项配对。交还后的标签、页面和交互元素观测经可信宿主
  加入原轮次模型上下文，再决定下一步，不重放旧点击。取消、停止、关闭和禁用仍是终止行为；
  交还不会复活已结束的轮次或创建新任务。
- 每条输入重新校验账号、聊天与插件；私有运行时统一校验 Agent 和人工执行准入。
  旧观察客户端、停止与关闭行为保持兼容，旧插件保持只读。

## 恢复与生命周期（H05）

控制权由服务端连接持有，同聊天其他窗口显示只读占用，不能抢占。刷新、断网、隐藏
页面、关闭侧栏、切换聊天、离开页面或账号会话重置会立即关闭输入并丢弃未发送队列。
每条命令（含心跳）重新校验账号及聊天；若撤权后宿主不能授权断连清理，私有运行时
独立的 30 秒期限仍会撤销控制。重连先同步状态与新画面，再主动接管并明确交还；
已取消的任务不会重启。

输入确认丢失表示操作可能已经执行，界面停止输入、提示未知结果且不重放。旧连接响应
不能重新启用输入。交还的 SSE 状态可能先于确认到达，此时仍禁止输入并等待确认。
所有撤销及终止路径都在原 CDP 会话上以共同的有界期限释放按键与可能按下的鼠标；
鼠标在文档之外释放，避免清理时完成不确定的提交点击。失败项保留以供接管重试，交还
失败保持暂停，确认关闭后清空已销毁会话的残留。宿主恢复准入前重新核验取消、所有权
及运行代次。停止保留浏览器，关闭/禁用销毁浏览器；明确重启产生新代次，旧凭证不能
复活旧会话。只读快照可恢复静默的截帧中断，无需重启 Chromium。
截图仅使用一个绑定实际浏览器及目标的独立内部 CDP 连接及会话，不进入 Agent 输入会话池，
不设置设备模拟参数；切换目标、
关闭及失败后释放或丢弃会话，重新绑定。辅助调试连接断开后，Agent 会话残留的设备
参数不会再通过截图反复改变当前页面视口。

验收夹具支持 `--recovery --pointer-input --text-input --lost-key-target`，使用两个
独立登录客户端、真实插件及私有 Chromium，并注入网络、生命周期和确认丢失故障；
不代表物理离线安装或物理 Windows 输入法验证。


## 键盘、组合输入与粘贴（H03）

同一有序通道支持 `key`（`phase: down|up`、`code`、`key`、修饰键位掩码
`modifiers`：Alt=1/Ctrl=2/Meta=4/Shift=8，以及 `repeat`）、`text`（`text`、
`source: typing|composition|paste`）和 `reset_keys`。按键及文本与点击一样携带
`input_id`、`control_epoch` 和显示画面的 `target`。`reset_keys` 也按编号执行，
但释放的是原 CDP 会话中的按键，因此目标变化后仍可清理。宿主 schema 与私有运行时
共同限制命令类型，不提供任意 CDP 或脚本代理。文本最多 2048 字符、4096 UTF-8 字节，
不接受 NUL 或无效 Unicode，超限整条拒绝。客户端最多排队 128 条命令，逐条等待确认；
失焦、目标变化与交还会丢弃排队内容。不确定的结果停止输入，不向其他视图自动重放。

单击画面聚焦本地组合输入框。普通文字通过 `beforeinput`/`insertText` 提交；
功能键和编辑快捷键分别发送按下、松开，避免第二次字符录入，Enter 使用明确的换行语义。
输入法预编辑与候选保留本地，组合期间显示本地预编辑框；`compositionend` 最终提交一次，
取消不提交。仅从用户主动触发的 `paste` 事件读取纯文本，不轮询或同步系统剪贴板。
该输入框拥有焦点时，包含全屏在内的 Tab、Escape 都发送到远程页面。
可见的 **退出键盘控制** 按钮让焦点回到本地控件；**交还控制权** 才明确交还 Agent。
失焦、目标失效、断连、交还、租期到期和停止会在原会话释放已按下的键。
输入时间线仅包含类别，不含密码、输入或粘贴负载；交还后 Agent 仍可读取页面可见内容。

使用 `scripts/browser_manual_control_acceptance.py --text-input`，并指定正常的插件、
运行时、Dashboard 与证据目录参数，可复现真实登录生产宿主链路。其 Chromium 原生 CDP
组合输入会产生真实浏览器组合事件，但不模拟实体 Windows 输入法候选窗或系统快捷键；
这些平台行为仍需人工使用 Windows 输入法检查。

`keyboard_input_version: 1` 单独声明键盘与粘贴能力。旧插件仍可点击，并显示键盘升级提示；旧只读客户端忽略新字段。


## 滚轮、双击与反馈（H04）

`pointer_input_version: 1` 独立声明滚轮/双击能力，旧插件保留单击。
`click` 的 `click_count` 为 1 或 2；本地原生双击依次发送 count=1、count=2 的按下/松开，不额外重复单击。
`wheel` 使用 CSS `x/y`、规范化至 CSS 像素且限 ±2048 的 `delta_x/delta_y`，携带显示目标、顺序 ID 和 epoch。
仅相邻且位置/目标一致的滚轮样本可合并，点击、文字、按键不进入可替换的画面槽。最多排队 128 条，过期滚轮丢弃，不重新绑定或静默重放。

新目标的可选 `position_revision` 由文档 scroll/resize 监听器采样，覆盖嵌套滚动，与帧序号和控制 epoch 独立。截图前后核对位置，拒绝混合坐标，图片缩小至最多 1920×1080，同时保留远端 CSS 视口尺寸；保留 2 MiB JPEG、3 MiB 事件及订阅数量限制。人工模式采集间隔为 100 ms，只读保持 250 ms，实际频率受机器影响。

帧中的 `applied_input_id` 在截图前采样。前端区分排队/待确认，以及已确认但尚未加载后续同 epoch 图片；相同 JPEG 仅在真实解码后复用。`data-frame-latency` 提供最近输入到已加载画面的毫秒数供本机验收，不记录内容。真实生产链路夹具的 `--pointer-input` 记录延迟及截图。


旧滚轮样本返回消耗该顺序 ID 的 `status: stale` 确认，不执行、不自动重放；保留人工所有权并等待新画面。其他拒绝或不确定命令继续采用失败关闭语义。

## 鼠标拖动与手动刷新

`drag_input_version: 1` 声明有序 `pointer` 输入，`phase` 为 `down`、`move`、`up` 或 `cancel`。按下按当前截图完整校验目标；后续移动和松开绑定原标签页、文档与视口，允许拖动导致滚动。完整保留每个移动采样，最多 8 条在途输入，松开不丢弃、不等待截图。目标切换、失焦、取消及断线在原 CDP 会话释放鼠标；不重放未知输入。`cancel` 和 `reset_keys` 不依赖旧画面坐标。

观测首次打开连接一次，断流和空闲不自动重试；刷新按钮显式重新授权、获取快照并订阅推送。租约心跳保留，和截图刷新无关。
