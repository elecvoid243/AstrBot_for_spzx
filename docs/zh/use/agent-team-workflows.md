# 工作流资产、依赖画布与独立运行

打开 **更多功能 → Agent 团队 → 工作流资产**。先在 **角色模板** 中保存一个已就绪的角色，绑定支持工具调用的本机模型，并选用内置 Agent 执行器。

## 自主团队

选择 **工作流资产 → 新建自主团队**，填写 **团队名称**，选择 **协调者角色** 及固定版本，再选择 **允许角色模板** 并逐个固定版本。配置 **成员上限**（包含协调者）、**最大并发任务数** 和 **成员任务上限**；角色的实例数与并发限制也会生效。填写可选的 **最终版本审批问题** 后，必须批准协调者最终产物的精确版本，整个运行才能完成。**输出契约（JSON Schema）** 约束最终结果，留空使用默认文本契约。

![正式自主团队配置页面](/images/agent-autonomous-editor-zh.jpg)

保存资产，点击 **启动运行**，输入非空的 **goal** 后启动。协调者通过 `team_manage` 创建允许角色的实例、派发任务、检查完整结果和等待。成员通过 `submit_task_result` 提交契约化结果。任务依赖会固定上游原始产物版本，供 `read_task_artifact` 完整读取；协调者也能读取成员的完整原始产物。普通“完成”文本和过早提交不能完成运行，成员不能通过调用工具名称获得协调者权限。

若资产声明了附加输入，启动时逐项填写。所有声明值都会从运行的冻结输入交付协调者，多行文本和字面大括号保持原值；后续资产编辑不会改变恢复的输入。运行概览保留成员身份与关系，完整冻结配置在运行详情中按需读取。

在 **独立运行 → 查看运行** 中查看动态任务及 **本次运行成员**。**展开执行图（只读）** 显示依赖和协调者的虚线 **派发** 连线；派发连线表示创建关系，不是执行前置依赖。选择任务查看完整产物、冻结配置和成员过程。同角色的不同实例、新运行拥有独立会话；同一实例在本次运行的多个任务间延续上下文，检查点恢复后也保持该连续性。

![实际自主运行中的任务与独立成员实例](/images/agent-autonomous-run-zh.jpg)

![动态派发与任务依赖关系](/images/agent-autonomous-graph-zh.jpg)

等待成员会释放活跃执行容量，并发为 1 时仍可推进。**等待成员** 是局部等待；暂停、继续、取消、原 Attempt 恢复、显式重试与未知工具结果处理沿用下文的公共协议。成员失败或调用结果不明会阻止成功。编辑模板只影响新运行；本次运行后创建的动态成员仍使用启动时冻结的模板与配置。必要的最终审批使用已有持久化人工待办。

版本化自主执行的入口对照：**团队侧栏／运行监控 → 工作流资产 → 新建自主团队／独立运行 → 查看运行**。旧入口和历史暂时保留，后续迁移另行处理；成员直接通信与工作流调用自主团队使用下文的版本化路径。

![暗色主题下的自主运行](/images/agent-autonomous-dark.jpg)

![窄屏下的自主运行](/images/agent-autonomous-mobile.jpg)

成员工具的外部效果未知时，在 **已保存的成员过程** 中展开该调用，核对参数和证据后再按公共处理协议作出决定。独立成员可以完成，但协调者不能用这些结果绕过尚未解决的成员调用。

## 依赖画布

选择 **新建画布工作流**，填写名称、必填文本输入与最大并发任务数。从角色工具箱拖放或点击角色添加任务，再选择节点编辑名称、指令、固定角色版本、成员实例标识、输入引用与输出契约。相同成员标识的任务必须使用相同的冻结角色与配置，并串行推进同一对话；不同标识创建独立上下文，可在工作流及角色限制内并行执行。

连接任务的右侧端口与后继任务的左侧端口。点击连线或使用 **选择依赖**，开启 **字段条件**，比较上游已校验的输出字段。条件使用 `eq`、`ne`、`gt`、`ge`、`lt`、`le` 与匹配类型的值，不执行代码。字段须是上游契约中的必填标量；可通过嵌套对象、本地 Schema 引用与 `allOf` 声明。大小比较仅支持数值字段。

使用 **添加输入引用**，为全局输入或上游结果字段命名别名，在指令中插入 `{别名}`。结果引用必须存在依赖路径。后继启动时固定生产者原始产物版本，可通过 `read_task_artifact` 读取完整内容。修订上游不会改变或重新执行已有消费者。非法引用、条件和无约束回边会在保存前返回明确字段路径。当前画布支持无环依赖、持久人工待办、显式有界循环体与固定版本自主团队调用。

画布控件支持缩放、适配，工具栏提供小地图、撤销重做与按依赖自动布局。布局及属性随资产版本保存。窄屏将工具箱与属性折叠为可展开区域。选择 **保存新版本**，再从保存后的资产 **启动运行**。保存不会执行流程，后续编辑不会改变已有运行。

![正式依赖画布中的角色、输入与输出属性](/images/agent-workflow-graph-zh.jpg)

**独立运行** 中显示只读冻结图。选择节点或使用 **查看任务**，查看真实状态、等待／失败原因、执行尝试、有效配置与具体产物版本。条件不匹配时跳过对应路径；汇合等待活跃路径，跳过路径不阻塞汇合。失败只阻塞相关后继，其他就绪分支继续。全部必要路径提交已校验结果后，整体才会完成。重复调度通知不会重复派工。

![正式 WebUI 中已完成的任务与跳过路径](/images/agent-workflow-graph-run-zh.jpg)

启动时幂等收尾已处于保存安全点的提交，其他遗留执行尝试标为中断。尚未开始的独立分支仍可按持久化状态推进。选择中断任务后，可从已保存的内置模型边界继续原尝试；新的执行所有权阻止旧执行者提交迟到结果。

## 工作流调用自主团队

先保存一个已就绪的自主团队。在 **工作流资产 → 新建画布工作流** 的角色工具箱中点击 **调用自主团队**，选择节点后配置 **固定子团队资产** 和 **固定团队版本**。为所选版本的每个必填输入声明来源，可选择工作流输入或具有依赖路径的上游结果字段。输出契约沿用所选团队版本。展开画布上方的团队定义可查看固定协调者与允许角色，再折叠以保持父图简洁。

设置 **根嵌套深度上限** 与 **最大并发任务数**，点击 **保存新版本**。重开资产后保留固定版本、输入引用和布局。启动时先冻结全部子定义、角色配置和资源绑定；后续编辑子团队只影响新运行。声明的中文、多行文本和字面大括号原样交付子协调者。必填输入在解析上游结果后仍须为非空文本；非法值显示输入字段错误，不创建子作用域，无关分支继续执行。

![正式画布新增并保存的固定版本子团队节点](/images/agent-workflow-child-editor-zh.jpg)

在 **独立运行 → 查看运行** 中，进度包含实际子协调者和动态派发的成员任务。展开 **子作用域** 查看调用父节点、精确资产版本、根运行身份与子任务图。从进度、子图或 **查看任务** 选择实际子任务，读取完整产物、执行尝试和成员过程。父调用通过声明输出契约返回子团队原始的已校验产物；后继输入固定该返回版本。

![正式运行的父子关联和实际子任务图](/images/agent-workflow-child-run-zh.jpg)

父等待释放根执行容量，因此根并发为 1 时也能完成子任务。子团队等待人工、模型失败或外部工具效果未知时，无关父分支仍可执行。子人工请求在根运行的 **人工待办** 中处理；选择受影响的子任务恢复、重试或处理未知工具。重试子任务在现有作用域中创建新的 Attempt。已保存模型调用数与执行步骤包含子任务和历史尝试；无法确定时显示 **未知**。预算精细汇总另行交付。

全局暂停、继续和取消覆盖全部作用域与执行者。暂停中回答会持久保存，继续后才消费，其他局部等待保持。恢复沿用原子作用域、Attempt 与冻结输入。父子成员和会话独立，父子关联不授予跨作用域消息或产物访问；只有声明的精确输入输出引用跨越边界。协调者反向调用已保存工作流由后续任务提供。

## 运行进度与成员过程

打开 **独立运行 → 查看运行**。运行列表与历史来自已保存的运行记录；进入详情后可展开 **运行列表与历史** 切换运行。详情先显示目标、固定资产版本、任务完成数与等待原因。点击进度中的任务或右侧需要处理的任务，查看该任务的产物及成员过程；**展开执行图（只读）** 保留图上的真实任务选择与固定输入版本。

运行列表只加载最多 200 字符的目标预览、状态、进度、等待原因、执行尝试及产物入口；完整目标、冻结输入值、结果与过程记录在所选运行的详情中读取。观测游标未变化时，轮询不返回快照，也不读取已保存的过程历史；变化与重连快照仍保留完整记录。

**产物** 区域仍可选择具体版本，读取完整结果并预览或下载文件。**已保存的成员过程** 按需展开完整模型响应、提供商实际返回的思考、工具调用参数和原始工具结果。工具先返回部分结果再失败时，各条原始结果和最终错误均可读取。记录明确显示任务、执行尝试和运行成员；没有返回思考内容的模型不会出现思考区域。长内容可滚动查看，不依赖截断摘要。

![实际运行详情的目标、任务进度、等待原因与成员](/images/agent-workflow-progress-zh.png)

关闭、刷新或离开页面不会取消运行。重新打开后读取一致的持久化快照；后续变化通过单调观测游标继续读取，重复事件不覆盖较新的状态，游标过期时重新读取快照。完整已完成的响应和工具结果在进程重建后仍可读取。这里的观测游标用于重连展示，不代表恢复未完成的模型或工具调用。

![暗色主题下的运行进度](/images/agent-workflow-progress-dark.png)

窄屏将进度、等待原因与运行成员纵向排列，长名称和身份标识换行，产物及过程操作仍可访问。

![窄屏下的进度、产物与成员过程](/images/agent-workflow-progress-mobile.png)

## 成员通信

打开 **独立运行 → 查看运行 → 选择任务 → 已保存的成员过程 → 成员消息**。每条投递显示发送者和接收者实例、作用域、来源任务和执行尝试。展开后可读完整消息，区分等待消费与已消费，并查看接收任务、尝试及保存的上下文位置。**读取完整版本**按消息中的固定引用读取产物；后续修订不会改变该引用。

成员通过 `team_communicate` 查看允许的接收者并发送提问或反馈。通信限定在当前运行和执行作用域内。成员可共享自己的产物、冻结的共同输入或已经明确共享给自己的具体版本；消息不能转授其他运行或未共享版本的访问权。成员创建、派工和整体完成仍由协调者负责。发送消息不会启动新任务或把工作标记完成。

模型请求进行中收到的消息留待下一个安全请求边界处理。消费位置与该请求的有效上下文一起提交。重复投递，或在消息、工具结果、上下文保存前后重启，不会再次追加已消费的消息。现有暂停、取消、容量及原尝试恢复协议继续适用。

## 继续原尝试

打开 **独立运行 → 查看运行**，选择已中断的任务，点击 **继续同一次尝试**。页面说明最后保存的是模型请求、完整模型响应还是已开始的工具。恢复保留原 Attempt、资产版本、成员会话、有效配置、临时上下文、多模态内容、提供商思考与签名及执行计数。资源消失或权限变化会阻塞执行，不切换默认资源。

完整响应已保存时，直接复用原响应和工具计划。响应尚未保存时可重发请求；不保证恢复半段流式生成或远端计费去重。内置执行器支持完整工具 Schema 和两阶段填参；其他执行器不能使用此工作流的内部恢复。

每个工具调用保存独立的意图、执行归属、原始结果和上下文应用位置。在 **已保存的成员过程** 展开工具条目可查看这些证据。已保存结果直接复用并只应用一次；上下文已经应用时，从下一模型步骤继续。部分输出与完成状态分别保存：尚未结束的生成器中断或失败时，即使已有输出落库，调用仍保持结果未知。同批部分完成时逐个恢复：复用已保存结果，执行尚未开始的调用，外部效果未知的调用保持待确认。所有结果确定前，不放行依赖这些结果的模型请求。

## 处理结果不明的工具调用

在 **独立运行 → 查看运行** 中选择受影响的任务，进入 **已保存的成员过程**，展开结果未知的工具条目。先核对原参数、部分输出、调用身份和已保存的查询证据。该任务等待处理时，独立工作流分支仍可继续。

- 适配器在执行前明确声明状态查询、幂等键或安全重试能力时，**继续同一次尝试** 可以按原调用身份对账；**按工具声明的能力对账** 可再次检查。不确定的查询仍保持未知，工具名和超时不能作为重放依据。
- 在 AstrBot 之外已经核实完整结果时，选择 **记录核实结果并继续** 或 **记录核实失败并继续**，填写已知证据和完整工具结果，再提交。没有证据与结果的普通完成标记不能解除未知状态。
- 决定重新执行时，选择 **明确请求新的执行** 并记录依据。这可能重复产生外部效果。新的调用关联原结果不明的调用，原证据继续可读；保留已保存模型计划、原 Attempt 和固定配置。

决定与对账结果在刷新、重启后保留。同一个已提交决定重复执行不会再次安排操作；原执行者的迟到结果不能覆盖已选择的新执行。恢复只能依赖工具声明的保证，AstrBot 不承诺任意外部工具恰好产生一次效果。

![正式 WebUI 中的原结果不明调用、参数与明确重试操作](/images/agent-workflow-tool-resolution-zh.jpg)

![刷新后，新执行仍保留原调用关联与已保存证据](/images/agent-workflow-tool-resolution-completed.jpg)

结果提交属于内部幂等操作，适用于默认文本契约和通用契约，包括稳定文件引用。恢复收尾已有意图或只重做该提交，保留一个产物版本和一次完成事件。已保存的接受或拒绝结果保留原状态和上下文位置。同批其他工具必须达到已知结果安全边界后才能完成；外部效果未知时不能收尾。继续执行前会重建大工具输出的完整临时文件，临时存储清理后仍可读取已有结果引用。

## 暂停、继续、取消和重试

打开 **更多… → Agent 团队 → 独立运行 → 查看运行**。“整个运行控制”作用于根运行及现有任务执行者；选择某个任务不会把全局暂停变成局部等待。

- **暂停运行**持久化决定，停止放行新任务、模型和工具调用。已经放行的外部调用可能仍会完成；执行者保存结果后在安全点停驻。暂停不会撤销外部效果，暂停时间不消耗回复超时。
- **继续运行**使用原快照和原 Attempt 解除全局暂停，保留局部失败和工具结果待确认。进程重启后，暂停仍生效；继续会恢复原检查点。“继续同一尝试”是中断任务的检查点恢复，与创建新 Attempt 不同。
- **取消运行**向现有执行者请求取消，并永久停止新派工。请在弹窗确认决定。已完成结果、已接受的结果证据、外部效果和历史在刷新或重启后仍可读取；迟到执行者无法覆盖取消状态。
- 选择失败任务，点击 **重试失败任务**。弹窗显示原始冻结文本输入和精确产物版本；点击 **确认决定**后使用这些输入创建新 Attempt。重试不会静默选取新版产物，也不会创建新的循环迭代。展开“历史尝试”可查看失败详情、输入引用与已保存的 token 消耗；完整过程记录继续按 Attempt 关联。图任务重试沿用已有容量和成员互斥限制。

请先在“已保存的成员过程”中处理结果不明的工具调用。普通任务重试不能绕过工具对账或有证据的人工决定协议。重复相同控制或重试请求不会新增决定或 Attempt；其他控制改变版本时，请刷新后再作新决定。

整个运行暂停期间，仍可保存核实结果、核实失败、显式工具重试或对账决定。页面会确认决定已保存，等待“继续运行”，保存决定本身不会放行外部工作。继续运行或在已接受继续后重启，会使用原 Attempt 与调用证据，并遵守局部等待及容量限制。正常关闭核心服务与意外停止进程都会保留暂停后的接续决定。已保存的待执行决定在被消费前不能由另一决定替换。

## 人工待办与版本批准

1. 打开 **工作流资产 → 新建画布工作流／编辑资产**，在 **角色工具箱** 添加 **人工问题** 或 **版本批准**。人工节点无需模型或角色。问题填写原因、允许回答（每行一个，可留空）与回答长度上限。
2. 版本批准选择上游 **产物任务** 和精确 **产物版本**，并将产物任务连接为依赖。保存为资产新版本后启动；已有运行仍使用原定义。
3. 在 **独立运行 → 查看运行 → 人工待办** 处理请求。问题、约束、关联任务、Attempt 和批准对象持久保存。等待释放执行容量，只阻塞需要答案的路径；独立分支继续，结果可在执行进度中选择查看。
4. 问题选择或填写回答，再点击 **提交回答**。批准必须先点击 **预览批准对象** 查看完整的固定版本，再点击 **批准此版本**。文件可预览；**拒绝并反馈** 必须填写反馈，保留拒绝证据并阻塞受影响路径。本票不自动创建修订循环。
5. 批准后点击 **导出已批准版本**，导出 JSON 包含完整内容和精确文件引用；预览后可下载该版本的文件。配置了批准节点的产物，其未批准版本不能通过下载接口导出。创建 v2 不继承 v1 批准、不修改已有预览，也不会自动重跑下游。
6. 刷新或重启后重新打开该运行可继续处理。重复相同回答不会重复消费；已回答待办不能被另一回答覆盖。整个运行暂停时允许保存答案，并明确显示 **回答已保存，将在整个运行继续后消费**。继续保留未回答待办；取消保留原待办和回答历史并阻止新的消费。人工请求不能通过普通任务重试重写答案。

如果指定的修订版本尚未生成，待办仍保留该精确版本，预览和批准会明确提示版本不可用。先在产物任务显式创建所需修订，再回到原待办预览和批准；系统不会换成已有 v1 或最新版本，也无需创建新尝试。

## 单任务资产

1. 点击 **新建工作流**，填写名称，选择角色模板及其版本。
2. 在 **必填输入** 中填写逗号分隔的输入名称，例如 `topic`。任务正文可用 `{topic}` 引用该输入；文字中的大括号需要成对双写以转义。仅支持声明的简单占位符。
3. **输出契约（JSON Schema）** 留空时使用非空文本结果，也可填写 `type: object` 的 JSON Schema 声明证据、审查标记或文件字段。仅支持本契约内的引用，不加载远端 Schema。点击 **保存新版本**；保存只创建定义，不创建成员会话，已有运行保持原版本。
4. 在资产卡片点击 **启动运行**，填写所有必填输入。需要前序产物时，在 **固定输入产物** 中选择具体版本；选择项的摘要只用于定位内容。缺失输入或不可访问资源显示字段路径，不换用默认资源。
5. 启动后打开 **独立运行 → 查看运行**。**产物版本** 可切换查看完整文本、证据或结构化结果；长内容在结果区域滚动，内容不会被截断。文件支持 **预览文件** 和 **下载文件**。展开 **输出契约（JSON Schema）**、**结果提交历史**、**固定的有效配置** 和 **已保存的成员过程** 查看冻结的约定及字段错误。
6. 点击 **创建产物修订**，编辑完整结果 JSON，可附加已就绪的文件，再点击 **保存产物版本**。修订必须通过原契约，创建不可变的新版本；版本冲突时先刷新并选择最新版本。原运行结果和既有消费者的输入保持不变，也不会自动重跑后继。

每次运行创建新的成员身份和独立会话。运行冻结角色、输入、人格提示词及有效配置；运行中的工具纠错沿用同一成员上下文。后续编辑模板只影响新的运行。

Agent 必须调用 `submit_task_result` 按契约提交结果。默认契约接受 `{"text":"完整结果"}`。自定义契约使用唯一的 `result_json` 参数，将完整结果对象编码为 JSON 文本，例如 `{"result_json":"{\"approved\":true}"}`。参数描述在 `full` 和两阶段 `skills_like` 模式的填参请求中提供完整冻结 Schema，包括组合结构和本地引用；provider 接收兼容的字符串参数，服务端仍按原契约校验解码后的结果。非法提交返回具体字段路径，允许在剩余执行预算内修正；普通回复不会完成任务。有效提交先保存意图，执行到已保存的安全点后，在同一事务中写入结果、产物版本、完成状态和关键事件。重复提交不会生成第二次完成或重复版本。

任务使用 `read_task_artifact(artifact_id, version)` 读取固定输入的完整内容，传入该版本内的 `file_id` 可读取完整文件；实际读取的引用持久保存，不能改读未声明的新版。通过现有授权工具取得完整文件内容后，先调用 `store_task_file(filename, content, encoding)`，成功后把返回的稳定引用放入 `files: [{"file_id":"..."}]`。content 可为 UTF-8 文本或 base64 字节。文件完整存入系统管理的数据库后才可提交，不保存临时绝对路径，刷新和进程重启后仍能预览、下载。单文件最大 50 MiB。

切换或关闭页面不会停止核心执行。刷新带有 `workflow_run` 参数的地址会重新读取该运行，也可从独立运行列表重新打开。核心进程重启时，已保存安全点的有效结果意图会自动幂等收尾，其余未完成执行标记为 **已中断**。通过 **继续同一次尝试** 恢复符合条件的模型边界；结果不明的工具保持待处理。

## 配置有界审查修订循环

打开 **Agent 团队 → 工作流资产 → 新建画布工作流／编辑资产**。配置撰写和独立审查任务，连接撰写到审查的无环依赖；审查输出契约包含必填布尔字段 `approved`。点击 **添加有界循环**，选择明确的循环体、退出结果任务、字段比较（`approved eq true`）和最大轮数（1–100，不能超过成员的有效迭代限制）。任意代码表达式、图回边、重叠循环体以及离开循环体后又进入它的路径在执行前报错。

为撰写任务声明第一轮的草稿与反馈输入。在循环中 **添加反馈输入**，显式将上一轮撰写结果的 text 传给下一轮草稿，将上一轮审查的 text 传给反馈。每轮内部的普通依赖输入读取本轮产物。可折叠或展开画布上的循环分组。保存产生资产新版本，已有运行保留原定义和有效配置。

每轮创建独立 Task 和新 Attempt，固定本轮输入版本，分别保留模型、工具过程及用量。修订产物有独立的不可变资产标识：比较具体版本时同时看 `artifact_id` 和 `version`，不能只看版本数字。重试保留 Task 和本轮固定输入，创建新 Attempt；恢复继续原 Attempt 的检查点。旧内容、审查结论与批准引用不会被覆盖。

在 **独立运行 → 查看运行 → 循环轮次** 展开某一轮，可查看输入、结果、退出结论的精确引用和任务模型调用数；未知用量显示“未知”。点击任务进入完整过程、产物与控制；展开该轮执行图查看真实任务状态。执行过的循环体只有在已校验退出条件匹配后才放行组外消费者。最后一轮仍不匹配时显示 **已达轮次上限**，运行需要处理且没有成功的最终结果。循环体局部等待时独立分支继续；全局暂停和取消也作用于跨轮次边界，重启不产生重复轮次或重放已保存效果。

如果首轮整个循环体因条件未选中而跳过，循环和轮次显示 **条件未选中，已跳过**，不产生退出产物或新轮次。汇合忽略这条未选中的路径，使用活跃分支的输入。已经执行但出口被跳过、执行失败或耗尽的循环仍会阻塞依赖它的消费者；跳过任务的输入不会生成替代结果。

可选条件分支被跳过时，退出任务仍可用已校验的通过结果结束循环。如果未通过的退出条件需要读取被跳过任务的反馈，循环会进入需要处理状态，因为该轮没有可固定的反馈结果。

不添加人工节点也能独立演示通过或达到上限。需要确认报告时，在审查依赖之后配置 **版本批准** 并选择撰写产物任务；待办固定通过轮次的具体产物，导出读取被批准的引用。手动新版产物不会自动重跑消费者，也不会继承旧批准。

| 详情中的默认运行图和回复 JSON | 执行进度优先；图移至展开执行图（只读），回复移至按需展开的已保存的成员过程。 |

单任务资产继续兼容。依赖资产在相同的任务结果协议上提供无环调度、字段条件与持久人工待办；有界修订循环与自主团队复用同一调度。结果不明的工具处理已位于所选任务的过程详情内。
