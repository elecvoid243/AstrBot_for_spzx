# Agent 团队资产与运行工作台

如需从固定资料搭建并行工作流，请参阅[多文档报告教程](./agent-team-report-tutorial.md)。

本文画布和工作台截图来自真实 Dashboard、隔离数据库和受控模型服务的联验。

打开 **更多功能 → Agent 团队 → 资产**：

- **团队**：自主团队由协调者按目标派发任务，成员从预设中创建。
- **工作流**：在画布上安排一个或多个 Agent、控制节点和子资产。
- **角色模板**：保存可复用的职责和本机资源配置，供团队或工作流引用。

资产卡片展示固定版本、任务或成员摘要及草稿状态，底部提供编辑和启动入口。团队和工作流卡片左下角依次为聊天访问、导出和删除；悬停可查看按钮名称，按钮也支持键盘操作。页面支持浅色和深色主题。

## 创建与配置

选择 **资产 → 工作流 → 新建工作流**，进入独立的工作流编辑页面。在顶部填写名称，通过 **工作流设置** 选择默认模型；画布可直接添加 Agent，无需先创建角色模板。选择 Agent，配置任务、职责、配置档案、人格、模型和资源，字段旁的说明解释用途及继承规则。未选人格表示不使用人格；未单独选模型时使用工作流默认模型。启动前每个本机 Agent 都须解析到允许使用的模型。

也可在 Agent 属性中选择角色模板及其**固定版本**。开启覆盖可替换模板值，关闭则继承；空职责表示清空职责，清空人格表示不使用人格，清空模型则回到工作流默认模型。工具、Skills 和知识库分别继承或完整自定义；自定义为空表示禁用该类资源。模板发布新版后须主动升级引用，已有运行不会自动改变。直接配置可保存为角色模板；新模板不会自动替换当前配置。

选择 **资产 → 团队 → 新建自主团队**，填写名称和默认模型，配置协调者及成员预设。每项可直接配置或引用固定角色版本并覆盖；同一模板可带不同覆盖多次使用。协调者只能创建允许的预设。展开 **执行限制、子工作流与最终审批**，可设置成员上限（含协调者）、并发、成员任务上限、最终版本审批及输出契约；启动时填写目标。

![真实工作流画布](/images/agent-teams-editor-page-zh.jpg)

画布左侧添加节点，中间编排连线，右侧编辑选中节点的属性。**复用资产** 收纳已保存的团队、工作流和角色。顶部 **工作流设置** 打开默认模型、执行设置与预算；**循环与子流程** 打开有界循环配置和嵌套调用预览。两个面板都可收起，不占用画布高度。窄屏下节点库和属性面板按需展开。

入口调整：原 **新建工作流／编辑资产 → 画布弹窗** 改为 **独立工作流编辑页**（`#/agent-teams/workflows/<资产 ID>`）；原弹窗的 **关闭** 改为左上角 **返回工作流**。顶部保留试运行和保存版本操作。草稿拥有独立地址，刷新后可继续编辑；返回列表或使用浏览器返回时会等待草稿保存。保存失败或冲突时会留在编辑页，供重试或明确放弃未保存的更改。

在新版画布上，工作流输入为每个声明的名称显示一个 `string` 输出端口。Agent 任务中的 `{input}` 对应名为 `input` 的必填输入端口。把所需的工作流输入拖到该端口，再把 Agent 的 `text · string` 输出拖到 **输出** 节点的 `text · string` 端口。带 **数据** 标签的虚线传递绑定值，实线控制连线决定执行路径。选中数据线后可在属性面板断开，也可以撤销或重做。给已有输入改名时，先单独更改该名称并离开输入框，再添加或删除其他输入。断开必填端口后仍可保存草稿，完整试跑或保存版本时会标出待修复的端口。旧固定版本沿用各自的属性字段绑定。

### 结构化端口

在编辑器选择 **使用结构化端口**。选中工作流输入节点，用 JSON Schema 对象的 `properties` 声明输入，用 `required` 指定必填字段，用 `default` 为省略的字段提供默认值。要接受显式 `null`，请在字段类型中包含 `"null"`。表格可以声明为 `array`，由 `items` 定义每行的对象结构。

画布在已声明的端口上标出**必填**或**可选**，并以 JSON 显示默认值，包括 `false`、`0`、`""` 和 `null`。省略输入时使用该端口声明的默认值。输出的默认值是 Schema 注解。固定工作流调用和已安装组件显示所选版本的契约。如果拖线的类型、对象字段或数组元素有明显冲突，画布会标出接收端口。全图试运行和发布会校验结构化连线。

1. 添加 **解析 JSON 对象**，将工作流的字符串输入连到 `text`，再声明解析输出，例如名为 `query` 的对象和名为 `rows` 的行列表。
2. 添加 **映射字段**，在输入和输出契约中声明目标字段名及类型。先从解析节点向映射节点画实线控制边，再把具名端口用虚线连接。映射节点保留对象和列表的结构。Agent 的占位符需要字符串时，先连接 **将 JSON 转为文本** 节点。
3. 将映射节点的 **result · object** 连到 **输出**。保存并重开检查连线，在 **试运行草稿** 或 **启动运行** 中将输入填写为 JSON 对象。从映射节点开始试跑时，在高级 JSON 输入中填写解析节点的产出。若输入契约有 `minProperties` 等根级约束，局部试跑会显示完整的工作流输入契约。

如果工作流输入命名为 `raw`，上述例子可用 `{"raw":"{\"query\":{\"limit\":0},\"rows\":[{\"id\":1}]}"}` 试跑。

结构化端口使用第 2 版契约，也支持固定子工作流调用和有界循环反馈。文本端口和旧固定版本保留原绑定语义。结果顶层的 `files` 保留给受管理附件，普通输入可以声明同名字段。

### 判断节点

在 Dashboard 的**提供商 → 判断**中添加并测试 System One 或 OpenAI Decisions 实例。在工作流编辑器启用**使用结构化端口**，从节点库添加**判断**，选择本地 Provider 和题型，并将文本或 JSON 材料连到 `state`。布尔题给出 `matched` 与 `probability`，选择题给出 `choice` 与 `probability`，评分题给出 `score`。把这些端口接到条件节点控制分支。导入资产时，在目标实例映射判断 Provider。

超时、拒答和无效响应会阻塞节点，可在运行详情重试。有效的 `false` 会照常进入相应分支。运行详情显示实际使用的 Provider 和模型，产物发布审批仍由人工待办处理。插件可用 `ctx.decision.ask()`、`ctx.decision.choose()` 或 `ctx.decision.yes_no()`，并可在默认配置中设置插件默认判断 Provider。

![判断节点、绑定的 Provider 与类型化端口](/images/agent-teams-decision-zh.jpg)

### 已安装插件组件

AstrBot 管理员先在**插件**中安装并启用插件。在工作流编辑器启用**使用结构化端口**，从左侧节点库选择已登记的组件版本。连上具名输入、输出。组件要求知识库时，在属性面板选择本地知识库。使用结构化 JSON 输入试跑草稿，校验通过后发布固定版本。

要把工具作为独立的工作流步骤执行，由插件将工具注册为工作流组件，并声明输入和输出契约。Agent 节点使用工具允许列表，由模型决定何时调用其中的工具。

![工作流画布上的已安装组件和固定端口](/images/agent-teams-plugin-component-zh.jpg)

已发布的工作流保留精确的组件版本和契约。编辑者和运行者需要拥有相应工作流或运行，并且能使用选定资源。当前 Dashboard 通过管理员角色开放这些资产操作，服务端另行检查每个资产和运行的归属。组件禁用、卸载或契约不兼容时，可以恢复所需版本，或编辑草稿后发布新版本。

含插件组件的工作流导出为 AstrBot 原生 V4 包。在目标实例的**插件**中安装并启用对应组件，预览资产包，选择本地资源后再导入。资产包只携带定义和固定版本引用，插件代码、插件设置和凭据由各实例独立管理。

连接器中断且外部效果未明时，从 Chat 打开同一运行工作台并选择受影响任务。连接器支持对账时，使用**对账**按原调用 ID 查询。已有回执的任务沿原尝试继续。人工确认结果时，提交符合页面固定输出契约的 JSON 对象。无法核实的调用保留待处理状态。

插件作者可以覆盖 `Star.workflow_components()` 并返回 `WorkflowComponent` 声明。为组件指定稳定名称、精确版本、对象端口、外部效果和所需的知识库读取权限。异步处理器会收到结构化输入、服务端授权的绑定及调用 ID。用 `ToolRecovery` 声明查询或安全重放能力，行为变化时提升组件版本。仓库的 `tests/agent_teams/fixtures/workflow_ledger_plugin` 提供了完整示例。


### 消息、产物和受管文件

在结构化工作流中，用以下格式声明具名对象端口，再连接格式相同的端口。

| 格式 | 值 |
| --- | --- |
| `astrbot-message` | `{"text": "选中的消息"}` |
| `astrbot-artifact` | `{"artifact_id": "...", "version": 2}` |
| `astrbot-file` | `{"artifact_id": "...", "version": 2, "file_id": "..."}` |

从节点的 **$artifact** 端口传递精确结果版本。节点输出契约声明受管附件时，**$file** 端口传递该版本的唯一附件。有多个附件时，可以声明格式为 `astrbot-file` 的工作流输入，在启动表单选择版本和文件，再连接该具名输入。下游使用显式输入契约的 Agent 或**映射字段**节点。Agent 的提示词占位符接收文本端口，已绑定的消息和引用通过独立的运行输入提供。

在**试运行草稿**中，可以为范围外的上游节点选择**精确历史产物**。启动时冻结所选版本和绑定字段。在工作台的**端口绑定来源**中核对版本、预览或下载文件。受审批约束的文件需要该精确版本获批后才能下载。后续修订不会改变已冻结的引用。

## 复用工作流画布

在工具箱中使用 **搜索节点**。可将匹配项拖到画布，也可聚焦按钮后按 Enter 添加。点击 **选择草稿起点** 可使用 **解析 JSON 标题** 模板，或根据描述生成草稿。模板接收名为 `text` 的工作流输入，将 `{"title":"季度报告"}` 作为字符串输入即可试运行。生成时请选择默认本地执行配置可用、且支持工具调用的模型。AstrBot 会把描述发给该模型，生成一串可编辑的文本处理 Agent。请先检查任务及绑定，再点击 **试运行** 和 **保存版本**。

按住 Shift 在空白画布拖动可框选，按住 Ctrl/Cmd 点击可追加节点。点击 **选区分组** 为整组命名。点击 **添加备注** 后，可在属性面板编辑纯文本并在画布上拖动。可用工具栏或 Ctrl/Cmd+C 和 Ctrl/Cmd+V 复制粘贴。副本保留选区内的数据和控制连线。选区外的依赖会在诊断中定位到副本，重新连接控制线后，移除对应的缺失连线占位。Ctrl/Cmd+Z 一次撤销整次粘贴，Shift+Ctrl/Cmd+Z 重做。画布节点获得焦点后，按 Enter 选中，可用方向键移动。

### 文档工作流示例

从空实例开始时，先配置支持工具调用的聊天模型和嵌入模型。在**知识库**中使用嵌入模型创建本地知识库，上传内容为「巡检阈值为 40」的 `threshold.md`。

在 **更多功能 → Agent 团队 → 资产 → 工作流**创建一个使用聊天模型的单 Agent 工作流。将 Agent 设为结果节点，声明包含字符串 `text` 和数组 `files` 的结构化结果。任务提示可写为「使用 `store_task_file` 保存 `inspection.md`，文件内容为『仪表读数为 42』。提交简短摘要，并用 `files: [{file_id: ...}]` 附上返回的文件 ID。」全图试跑后，在已完成任务的产物中确认附件。下方的文件选择器使用该产物的精确版本。

1. 在画布点击**使用结构化端口**并声明必填输入 `document`（`{"type":"object","format":"astrbot-file"}`）及字符串 `query`。添加**读取文档**和**检索知识库**，连接 `document → file` 和 `query → query`，再选择本地知识库。
2. 将两个 `text` 输出接到 Agent 的两个输入端口，编写比较仪表读数和阈值的任务提示，按需选择现有角色、模型、Skills 和允许的工具。声明整数字段 `gauge` 和 `threshold`，连到输入输出类型一致的**字段映射**节点，设为工作流结果，并连通至 Agent 和字段映射的控制路径。检索还提供结构化 `matches` 列表，包含知识库、文档和片段 ID。
3. 保存草稿，选择**试运行草稿 → 完整流程**，输入精确文件引用和查询「巡检阈值」。检查解析和检索结果、Agent 实际收到的上下文及工具调用，以及最终结果 `{"gauge":42,"threshold":40}`。再选择**从选中节点开始**，以 Agent 为起点，选择两个上游节点的精确历史产物。此次仅执行 Agent 和字段映射。
4. 发布固定版本后用同一输入启动。固定版本保留本地知识库 ID、角色版本和资源选择。检索读取当前索引。向量检索或重排失败但仍有可用命中时，检索节点通过 `warnings` 列表返回降级诊断。

![文档工作流画布与已选本地知识库](/images/agent-teams-native-document-zh.jpg)

文档节点复用现有 Markdown、纯文本、PDF、EPUB、DOCX 和 XLS/XLSX 解析器，支持不超过 10 MiB 的受管理文件和不超过 100,000 个字符的提取文本。受审批约束的文件必须先通过对应产物版本的审批。资源、文件或工具失败时，在对应节点或尝试的工具时间线查看诊断。更正草稿或输入后可重新试跑。

含这些文档或知识库节点的工作流从 Dashboard 启动。消息平台的工作流授权不包含 Dashboard 资产所有者的文件或知识库访问。

两个原生节点都计入根运行并发和步数。文档解析消耗零模型 token。知识库接口未提供嵌入和重排用量，检索的 token 用量显示为未知。设定 token 预算时，系统会在调用前阻止显式检索。若服务在调用已有计量回执、结果尚未保存时重启，可用原输入重试失败节点。重试算作根运行的一次新调用。


## 草稿、固定版本和试运行

编辑资产及画布布局时自动保存草稿，未保存版本的新草稿也显示在列表中。检查保存状态：失败可重试；冲突时可保留本地内容或主动读取服务器草稿。若固定版本变化引起冲突，核对原基版本和最新版本后选择保留整份草稿并使用所选基版本，或读取最新版本重新编辑；系统不会合并字段。

点击 **保存版本** 校验草稿并生成固定版本。正式运行、聊天授权和新引用使用已保存版本；后续编辑不会改变已有运行的冻结定义、输入及配置。

在编辑器选择 **试运行草稿**，检查显示的草稿修订。工作流可选 **完整流程**、**仅选中节点** 或 **从选中节点开始**；自主团队试运行包含协调者和动态成员。预览列出实际执行步骤及所需输入。范围之外的上游数据可按提示选择**精确历史产物**及版本，或按字段类型填写测试数据；要求固定产物的来源须选择产物。检查后点击 **开始试运行**。

试运行真实调用模型和工具，可能产生费用或外部效果；它使用所选草稿修订，不发布固定版本。运行列表可按 **草稿试运行** 和 **正式运行** 区分，并使用同一运行工作台检查结果。

审批目标和推荐依据必须选择真实产物。孤立的全部汇合、不完整循环或缺少并行前驱的局部范围不能启动；单独测试循环内 Agent 只执行一次，并须提供初始反馈。

![真实单节点试运行](/images/agent-teams-live-trial-zh.png)

在已发布工作流的编辑器打开 **固定版本**，选择两个版本，展开有变化的部分可查看任务顺序、控制连线及其他差异。点击 **恢复为草稿** 并确认后，所选版本会替换当前草稿。若期间另一个编辑者保存了草稿或发布了新版本，重新读取并核对后再试。恢复的草稿可试运行并发布为新版本，已有运行保留各自的固定定义。

![Dashboard 固定版本比较](/images/agent-workflow-versions-zh.jpg)

## 连接输入、输出和控制路径

在输入节点声明输入。新版 Agent 可以绑定工作流输入或控制路径上游任务的必填字符串字段，并在任务中用 `{别名}` 插入绑定值。控制线决定执行顺序和路径是否激活。Agent 只接收显式绑定的字段。使用旧定义的工作流仍可通过属性面板绑定必填标量。默认输出是文本。使用第 1 版文本契约时，可在结果任务上声明名为 `text` 的必填字符串字段。文本端口校验该字段，运行结果仍是所选任务的完整已校验产物。在输出节点选择返回结果的任务。删除节点或更改字段后，按保存或启动时的诊断修复失效引用。

画布支持缩放、适配、小地图、撤销重做和自动布局；窄屏可展开工具箱及属性。添加**条件**节点，选择输入或上游必填标量、比较方式及同类型值，连接**成立**和**不成立**出口。**全部汇合**等待所有实际进入的路径成功，忽略跳过的路径；没有路径进入时汇合也跳过。局部失败阻塞依赖它的后继，独立路径仍可继续。

在 V2 画布勾选**控制入口任务**，或从工作流输入的控制锚点连到该任务。指定入口后，任务通过入口或控制线激活。数据端口单独连线。运行图标出实际经过的路径，任务状态说明跳过或缺少数据的原因。此模式下，**全部汇合**输出 `results` 数组，按控制入边的添加顺序收集已进入且成功的路径结果。可以将数组连接到下游，也可以选汇合节点作为工作流结果。

![V2 条件节点的控制入口与布尔数据连线](/images/agent-teams-v2-control-zh.jpg)

添加**列表分派**，为 Agent 选择模型，把数组连接到 `items`，在提示词中用 `{item}` 读取当前项。在节点属性中设置最大项数和并发项数，两项上限均为 30。分派项复用角色允许的成员实例，并遵守工作流和角色的并发上限。每项提交文本结果。即使有重复项或完成顺序变化，汇总仍按原输入顺序列出 `item-0`、`item-1` 等结果。空列表返回空数组。有失败项时，在运行工作台展开分派作用域并按原输入重试该项。

从**复用资产**添加已保存的工作流或自主团队作为调用节点，然后选择固定版本。在结构化画布拖动同类型的具名输入和输出端口建立连接。可选输入留空时使用子版本声明的默认值。端口允许显式空值时，连线会保留该值。自主团队显示固定版本声明的文本输入。另用控制线决定调用和后续节点何时执行。

每次调用在同一根运行中创建独立作用域，只接收画布声明并绑定的值，同时返回公开结果字段。省略子结果的内部字段或父流程配置独立审批时，公开结果具有自己的精确产物引用。显式传递的受管文件保留来源。展开子作用域可查看任务和审批。子作用域沿用根运行限制，也执行自身限制。发布新版本后，在途运行继续使用冻结的依赖。

### 人工节点和有界返工

添加**人工问题**，填写问题和可选答案；选项留空允许自由输入。可明确选择上游必填字符串字段作为推荐及理由。也可添加**版本批准**，连接产物任务，配置通过和退回路径。审批绑定具体产物及版本；退回需要反馈，不会自动重跑作者。

需要反复审查时，打开**循环与子流程**添加有界循环，把调用和审批放进循环体。选择审批的 `approved` 字段作为退出条件，与 `true` 比较，再设置最大轮数，例如两轮。把审批的 `text` 反馈映射到调用的下一轮返工输入，并为该端口配置首轮绑定或默认值。反馈保留所选值的类型。可选值缺失时，使用目标端口声明的默认值。单节点试跑也可以省略可选反馈来源。

![结构化子调用与两轮审批返工](/images/agent-teams-fixed-rework-zh.jpg)

审批固定调用时使用该调用返回的精确版本。退回后，旧待办及产物仍可查看，下一轮会收到独立审批。循环外的步骤读取通过轮次的结果。达到上限时，运行保留历史并显示需要处理的原因。在运行工作台选择具体轮次中的产物可打开记录中的精确版本。服务重启后，可以从原根运行重新打开未处理的子流程审批。

人工问题、动态选择和审批默认一直等待。可设置期限并选择继续等待或采用请求创建时已展示的有效推荐；推荐缺失、无效或依据不可用时仍等待人工，不会在期限到达时新调用模型。

## 启动与查看运行

在资产卡片选择 **启动运行**，填写声明输入及团队目标；启动前检查依赖和执行器就绪情况，按提示修复不可用资源或权限。运行使用启动时固定的资产、角色、输入和配置。修改资产只影响之后的版本和运行。

**运行 → 进行中**显示未完成运行；**待处理**集中显示需要关注的运行和 **需我处理** 的人工请求；**历史**可分页查看有权访问的资产运行。在列表选择 **查看运行**。

桌面工作台按任务、过程、待办与产物分栏。选择任务查看保存的模型回复、实际提供的思考、工具过程和产物；可按需加载更早过程、展开模型实际上下文及其装配来源。实际上下文可能被截断或由远端执行器缺省；来源先于插件修改，不保证全部保留在最终请求中。切换执行图可查看只读运行快照和任务状态；子作用域及循环轮次可展开。窄屏使用面板切换查看相同内容。后台刷新会保留正在填写的答案。

![真实运行工作台](/images/agent-teams-live-workbench-zh.png)

工作台左栏选择任务，中栏阅读执行过程，右栏处理人工请求和查看产物。**加载更早过程** 收起为工具行，展开后可分别加载过程、消息、事件和尝试记录；窄屏切换面板会保留正在查看和填写的内容。

等待前驱、配额或人工会显示原因；人工等待只阻塞相关路径。打开待办的 **查看过程** 核对依据，再回答问题。审批须先预览指定版本及文件，再批准或填写反馈退回；如指定版本不可用，先创建该版本，系统不会改用最新版。批准后可导出批准版本及其文件。暂停期间可以保存答案，继续运行后才消费；取消会关闭待办并阻止迟到推进。

关闭或刷新页面不会取消运行；重新打开可读取已保存的过程和结果。运行的所有者权限不因回答待办而授予其他人。

### 在 Dashboard Chat 打开同一次运行

在 Bot 运行工作台选择 **在 Chat 中打开**。同一资产启动多次时，每条根运行各有一条运行会话。可从 Chat 侧栏或直接链接（`#/chat/runs/<根运行 ID>`）打开，查看资产、固定版本、根运行 ID 和当前状态。草稿试运行显示草稿修订号。选择 **打开运行工作台** 可回到同一次运行。

在 Chat 的任务列表中展开子流程、子团队和循环轮次。执行过程面板显示所选任务的已保存事件、运行尝试和已记录的输入来源。用 **加载更早过程** 往前翻页。窄屏下通过 **任务**、**执行过程** 和 **待办与产物** 切换面板。右侧面板也可打开精确产物版本并下载有权限的文件。

在 **待办与产物** 中，可回答指定的人工问题，也可预览指定产物版本后批准，或填写反馈退回。Bot 和 Chat 显示同一批待办，包括嵌套流程的待办。另一页已提交决定时，卡片会刷新并显示已保存的结果。若从 Bot 待办收件箱提交时发生冲突，工作台会打开对应的运行。如果流程将返工产物送审，请打开新的待办并预览该版本后再决定。

连接中断后，已打开的会话会从最后应用的事件续读。关闭或刷新 Chat，或再次登录后，在 Chat 侧栏的 **本机** 下选择 **工作流运行**。向下滚动或选择 **加载更多** 查找较早的运行。同名会话可以用名称旁的根运行 ID 区分。选择 **全部** 可同时查看普通聊天和工作流运行。

![Chat 侧栏筛选工作流运行并打开指定的根运行](/images/agent-teams-chat-filter-zh.png)

![从 Bot 工作台打开运行会话](/images/agent-teams-run-bot-zh.png)

![Chat 运行会话中的保存过程、产物及返回工作台入口](/images/agent-teams-run-chat-zh.png)

在 **待办与产物** 的 **整个运行控制** 中暂停、继续或取消运行。原先位于 Chat 运行会话标题下方的 **取消运行** 现在也在这里。选中失败任务后，可在同一会话内重试。控件会显示结果，并在需要时提示去 Bot 工作台核对保存的结果或处理结果不明的工具调用。

![Chat 中的运行控制及失败任务重试](/images/agent-teams-chat-controls-zh.png)

已发布的运行完成后，选择 **再次启动** 并确认显示的版本。新会话沿用原运行的固定资产版本及输入，包括精确的输入产物版本。打开原会话可以比较两次运行的过程与产物。如果启动响应丢失，在同一浏览器重新打开原会话并选择 **再次启动**，即可找回同一次启动。

运行所有者可使用管理员 Dashboard 会话打开此页面。下文的外部来源授权链接有独立的访问校验。**归档会话** 会把会话移到 **查看归档**，运行继续执行。还原后会话重新出现在侧栏。

## 恢复和用量

在运行详情可暂停、继续或取消整个运行。暂停停止放行新工作，已发出的外部调用仍可能完成；取消不会撤销已发生的效果。失败任务可在核对冻结输入后 **重试失败任务**，这会创建新的尝试；使用内置执行器的任务有可续检查点时，可选择 **继续同一次尝试**。继续原尝试会复用已保存的工具结果。如果工具结果保存后模型请求失败，继续时可带着该结果重新发送原模型请求。模型请求可能产生费用。当前尝试有已保存的工具结果时，工作台禁用普通重试。若检查点不可续，请先核对已保存的结果和外部账本，再决定是否启动新的运行。

工具结果不明时，选择任务并展开 **Agent 执行过程** 中的调用，核对参数、部分输出和外部证据。只有工具明确支持的查询或安全对账才能用于确认；查询仍不确定时保持等待。已在外部核实完整结果或失败时，可记录证据和结果；也可明确请求新的执行，但可能重复外部效果。普通重试不能绕过此决定。远端执行器如支持 **查询原远端运行**，先查询原身份；查不到或状态不明不代表操作未发生，决定新尝试前应检查远端服务。

在资产的 **范围限制** 中按需设置调用步数、成员、循环轮数和 token 等上限；保存新版本后应用于新运行。**运行 → 查看运行 → 用量与限制**显示根运行及子作用域、历史尝试的用量。提供商未报告的消耗显示未知，不等于免费；插件或工具内部未计量的费用不受此处硬限制。估算和并发预留也不能保证绝不超额。达到限制后新调用会停止，已保存的结果和效果仍可查看。

## 从聊天调用和处理待办

1. 请调用者在目标平台会话发送 `/asset whoami`。资产所有者打开资产卡片的 **聊天访问**，粘贴完整返回内容，核对平台、发送者、来源会话和配置档案，再选择 **开放此版本**。授权绑定该发送者、确切会话及固定版本；粘贴内容本身不证明身份或授予管理权限。群聊授权允许最终结果在群内可见。
2. 所有可达角色、允许的成员和嵌套工作流必须使用来源配置档案，并遵守模型、人格、工具、技能和知识库限制。导入资产不会自动授权；撤销访问阻止后续调用和结果投递，已有执行记录保留。
3. 调用者用 `/asset list` 查看授权资产，再按卡片提示发送 `/asset <名称或 ID> | {"输入名":"值"}`。名称不唯一或缺少输入时先澄清；普通聊天不会自动选择资产。使用 `/asset status <运行 ID>` 在原授权会话重新取得已有运行的通知和入口。
4. 打开运行链接并保持页面打开，由**原发起者在原会话**发送页面显示的 `/asset connect <连接码>`。连接仅限本次运行、有效期 30 分钟；短时断网时保持页面打开，等待自动重试或点击 **检查连接 / 刷新**，即可继续查看同一运行和待办。刷新整个页面、连接到期或服务重启后，需要重新确认连接才能继续处理原运行。链接或连接码不会让其他群成员取得发起者身份。
5. 在受限页面回答同一人工待办或审批其指定的精确产物版本，也可按原会话通知中的指令回答。审批只能查看请求指定版本及其声明的文件；完成后可读取根运行发布的最终结果及文件。所有者的过程、思考、工具记录和资源配置不开放。撤销授权或来源配置档案变化后，已有连接也不能继续读写。

Satori 会话和 Misskey note 会话当前不能唯一保留所需来源身份，不能用于资产调用；Misskey 私聊和聊天室可用。企业微信智能机器人须有可用的原会话响应通道：HTTP 回调模式需关闭仅 webhook 发送并设置非空初始响应；通道过期或重启后，在原授权会话发送 `/asset status <运行 ID>` 取回待发送内容。

## 从 Bot、消息平台和公开 API 启动同一固定版本

三个入口均校验已发布的输入契约，并在启动时冻结有效输入和固定依赖。按声明的字段名和类型提交 JSON 对象。缺省字段使用已声明的默认值。显式传入的 `null` 保留原值，输入类型须允许空值。消息平台的 `/asset list` 会列出授权的固定版本、必填字段和结构化输入类型。平台用同一上游消息 ID 重投时复用原运行。另发一条命令会独立启动。无法提供稳定上游消息 ID 的适配器无法识别重投。

Bot 启动请求丢失响应时，在原浏览器标签页重新打开同一资产和版本并提交原输入。Dashboard 会先查询待确认回执，再检查当前本地资源。每次独立启动有单独的根运行和 Chat 运行会话。固定子调用归入所属根运行，沿用其预算和可见性边界。

![真实 Dashboard Chat 中的三次独立启动](/images/agent-teams-authorized-launch-zh.jpg)

### 授权公开 API 调用者

1. 在 Dashboard **设置 → OpenAPI** 创建带 `workflow` 权限的 API Key，生成时复制密钥。用已登录的 Dashboard 管理员会话请求 `GET /api/apikey/list` 取得 `key_id`。授权时使用该标识符，调用公开 API 时使用密钥。
2. 用 Dashboard 资产所有者的会话发送 `PUT /api/v1/workflow_assets/{asset_id}/api_access/{key_id}`，请求体为 `{"version":1}`。使用该 Dashboard 会话的 Cookie 或 JWT 认证。启动需要同时具备 scope 和固定版本授权。资产 ID 和已发布版本可从卡片或所有者端点 `GET /api/v1/workflow_assets` 核对。
3. 带上 `Authorization: ApiKey <密钥>`，发送 `POST /api/v1/workflows/{asset_id}/runs`，例如 `{"version":1,"request_id":"inspection-001","inputs":{"query":{"gauge":42}}}`。根据资产契约填写 `inputs`。用相同 `request_id` 重发有效输入相同的请求。对已提交的请求 ID 改动有效载荷会返回 HTTP 409，独立启动请使用新 ID。
4. 使用原 API Key 查询 `GET /api/v1/workflows/runs/{run_id}`，获取根运行状态和完成后的发布结果。Dashboard 所有者可以打开该运行会话。公开 API Key 无权打开 Dashboard 工作台、读取子运行或取得消息平台连接凭据。

使用资产所有者的 Dashboard 会话执行 `DELETE /api/v1/workflow_assets/{asset_id}/api_access/{key_id}` 可撤销单项授权，也可在 **设置 → OpenAPI** 撤销 API Key。撤权阻止重放、读取结果，以及通过下一次执行准入启动新工作。已获准发出的调用可以完成。外部启动授权仅适用于允许的输入和节点。Dashboard 历史产物和文件输入、原生文档或知识库节点、已安装插件组件仍限站内，包括固定子调用里的节点。AstrBot 现有提醒和 Agent 定时任务没有固定工作流版本启动入口。

## 导入、导出与删除

在 **资产 → 团队／工作流** 选择 **导出资产 JSON**，包包含入口的固定子资产和角色及资源需求，不包含凭证、资源内容、授权或运行历史。在目标实例选择 **导入资产包 → 校验并预览**，逐项选择兼容的本机配置档案、模型、人格、工具、技能和知识库，即使 ID 相同也须选择。缺少资源时先配置，再确认安装。安装完整依赖或整体失败；导入不会安装插件、执行脚本或启动运行。

在团队、工作流或角色卡片选择 **删除**并确认影响。所有版本退出新的选择范围，不能直接启动，已有聊天授权也不能启动；既有固定引用、进行中的运行、历史和产物保留。已有父资产仍可使用原固定引用，但不能新增引用。导出有效父资产仍包含其固定依赖；重新导入对应已删除资产的包会冲突，不会恢复资产。删除无法撤销。
