# 工作流资产、依赖画布与独立运行

打开 **更多功能 → Agent 团队 → 工作流资产**。先在 **角色模板** 中保存一个已就绪的角色，绑定支持工具调用的本机模型，并选用内置 Agent 执行器。

## 将完整嵌套资产移植到另一实例

在实例 A 的**工作流资产**中，选择单任务工作流、画布工作流或自主团队的**导出资产 JSON**，检查实际包含的提示词与完整 JSON，然后**下载 JSON**。导出前先补齐源实例缺失的资源。版本化 `astrbot.workflow` 包包含资产身份、固定角色版本、契约、条件、有界循环、布局和逻辑依赖。格式 2 包含所有精确版本子团队与子工作流的完整闭包，子定义不依赖仅存在于原机器的资产；既有格式 1 单层包仍可导入。继承得到的有效提示词和资源允许列表会转成明确内容，`prompt_source` 标明实际包含的提示词来自角色、人格、配置文件还是任务覆盖。包不携带知识库内容、本机凭证、绑定 ID、会话或运行历史。

![正式完整资产导出对话框](/images/agent-nested-package-export-zh.jpg)

在实例 B 选择**工作流资产 → 导入资产包**，选择 JSON 文件或粘贴完整内容，再选择**校验并预览**。格式、契约、所有固定引用、返回任务、深度、循环引用与迭代限制通过校验后才会安装；未知格式版本与脚本字段会被拒绝。**包含的固定资产版本**逐项展示确认后将安装、复用相同版本还是添加新版本。

核对实际提示词，并展开**查看完整定义、契约、布局与依赖**。每个角色集中显示配置文件和本机资源槽位，并保留原逻辑用途和资源说明。核对所需工具输入结构，以及所选候选的说明和输入结构；已声明的工具输入结构必须匹配。模型自动匹配要求适配器、模型及来源指纹一致、能力满足且候选唯一；配置文件还须允许兼容模型并满足执行器要求。显示名称相同不代表兼容。没有来源证据的资源，包括工具、技能和知识库，需要明确审查并选择本机资源。配置文件与人格的权限限制仍然生效，包不会授予权限。缺少候选时可通过**配置本机资源**进入原有配置入口；插件或外部服务需要自行配置。

![正式嵌套闭包与集中依赖配置](/images/agent-nested-package-import-zh.jpg)

检查就绪和每次新启动都会重新校验包内全部已声明依赖，包括被任务覆盖为未使用的基础资源；重建服务后这些要求仍然保留。运行中的任务在继续外部工作前，也会校验原包要求和该次冻结绑定，包括人工等待、暂停或检查点恢复之后。若已绑定资源的 ID 不变，但模型来源或工具输入结构变为不兼容，执行会被阻止。恢复原资源的兼容配置后，再继续或重试受影响任务。编辑资产或重新绑定当前安装只影响新运行，不会替换已有运行的冻结绑定或改写其快照。

独立导出的子定义保留角色默认值和显式声明的工具、技能、知识库要求；仅由任务覆盖引入的依赖归属于使用它的精确资产版本。因此，父定义新版增加工具覆盖时会复用未修改的子定义，保留其仍然兼容的原有绑定。有效要求不同的上下文采用独立本机安装，包括协调者所需能力。显式未使用依赖和既有格式的声明仍须匹配兼容且当前有权限的绑定，不会扩大可执行资源允许列表。角色默认提示词缺失、由任务补充时，每个任务仍保留自己的完整指令。

依赖预览也会检查复用的安装。原资源不可用、且经来源校验只有一个兼容匹配时，可以自动选择替代资源；仍然兼容的保存选择会保留。若复用安装保存了不同的兼容选择，须选择并确认统一绑定后再安装；缺失或歧义仍显示未就绪。保存为待配置时，未解决字段会保留原有绑定，包括界面发送自动复制的预览建议时。新绑定只影响新运行，已有运行保留冻结选择。同一子定义经多条路径引用时，必须满足每条路径的深度限制。

![父定义新增工具后添加第二版，两个未修改的第一版子定义继续复用](/images/agent-nested-package-parent-upgrade-zh.jpg)

包内固定引用入口资产的其他版本时，安装仍保留子引用的精确版本，并将选中的入口设为编辑和新运行使用的默认本机版本。

依赖选择会保留在已审查的包上，编辑或替换 JSON 后才会清空。预览会根据角色的有效设置检查循环迭代次数和不同成员的数量，包括从所选本机配置继承的限制。限制阻止安装时，请选择兼容配置或修正源资产。

每个成员自身的深度上限都会按其引用深度检查，包括末端成员和经不同路径到达的共享子定义。深度为空时继承所选本机配置。协调者的上限也约束其声明的子调用；其他成员保留自身所在深度的限制。导入资产的就绪检查和新运行会校验当前定义的完整闭包，后续本地版本同样生效。普通本地资产保留运行时调用边界的检查。保存为待配置的父资产在闭包就绪前仍会阻止启动；独立就绪的子资产可以从自己的入口运行。共享角色的待配置升级或独立包，其图限制与仍然有效的旧版本分别校验。每次启动都会检查所选固定版本闭包和原包资源契约。

模型响应之后或工具／用量准入边界发现不兼容时，任务保留资源阻塞状态及具体绑定原因。真正的检查点或用量存储失败仍会停止后继执行。恢复原资源后，**继续同一次尝试** 会复用已保存的完整响应，包括 OpenAI 流式响应；**重试失败任务** 会创建新 Attempt，并保留旧阻塞历史。

![实际进程重建后，同 ID 来源漂移阻止普通启动](/images/agent-workflow-package-drift-zh.jpg)

![人工回答已保存后，绑定模型变化使研究任务保持阻塞](/images/agent-workflow-package-waiting-zh.jpg)

依赖齐全后，一次**确认安装**即可在同一事务中保存全部定义和已审查的本机绑定；校验或存储失败不会留下可执行半成品。随后使用资产原有的**启动运行**并填写声明输入。缺失或歧义时可**保存为待配置**，保留整个闭包，但受影响的入口不能启动。再次导入同一个 JSON 可补齐本机绑定，相同版本会复用。升级在同一资产身份下追加可选的本机新版本，每条子引用仍映射到精确安装版本。同资产或角色身份同版本但内容不同会明确冲突。已有运行、子定义、历史产物与审批保留原快照，进程重启后也不改写；本机角色升版不会取消原包兼容要求或当前权限检查。

![正式导入后的工作流运行](/images/agent-workflow-package-run-zh.jpg)

## 从普通聊天明确调用资产

请调用者在目标平台会话发送 `/asset whoami`，取得真实的平台实例 ID、发送者 ID、来源会话（UMO）和来源配置档案 ID。显示名称或与 Dashboard 账户重名的发送者 ID 不会关联两种身份。

资产所有者进入 **Agent 团队 → 工作流资产 → 聊天访问**，填入这四项内容，选择 **开放此版本**。授权固定为页面显示的资产版本，并允许向该确切会话返回最终结果；群聊授权因此明确允许结果在该群内可见。所有可达角色、允许创建的成员及嵌套工作流必须使用来源配置档案，继续遵守现有模型／人格池及工具、技能、知识库限制。导入资产包不会自动向聊天用户开放。选择 **撤销访问** 后阻止后续外部调用和结果投递，已发生的执行仍保留记录。


使用 `/asset list` 查看已开放的资产名称、ID、固定版本和必填输入名称。例如明确调用：

```text
/asset 调研报告 | {"topic":"风能"}
```

同名资产使用返回的资产 ID 区分。缺少必填输入时，在下一条明确指令中补齐字段；选择和输入有效前不会创建运行。普通聊天不会自动选择资产。使用 `/asset status <运行 ID>` 可在同一已授权来源会话中重新连接已受理的根运行。

来源会话会收到受理、人工输入提示及最终契约化结果，长结果分段发送。消息包含运行 ID 和 `/#/asset-run?workflow_run=...` 路径，将其接在本实例 WebUI 地址后即可打开 **聊天发起的运行**。页面显示 `/asset connect <连接码>`，请由本次运行的实际发起人在最初的同一个聊天会话发送该指令，并保持浏览器页面打开。确认后，无需 Dashboard 账户即可查看本次运行状态、回答原来的持久人工待办及读取最终结果。群里的链接和连接码本身不会让其他群成员取得发起者身份。

连接仅限这次运行，有效期 30 分钟；到期、刷新页面或服务重启后重新连接并确认，仍处理原运行和同一个待办，不会重新发起资产执行。撤销授权或修改来源配置档案后，已有连接也不能继续读写。审批待办只能预览它明确要求的固定产物版本及该版本声明的文件，不提供其他子产物、版本、导出或修改入口。所有者私有的运行过程、思考、工具记录和资源配置不会开放给发起者。

入口映射：聊天返回的旧 `/#/agent-teams?workflow_run=...` 改为发起者受限入口 `/#/asset-run?workflow_run=...`；前者仍作为所有者登录 Dashboard 后的完整 **独立运行** 详情入口。旧消息只有运行 ID 时，可从原授权会话发送 `/asset status <运行 ID>` 获取新入口。

完成后，可选择 **预览文件** 在当前页面读取最终文本文件，或选择 **下载文件** 取得带原文件名的完整字节；二进制文件请下载后使用本机应用打开。文件列表仅包含本次根运行实际发布的不可变结果版本所声明的文件，无需额外创建审批待办。所有者后续修订、无关子产物及其他运行的文件不会因此开放。每次文件请求仍须通过原来源确认和当前授权校验。

![发起人确认后的浏览器处理原有持久人工待办](/images/agent-chat-source-question-zh.jpg)

![真实进程重启并重新连接后，原运行完成并显示最终结果](/images/agent-chat-source-result-zh.jpg)

运行保存带平台命名空间的实际发起人及来源，由资产所有者继续在 Dashboard 管理这次委托运行。合成成员消息保持普通成员权限，即使 ID 与管理员重名也不会提升。聊天仅能读取根运行已完成的最终结果，不能通过子任务 ID 或未批准版本越过结果边界。重启后续传已有通知游标、继续处理原待办；平台已受理消息但回执尚未保存时崩溃，可能重复投递消息，不会因此重新发起资产运行。

来源必须唯一标识接收受众和账号。Satori 会话和 Misskey note 会话的现有来源身份不能保留这一区分，当前不可用于资产调用；Misskey 私聊和聊天室继续支持。请使用受支持的独立会话，或由所有者在 WebUI 发起资产运行。

企业微信智能机器人的资产回复要求原会话响应通道可用。HTTP 回调模式须关闭仅 webhook 发送，并设置非空的初始响应文本，让平台获得可轮询的流；否则 `/asset` 不会创建运行。长连接模式可以使用原请求回复，即使普通回复配置为仅 webhook 发送。资产通知不会发到全局群 webhook。原响应过期或进程重启后，请在同一个已授权会话、响应通道可用时发送 `/asset status <运行 ID>`，取回待发送通知和结果。无法确认原会话投递通道时，消息保持待发送状态。

## 自主团队

选择 **工作流资产 → 新建自主团队**，填写 **团队名称**，选择 **协调者角色** 及固定版本，再选择 **允许角色模板** 并逐个固定版本。配置 **成员上限**（包含协调者）、**最大并发任务数** 和 **成员任务上限**；角色的实例数与并发限制也会生效。填写可选的 **最终版本审批问题** 后，必须批准协调者最终产物的精确版本，整个运行才能完成。**输出契约（JSON Schema）** 约束最终结果，留空使用默认文本契约。

![正式自主团队配置页面](/images/agent-autonomous-editor-zh.jpg)

保存资产，点击 **启动运行**，输入非空的 **goal** 后启动。协调者通过 `team_manage` 创建允许角色的实例、派发任务、检查完整结果和等待。成员通过 `submit_task_result` 提交契约化结果。任务依赖会固定上游原始产物版本，供 `read_task_artifact` 完整读取；协调者也能读取成员的完整原始产物。普通“完成”文本和过早提交不能完成运行，成员不能通过调用工具名称获得协调者权限。

若资产声明了附加输入，启动时逐项填写。所有声明值都会从运行的冻结输入交付协调者，多行文本和字面大括号保持原值；后续资产编辑不会改变恢复的输入。运行概览保留成员身份与关系，完整冻结配置在运行详情中按需读取。

在 **独立运行 → 查看运行** 中查看动态任务及 **本次运行成员**。**展开执行图（只读）** 显示依赖和协调者的虚线 **派发** 连线；派发连线表示创建关系，不是执行前置依赖。选择任务查看完整产物、冻结配置和成员过程。同角色的不同实例、新运行拥有独立会话；同一实例在本次运行的多个任务间延续上下文，检查点恢复后也保持该连续性。

![实际自主运行中的任务与独立成员实例](/images/agent-autonomous-run-zh.jpg)

![动态派发与任务依赖关系](/images/agent-autonomous-graph-zh.jpg)

等待成员会释放活跃执行容量，并发为 1 时仍可推进。**等待成员** 是局部等待；暂停、继续、取消、原 Attempt 恢复、显式重试与未知工具结果处理沿用下文的公共协议。成员失败或调用结果不明会阻止成功。编辑模板只影响新运行；本次运行后创建的动态成员仍使用启动时冻结的模板与配置。必要的最终审批使用已有持久化人工待办。

版本化自主执行的入口对照：**团队侧栏／运行监控 → 工作流资产 → 新建自主团队／独立运行 → 查看运行**。旧入口和历史暂时保留，后续迁移另行处理；成员直接通信与工作流调用自主团队使用下文的版本化路径。

![暗色主题下的自主运行](/images/agent-autonomous-dark.jpg)

![窄屏下的自主运行](/images/agent-autonomous-mobile.jpg)

成员工具的外部效果未知时，在 **已保存的成员过程** 中展开该调用，核对参数和证据后再按公共处理协议作出决定。独立成员可以完成，但协调者不能用这些结果绕过尚未解决的成员调用。

## 协调者调用已保存工作流

进入 **工作流资产 → 新建自主团队／编辑资产 → 允许调用的工作流**，通过 **允许一个已保存工作流** 添加引用，选择 **固定工作流版本** 和 **返回任务**。面板展示该版本的必填文本输入和返回任务的输出契约。单任务工作流返回 **result** 任务；画布工作流返回所选任务。将团队保存为新版本；未列入允许范围的工作流不能由其协调者调用。

![正式 WebUI 中允许工作流的固定版本与返回契约](/images/agent-team-workflow-config-zh.jpg)

设置 **根运行嵌套深度上限** 和 **最大并发任务数**，再 **启动运行** 并填写目标。协调者调用允许的工作流时须提供所有声明输入，可显式交接可见的精确产物版本。每次调用创建独立成员，不继承父对话和无关产物。协调者等待调用任务，再读取完整结果及不可变产物。所选返回任务必须具有已校验结果；返回任务被跳过时，即使其他路径完成，调用仍明确需要处理。

在 **独立运行 → 查看运行** 选择协调者，通过调用旁的 **查看子工作流** 进入调用任务，查看返回值、父调用产物和精确子返回引用。嵌套团队中的协调者也使用这一路径。再次选择 **查看子工作流** 可检查子任务，或展开 **子作用域** 查看保存的工作流图。**人工待办**、进度和 **已保存的成员过程** 展示实际任务、等待、尝试及工具结果。

![正式 WebUI 中协调者、工作流任务与精确返回产物](/images/agent-team-workflow-run-zh.jpg)

## 依赖画布

选择 **新建画布工作流**，填写名称、必填文本输入与最大并发任务数。从角色工具箱拖放或点击角色添加任务，再选择节点编辑名称、指令、固定角色版本、成员实例标识、输入引用与输出契约。相同成员标识的任务必须使用相同的冻结角色与配置，并串行推进同一对话；不同标识创建独立上下文，可在工作流及角色限制内并行执行。

连接任务的右侧端口与后继任务的左侧端口。点击连线或使用 **选择依赖**，开启 **字段条件**，比较上游已校验的输出字段。条件使用 `eq`、`ne`、`gt`、`ge`、`lt`、`le` 与匹配类型的值，不执行代码。字段须是上游契约中的必填标量；可通过嵌套对象、本地 Schema 引用与 `allOf` 声明。大小比较仅支持数值字段。

使用 **添加输入引用**，为全局输入或上游结果字段命名别名，在指令中插入 `{别名}`。结果引用必须存在依赖路径。后继启动时固定生产者原始产物版本，可通过 `read_task_artifact` 读取完整内容。修订上游不会改变或重新执行已有消费者。非法引用、条件和无约束回边会在保存前返回明确字段路径。当前画布支持无环依赖、持久人工待办、显式有界循环体与固定版本自主团队调用。

画布控件支持缩放、适配，工具栏提供小地图、撤销重做与按依赖自动布局。布局及属性随资产版本保存。窄屏将工具箱与属性折叠为可展开区域。选择 **保存新版本**，再从保存后的资产 **启动运行**。保存不会执行流程，后续编辑不会改变已有运行。

## 继续原尝试

打开 **独立运行 → 查看运行**，选择已中断的任务，点击 **继续同一次尝试**。页面说明最后保存的是模型请求、完整模型响应还是已开始的工具。恢复保留原 Attempt、资产版本、成员会话、有效配置、临时上下文、多模态内容、提供商思考与签名及执行计数。资源消失或权限变化会阻塞执行，不切换默认资源。

完整响应已保存时，直接复用原响应和工具计划。响应尚未保存时可重发请求；不保证恢复半段流式生成或远端计费去重。内置执行器支持完整工具 Schema 和两阶段填参；其他执行器不能使用此工作流的内部恢复。

每个工具调用保存独立的意图、执行归属、原始结果和上下文应用位置。在 **已保存的成员过程** 展开工具条目可查看这些证据。已保存结果直接复用并只应用一次；上下文已经应用时，从下一模型步骤继续。部分输出与完成状态分别保存：尚未结束的生成器中断或失败时，即使已有输出落库，调用仍保持结果未知。同批部分完成时逐个恢复：复用已保存结果，执行尚未开始的调用，外部效果未知的调用保持待确认。所有结果确定前，不放行依赖这些结果的模型请求。

## 处理结果不明的工具调用

在 **独立运行 → 查看运行** 中选择受影响的任务，进入 **已保存的成员过程**，展开结果未知的工具条目。先核对原参数、部分输出、调用身份和已保存的查询证据。该任务等待处理时，独立工作流分支仍可继续。

- 适配器在执行前明确声明状态查询、幂等键或安全重试能力时，**继续同一次尝试** 可以按原调用身份对账；**按工具声明的能力对账** 可再次检查。不确定的查询仍保持未知，工具名和超时不能作为重放依据。
- 在 AstrBot 之外已经核实完整结果时，选择 **记录核实结果并继续** 或 **记录核实失败并继续**，填写已知证据和完整工具结果，再提交。没有证据与结果的普通完成标记不能解除未知状态。
- 决定重新执行时，选择 **明确请求新的执行** 并记录依据。这可能重复产生外部效果。新的调用关联原结果不明的调用，原证据继续可读；保留已保存模型计划、原 Attempt 和固定配置。

决定与对账结果在刷新、重启后保留。同一个已提交决定重复执行不会再次安排操作；原执行者的迟到结果不能覆盖已选择的新执行。恢复只能依赖工具声明的保证，AstrBot 不承诺任意外部工具恰好产生一次效果。

## 暂停、继续、取消和重试

打开 **更多… → Agent 团队 → 独立运行 → 查看运行**。“整个运行控制”作用于根运行及现有任务执行者；选择某个任务不会把全局暂停变成局部等待。

- **暂停运行**持久化决定，停止放行新任务、模型和工具调用。已经放行的外部调用可能仍会完成；执行者保存结果后在安全点停驻。暂停不会撤销外部效果，暂停时间不消耗回复超时。
- **继续运行**使用原快照和原 Attempt 解除全局暂停，保留局部失败和工具结果待确认。进程重启后，暂停仍生效；继续会恢复原检查点。“继续同一尝试”是中断任务的检查点恢复，与创建新 Attempt 不同。
- **取消运行**向现有执行者请求取消，并永久停止新派工。请在弹窗确认决定。已完成结果、已接受的结果证据、外部效果和历史在刷新或重启后仍可读取；迟到执行者无法覆盖取消状态。
- 选择失败任务，点击 **重试失败任务**。弹窗显示原始冻结文本输入和精确产物版本；点击 **确认决定**后使用这些输入创建新 Attempt。重试不会静默选取新版产物，也不会创建新的循环迭代。展开“历史尝试”可查看失败详情、输入引用与已保存的 token 消耗；完整过程记录继续按 Attempt 关联。图任务重试沿用已有容量和成员互斥限制。

请先在“已保存的成员过程”中处理结果不明的工具调用。普通任务重试不能绕过工具对账或有证据的人工决定协议。重复相同控制或重试请求不会新增决定或 Attempt；其他控制改变版本时，请刷新后再作新决定。

整个运行暂停期间，仍可保存核实结果、核实失败、显式工具重试或对账决定。页面会确认决定已保存，等待“继续运行”，保存决定本身不会放行外部工作。继续运行或在已接受继续后重启，会使用原 Attempt 与调用证据，并遵守局部等待及容量限制。正常关闭核心服务与意外停止进程都会保留暂停后的接续决定。已保存的待执行决定在被消费前不能由另一决定替换。

## 人工待办与版本批准

1. 打开 **工作流资产 → 新建画布工作流／编辑资产**，在 **角色工具箱** 添加 **人工问题** 或 **版本批准**。人工节点无需模型或角色。问题填写原因、允许回答（每行一个，可留空）与回答长度上限。
2. 版本批准选择上游 **产物任务** 和精确 **产物版本**，并将产物任务连接为依赖。保存为资产新版本后启动；已有运行仍使用原定义。
3. 在 **独立运行 → 查看运行 → 人工待办** 处理请求。问题、约束、关联任务、Attempt 和批准对象持久保存。等待释放执行容量，只阻塞需要答案的路径；独立分支继续，结果可在执行进度中选择查看。
4. 问题选择或填写回答，再点击 **提交回答**。批准必须先点击 **预览批准对象** 查看完整的固定版本，再点击 **批准此版本**。文件可预览；**拒绝并反馈** 必须填写反馈，保留拒绝证据并阻塞受影响路径。本票不自动创建修订循环。
5. 批准后点击 **导出已批准版本**，导出 JSON 包含完整内容和精确文件引用；预览后可下载该版本的文件。配置了批准节点的产物，其未批准版本不能通过下载接口导出。创建 v2 不继承 v1 批准、不修改已有预览，也不会自动重跑下游。
6. 刷新或重启后重新打开该运行可继续处理。重复相同回答不会重复消费；已回答待办不能被另一回答覆盖。整个运行暂停时允许保存答案，并明确显示 **回答已保存，将在整个运行继续后消费**。继续保留未回答待办；取消保留原待办和回答历史并阻止新的消费。人工请求不能通过普通任务重试重写答案。

如果指定的修订版本尚未生成，待办仍保留该精确版本，预览和批准会明确提示版本不可用。先在产物任务显式创建所需修订，再回到原待办预览和批准；系统不会换成已有 v1 或最新版本，也无需创建新尝试。

## 单任务资产

1. 点击 **新建工作流**，填写名称，选择角色模板及其版本。
2. 在 **必填输入** 中填写逗号分隔的输入名称，例如 `topic`。任务正文可用 `{topic}` 引用该输入；文字中的大括号需要成对双写以转义。仅支持声明的简单占位符。
3. **输出契约（JSON Schema）** 留空时使用非空文本结果，也可填写 `type: object` 的 JSON Schema 声明证据、审查标记或文件字段。仅支持本契约内的引用，不加载远端 Schema。点击 **保存新版本**；保存只创建定义，不创建成员会话，已有运行保持原版本。
4. 在资产卡片点击 **启动运行**，填写所有必填输入。需要前序产物时，在 **固定输入产物** 中选择具体版本；选择项的摘要只用于定位内容。缺失输入或不可访问资源显示字段路径，不换用默认资源。
5. 启动后打开 **独立运行 → 查看运行**。**产物版本** 可切换查看完整文本、证据或结构化结果；长内容在结果区域滚动，内容不会被截断。文件支持 **预览文件** 和 **下载文件**。展开 **输出契约（JSON Schema）**、**结果提交历史**、**固定的有效配置** 和 **已保存的成员过程** 查看冻结的约定及字段错误。
6. 点击 **创建产物修订**，编辑完整结果 JSON，可附加已就绪的文件，再点击 **保存产物版本**。修订必须通过原契约，创建不可变的新版本；版本冲突时先刷新并选择最新版本。原运行结果和既有消费者的输入保持不变，也不会自动重跑后继。

每次运行创建新的成员身份和独立会话。运行冻结角色、输入、人格提示词及有效配置；运行中的工具纠错沿用同一成员上下文。后续编辑模板只影响新的运行。

Agent 必须调用 `submit_task_result` 按契约提交结果。默认契约接受 `{"text":"完整结果"}`。自定义契约使用唯一的 `result_json` 参数，将完整结果对象编码为 JSON 文本，例如 `{"result_json":"{\"approved\":true}"}`。参数描述在 `full` 和两阶段 `skills_like` 模式的填参请求中提供完整冻结 Schema，包括组合结构和本地引用；provider 接收兼容的字符串参数，服务端仍按原契约校验解码后的结果。非法提交返回具体字段路径，允许在剩余执行预算内修正；普通回复不会完成任务。有效提交先保存意图，执行到已保存的安全点后，在同一事务中写入结果、产物版本、完成状态和关键事件。重复提交不会生成第二次完成或重复版本。

任务使用 `read_task_artifact(artifact_id, version)` 读取固定输入的完整内容，传入该版本内的 `file_id` 可读取完整文件；实际读取的引用持久保存，不能改读未声明的新版。通过现有授权工具取得完整文件内容后，先调用 `store_task_file(filename, content, encoding)`，成功后把返回的稳定引用放入 `files: [{"file_id":"..."}]`。content 可为 UTF-8 文本或 base64 字节。文件完整存入系统管理的数据库后才可提交，不保存临时绝对路径，刷新和进程重启后仍能预览、下载。单文件最大 50 MiB。

切换或关闭页面不会停止核心执行。刷新带有 `workflow_run` 参数的地址会重新读取该运行，也可从独立运行列表重新打开。核心进程重启时，已保存安全点的有效结果意图会自动幂等收尾，其余未完成执行标记为 **已中断**。通过 **继续同一次尝试** 恢复符合条件的模型边界；结果不明的工具保持待处理。

## 配置有界审查修订循环

打开 **Agent 团队 → 工作流资产 → 新建画布工作流／编辑资产**。配置撰写和独立审查任务，连接撰写到审查的无环依赖；审查输出契约包含必填布尔字段 `approved`。点击 **添加有界循环**，选择明确的循环体、退出结果任务、字段比较（`approved eq true`）和最大轮数（1–100，不能超过成员的有效迭代限制）。任意代码表达式、图回边、重叠循环体以及离开循环体后又进入它的路径在执行前报错。

为撰写任务声明第一轮的草稿与反馈输入。在循环中 **添加反馈输入**，显式将上一轮撰写结果的 text 传给下一轮草稿，将上一轮审查的 text 传给反馈。每轮内部的普通依赖输入读取本轮产物。可折叠或展开画布上的循环分组。保存产生资产新版本，已有运行保留原定义和有效配置。

每轮创建独立 Task 和新 Attempt，固定本轮输入版本，分别保留模型、工具过程及用量。修订产物有独立的不可变资产标识：比较具体版本时同时看 `artifact_id` 和 `version`，不能只看版本数字。重试保留 Task 和本轮固定输入，创建新 Attempt；恢复继续原 Attempt 的检查点。旧内容、审查结论与批准引用不会被覆盖。

在 **独立运行 → 查看运行 → 循环轮次** 展开某一轮，可查看输入、结果、退出结论的精确引用和任务模型调用数；未知用量显示“未知”。点击任务进入完整过程、产物与控制；展开该轮执行图查看真实任务状态。执行过的循环体只有在已校验退出条件匹配后才放行组外消费者。最后一轮仍不匹配时显示 **已达轮次上限**，运行需要处理且没有成功的最终结果。循环体局部等待时独立分支继续；全局暂停和取消也作用于跨轮次边界，重启不产生重复轮次或重放已保存效果。

如果首轮整个循环体因条件未选中而跳过，循环和轮次显示 **条件未选中，已跳过**，不产生退出产物或新轮次。汇合忽略这条未选中的路径，使用活跃分支的输入。已经执行但出口被跳过、执行失败或耗尽的循环仍会阻塞依赖它的消费者；跳过任务的输入不会生成替代结果。

可选条件分支被跳过时，退出任务仍可用已校验的通过结果结束循环。如果未通过的退出条件需要读取被跳过任务的反馈，循环会进入需要处理状态，因为该轮没有可固定的反馈结果。

不添加人工节点也能独立演示通过或达到上限。需要确认报告时，在审查依赖之后配置 **版本批准** 并选择撰写产物任务；待办固定通过轮次的具体产物，导出读取被批准的引用。手动新版产物不会自动重跑消费者，也不会继承旧批准。

## 执行器就绪与远端恢复

进入 **工作流资产 → 启动运行**，对话框先检查固定版本的本机依赖与执行器能力，再放行 **启动运行**。**检查就绪** 可重新执行与启动相同的判定；阻塞项显示具体字段。角色、画布工作流和自主团队共享规则；自主协调者必须支持本机派工工具。

| 执行器 | 已接入的恢复边界 |
| --- | --- |
| 内置执行器 | 完整模型上下文及逐个工具调用检查点。 |
| Dify 工作流 | 原 `workflow_run_id` 与已配置的工作流输出。 |
| 开启保存历史的 Coze | 原 `chat_id`、`conversation_id` 和该次 chat 的回答；关闭保存历史则不提供查询能力。 |
| 当前 DeerFlow API | 原线程／运行 ID、精确运行状态及分页的该次运行消息；接口或完整输出缺失时须确认。 |
| Dify chat／agent／chatflow、百炼 Application | 仅外部调用边界；Chatflow 的状态查询不能单独恢复经过输出审核的最终回答。 |

在 **独立运行 → 查看运行** 选择受影响任务。执行器面板显示恢复边界和原远端身份；**查询原远端运行** 保留原 Attempt，仅查询该身份，不创建新运行。已保存完整响应直接复用。身份缺失、查询不可达、身份不匹配、状态仍活动／未知或完整输出缺失时保持待确认。明确选择新 Attempt 前先检查原服务；查询失败不证明操作未发生。

Dify 工作流通过已配置输出键提供结构化对象，由原输出契约校验器接收。远端普通文本和展示用 JSON 不会自动完成任务。Coze、DeerFlow 的回答保存为过程输出，缺少显式结果提交时显示 **等待提交结果**；要求 `task_result` 的资产会拒绝没有该能力的执行器。远端查询不恢复其内部工具；未接入协议的插件／工具内部调用只保证 AstrBot 实际保存的边界。思考与签名按提供商实际返回保留；不返回思考的模型正常工作。

## 根运行用量与限制

在 **工作流资产 → 编辑资产 → 作用域限制** 配置总调用步骤、子树成员实例数、每个循环的轮次、Token 额度和单次模型输出上限。单任务、画布工作流和自主团队使用同一表单；留空不增加上限。保存新版本后启动运行，已有运行仍使用原版本的限制。画布和自主团队原有的并发、深度与局部成员限制继续生效，嵌套同时遵守祖先作用域的限制。

“总调用步骤”按每次获准的模型、工具或状态查询投递计数，包括协调者、成员、参数补全、压缩、重试和子调用。等待人工、子流程或在途预留释放执行容量。进入额度预留等待时会自动唤醒独立就绪任务，仍遵守根与祖先作用域的限制。挂起的 Agent 回合仍持有成员上下文，同成员的其他任务等待该回合退出后再推进。从检查点恢复保留原 Attempt；显式重试产生新 Attempt，但已发生用量与限制不清零。循环上限限制每个循环的轮次，不能通过恢复或重试创建额外轮次。

在 **独立运行 → 查看运行 → 用量与限制** 查看根汇总，选择任务或进入子作用域查看对应明细；展开 **调用明细** 可追溯作用域、任务、Attempt、Invocation 和实际投递身份。父子明细共享同一记录，汇总不重复计数。读取其他根运行的输入产物不会转移其历史消耗。

Token 汇总分别展示提供商已报告的部分、估算、在途预留以及用量未确认调用。缺失报告显示未知；工具没有 Token 报告时也显示未知，不能据此推断工具没有其他费用。Token 额度约束接入此协议、可估算的模型请求；插件或工具内部未接入协议的收费不能作为硬性额度控制。未配置单次输出上限时使用请求已有上限；请求也未提供时采用 2048。预留约束并发新增调用，但输入估算和提供商输出约束可能不准确，事后报告可能超过额度，不能保证任何情况下绝不超支。

用量追踪启用前创建的运行保留原有过程记录。面板单独显示已保存的历史模型响应及历史消耗未知状态，恢复后出现新用量也不会清除该标记。历史响应和检查点步骤不是准入凭据；已报告总量仅涵盖已计量部分。这类运行中，用量未知的调用总数仍显示未知。

达到可判定限制后停止新增调用，并展示限制名称、值和任务归属。已保存的结果和外部效果仍可追溯；若有效结果及整个工具批次已提交并应用，额度拒绝后续收尾叙述不妨碍结果完成。终止时未确认的消耗保留保守估算，迟到报告可补齐原记录，却不能取得当前执行权。仅被其他在途调用占用的额度会等待释放，等待不占活跃名额。
