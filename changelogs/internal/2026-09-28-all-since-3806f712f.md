### 修复

- Agent 工作胶囊不再吞掉仍待作答的交互选项框：折叠态只渲染回复区，而回复区会把其中的 `interactive_choice` 剔除（该 part 既不在回复区、也不在 work 组，页面上渲染次数为 0）。此前仅靠标签页运行态（`is-streaming`）间接兜底——刷新后 SSE 连接消失、run 已结束或答案来自另一标签页时，胶囊出现并把框一起吞掉，用户必须点开胶囊才看得见它。改为按选项框自身状态机判断：待作答（未提交 / 未取消 / 未忽略）则整条消息保持展开，终态的框照常折叠（展开胶囊仍走同一组件回看）；同时把回复区隐藏的 part 折回 work 组，使两个区域互为补集，杜绝"谁都渲染不到"的第三态。附回归测试：`ChatMessageList.pendingChoice.spec.ts` 3 例、`agentWorkSplit.spec.ts` 2 例（先红后绿）。 (`bb5aa3865`, `052bc6226`)

- 一轮对话只落一条历史记录：`ask_user_choice` 让回合在中途落盘（问题必须在等待作答期间就落库，否则刷新即丢），而每次落盘都会新开一行历史——直播时前端把整个 run 累积成一个气泡，刷新后按行渲染，于是一轮被拆成多个气泡、每个都带自己的胶囊。现在本轮首次保存建行，之后每次保存把本段 parts 追加后改写同一行；`agent_stats` / `file_changes` / `refs` 改取 run 级取值，避免后一段冲掉前一段的元数据。附 `tests/unit/test_chat_service_turn_history_record.py` 2 例。该修复需**重启后端进程**才生效（重启前旧进程仍按每次落盘开新行）；重启后实测一轮 5 个选项框 + 思考 + 正文落在同一行，刷新渲染与直播一致。**修复前已落盘的旧轮次不会回溯合并**，刷新后仍是多个气泡，如需合并需另做一次性数据迁移。 (`ebac3152d`, `c2f091e07`)

- 文件变更摘要卡两处修补：①subagent 内改动的文件此前不进回合摘要卡——子代理上下文持有独立的 `extra` dict，文件工具写入的 `changed_files` 列表主 runner 从不读取，现在主 / 子代理共享同一列表对象；②被删除或不可读的文件在卡片上明确标注，而不是静默跳过或报错（回合摘要按当前磁盘内容算净 diff，worktree 已删的文件会炸）。 (`e68cb8a12`, `25cc140be`)

- 本地 Shell kill 目标解析：按名称选择目标的 kill 形式（taskkill / pkill / Stop-Process）此前被 `_would_kill_self` 一律拒绝，现在先解析目标再判断是否误伤自身；非本机目标的拒绝信息更清晰。 (`eb7d63856`, `e1cfc90a0`)

- 切换「本地 Shell 类型」不再让系统配置保存失败：面板保存路径调用 `shutdown_sessions(invalid_only=True)`，但该关键字早已随本地 shell 运行时重构从 `LocalShellComponent` 上消失——2026-09-15 合并上游（`f9488d514`）时 `config_service.py` 取了上游版本、`local.py` 保留了分支自己的版本，两文件之间没有文本冲突，调用点就此与实现脱钩。该调用带 `booter is not None` 守卫，而 local booter 是进程级懒加载（首次本机 shell / Python 工具调用才创建），于是表现为**重启后第一次保存成功、之后每次保存必失败、再重启又好一次**；又因为调用位于配置写盘之后，面板报「保存失败」时文件其实已经更新，`reload_pipeline_scheduler` 也不会执行。现在 `shutdown_sessions` 新增 `keep_family`：切换 shell 时只终止旧 shell 的会话、保留当前 shell 的会话；清理改为 best-effort（失败只记 warning），不再把一次成功的保存变成失败。回归测试 4 例（组件过滤 1、helper 2、真实保存路径 1，均先红后绿），其中 service 层用例在修复前复现了原始 `TypeError`（`config_service.py:809`）。 (`6fcf2eee1`)

- Git Bash 托管 Shell 会话的 poll / interrupt / terminate 不再挂起或报错（git bash + pythonw 环境逐项实机复现后修复）：①reader 协程只在管道 EOF 时结束，而 MSYS2 孙进程脱离 Windows 父进程链、继承 stdout 句柄使 EOF 永远不来，`poll_session` 中 4 处无界 `await reader_task` 令 terminate 挂起约 110 秒直到进程自然死亡；②`_terminate_process` 尾部与 `shutdown_sessions` 的 reader gather 同为无界等待；③pythonw 无 console，`CTRL_BREAK_EVENT` 无法投递且 CPython 误报为 `SystemError: returned a result with an exception set`，`interrupt_session` 原本完全没有异常防护；④进程被杀后 `wait_task` 以 `OSError: 句柄无效` 收场，两处遗留的裸 `wait_for(shield(...))` 把该异常（或其 SystemError 变体）原样抛给调用方；⑤reader 未结束时 unlink 会话输出文件触发 `WinError 32` 文件占用。修复：新增 `_bounded_await`（硬超时，且把"任务以异常收场"视为已完成），会话任务的全部等待统一改经它；Windows 信号路径加防护并降级为 taskkill 温和清理；会话清理先取消卡住的 reader 再删文件，删除失败降级为 debug 日志。附 12 个回归测试（均先红后绿），pythonw 实机验证 interrupt / terminate 秒级干净返回、无残留会话与新增临时文件；MSYS2 孙进程仍短暂存活但会自行退出（已知取舍，不再阻塞任何调用）。需重启后端进程生效。 (`d3969c9d9`, `8b374284a`, `0514ddfb1`, `fecd7811e`, `d1dffdd63`, `56e7e5455`)
