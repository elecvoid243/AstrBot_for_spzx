### 修复

- Agent 工作胶囊不再吞掉仍待作答的交互选项框：折叠态只渲染回复区，而回复区会剔除 `interactive_choice` part，该框无处渲染；此前仅靠标签页运行态兜底（刷新、run 结束或跨标签页作答即失效）。改为按选项框自身状态机判断——待作答则整条消息保持展开，终态照常折叠；并把回复区隐藏的 part 折回 work 组，使两区域互为补集。附回归测试（先红后绿）。 (`bb5aa3865`, `052bc6226`)

- 一轮对话只落一条历史记录：`ask_user_choice` 让回合中途落盘（问题须在等待作答期间就落库），而每次落盘新开一行——直播时前端把 run 累积成一个气泡，刷新后按行渲染便拆成多个气泡、各带胶囊。改为首次保存建行、后续把本段 parts 追加改写同一行；`agent_stats` / `file_changes` / `refs` 改取 run 级取值。附 2 例测试，需重启后端生效；修复前已落盘的旧轮次不会回溯合并。 (`ebac3152d`, `c2f091e07`)

- 文件变更摘要卡两处修补：①子代理上下文持有独立 `extra`，其文件工具写入的 `changed_files` 主 runner 从不读取 → 主 / 子代理共享同一列表；②被删除或不可读的文件明确标注，而非静默跳过或报错。 (`e68cb8a12`, `25cc140be`)

- 本地 Shell kill 目标解析：按名称选择目标的 kill 形式不再被 `_would_kill_self` 一律拒绝——先解析目标再判断是否误伤自身；非本机目标的拒绝信息更清晰。 (`eb7d63856`, `e1cfc90a0`)

- 切换「本地 Shell 类型」不再让系统配置保存失败：保存路径调用的 `shutdown_sessions(invalid_only=True)` 早已随运行时重构消失（2026-09-15 合并上游 `f9488d514` 时 `config_service.py` 取上游版本、`local.py` 保留分支版本，两文件无文本冲突，调用点与实现脱钩），在 `booter is not None` 守卫下表现为"重启后第一次保存成功、之后必失败"；又因调用位于写盘之后，面板报错时文件其实已更新。`shutdown_sessions` 新增 `keep_family`（只终止旧 shell 会话、保留当前 shell），清理改 best-effort 只记 warning。附 4 例回归（service 层用例在修复前复现原始 `TypeError`）。 (`6fcf2eee1`)

- Git Bash 托管 Shell 会话的 poll / interrupt / terminate 不再挂起或报错：MSYS2 孙进程脱离父进程链并继承 stdout 使 EOF 永不到来，多处无界 `await` 令 terminate 挂起约 110 秒；pythonw 无 console 时 `CTRL_BREAK_EVENT` 无法投递且 CPython 误报 `SystemError`；进程被杀后 `wait_task` 以 `OSError: 句柄无效` 收场并原样抛给调用方；reader 未结束时 unlink 触发 `WinError 32`。新增 `_bounded_await`（硬超时，任务异常收场视为已完成）统一承载所有等待，Windows 信号路径加防护并降级 taskkill，清理先取消卡住的 reader 再删文件。附 12 例回归，pythonw 实机验证秒级干净返回。需重启后端生效。 (`d3969c9d9`, `8b374284a`, `0514ddfb1`, `fecd7811e`, `d1dffdd63`, `56e7e5455`)

- 已作答的交互选项框不再被重新贴到对话尾部：历史分页（`HISTORY_PAGE_SIZE`）后，携带 `interactive_choice` 的记录已不在已加载消息里，而 store 镜像把终态 part 重新塞回 `activeChoices` 并写进 localStorage，`injectOrphans` 找不到该 part 自己的记录，就把过期框追加到**最后一条** bot 消息上。修复：跳过带 answer / resolved 或 `request_id` 已 submitted / cancelled / ignored 的 part，镜像也不再写回终态 part。附 `interactiveChoice.test.ts` 5 例、`ChatMessageList.pendingChoice.spec.ts` 4 例（先红后绿）。 (`503347707`)

- SubAgent 追加输入框只在卡片展开时出现（`SubAgentRunBlock.vue`），reducer 不再把 follow-up 输入当作收起态的常驻部件。 (`249d4936b`, `25b71784d`)

- Python 工具超时语义修正：`astrbot_execute_python` / `astrbot_execute_ipython` 此前用 `min(timeout, tool_call_timeout)` 封顶执行时长，列进 `tool_call_timeout_exclude` 只去掉 runner 层 `wait_for`，配置值仍掐着实际执行；现被排除的工具只认模型传入的 timeout，缺省回落 schema 默认值 **60s（原 30s）**。默认值收敛为单个模块常量，schema 与两个工具签名共用。 (`8a1be2d05`)
