# 从历史运行调试时默认使用原运行版本

一次失败运行结束后，编辑者可能已经修改了草稿中的提示词、端口或节点。由历史运行创建的调试分支默认采用原运行实际使用的工作流定义和记录的输入，让编辑者可以只改一个字段并比较结果。验证草稿中的修复时，由编辑者显式选择当前草稿。

调试分支默认只执行选中的节点，便于将这次输出与原节点的结果直接对照。需要验证后续审批或交付路径时，编辑者可以在启动前显式选择从该节点运行下游。

调试中遇到外部写入时，默认预览本次调用的目标和参数。例如，发送报告前先展示收件群和待发送内容，由有权限的用户显式选择实际发送。原运行的回执保留作对照，本次投递的状态依据本次调用取得的证据。

用户也可以在预览处选择「用测试值继续」，提供符合输出契约的模拟回执，以验证下游如何使用返回值。调试时间线和使用该值的结果都标明模拟来源；后续遇到的每次外部写入仍单独预览。

变量检查器跟随当前选中的轮次和任务尝试。点击数据线时，优先展示消费节点在这次尝试中实际读取的值；若节点被跳过，则显示「已跳过 · 未读取」，并可另行查看本轮上游产物。查看其他轮次或尝试的值需要显式切换，从失败尝试进入时直接定位到该次尝试。

从父画布调试失败的子流程调用时，默认进入该次调用的内部失败尝试，展示其历史输入，由编辑者确认后试跑该节点。检查父子输入映射或内部步骤之间的配合时，可显式选择「试跑整个子流程」。

历史输入无法完整还原时，检查器逐项标明缺失内容。编辑者可以显式补齐符合输入契约的测试值，受管文件或产物须选择当前有权读取的精确版本。调试分支及结果对比保留每项输入的来源，使读者能区分原值与本次替换值。

首版支持从工作流画布节点和固定子工作流内部节点创建调试分支。自主团队的动态成员提供按尝试查看历史任务、消息和产物的入口；需要验证成员协作时，编辑者可以显式试跑整个团队。单独重跑动态成员涉及还原成员身份、已消费消息和结果接收者，留待后续设计。
